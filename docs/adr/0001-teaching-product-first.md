# ADR-0001：验收轴由「可维护性」改判为「教学产品优先」

- 状态：已采纳
- 日期：2026-11-08
- 决策者：维护者
- 相关：规格 #19；ADR-0002

## 背景

本技能的用户是**真人学员**，不是 agent。它教人学习：先教后练、进度落盘、跨会话续学，
并用十一条常驻红线保护学员体验（不先测未讲、不代答代判、失败日零施压、呈现克制）。

但过去连续七个以上版本，验收标准实际上是**可维护性**：
规则分册被切到中位 35 行、十一行一册，全仓上千处文档指针，一份机器契约反向生成三张加载表，
再由脚本校验一百余个分册的文件头、指针与版本。每次改一条规则，先要跑生成器。

结果：结构越来越整齐，规则仍反复漂移；而**从没有一次验收问过「学员这一轮有没有被教对、
有没有被催促或被代答」**。维护者因此觉得入口文档与分册「很奇怪」。

## 决策

**验收轴改为教学产品优先（D）**：唯一验收标准是学员体验与教学闭环有效性。
可维护性是达成它的**抓手**，不是目标本身。

推论：

1. 硬约束序变为：① 教学语义 + 学员可见输出纪律零退化（不可破）② 行为机检不退化
   ③ 官方 Agent Skills 规范符合度 = **参考，不设闸**。
2. 官方规范从「硬约束」降为「报告项」。理由：该规范管的是「把知识交给 agent」，
   不裁「怎么教好真人」——它不能作为本技能的主验收标准。
3. 一切结构改动的正当性，只能由「它让学员这一轮被教得更好，或让维护者更改得动规则」来论证。

## 后果

- **正面**：验收终于对齐真实用户；「册数变少」不再算成功，「学员没被代答与催促」才算。
- **正面**：官方规范符合度仍被报告，只是不再拿它当闸口——符合度下降不会被掩盖，但也不会
  为了它牺牲教学语义。
- **负面**：失去「结构自洽」这个容易自动化的验收信号，必须改用红线盲回放 + 真人冷读这类
  更贵、更慢、需要人的证据。这是**有意付出的代价**：容易测的指标不等于重要的指标。
- **风险**：红线回归与冷读尚未实际执行（见 #27），所以本次交付的「教学产品优先」
  目前只体现在**判据自足与结构简化**上，还没有实测数据支撑。这一点必须明说，不能当成已达成。

## 风险栏：评分本身不可靠（实测，2026-11-08）

改用「教学产品优先」后，主证据是**红线盲回放**。回放本身是可靠的——盲测由目录结构保证，
执行者拿不到判据。**但评分不可靠，而且已经被实测证伪。**

### 四次评分修正（同一批输出、同一套判据）

| 次序 | 结论 | 偏差性质 |
|---|---|---|
| 初评 | 11/11 | **过宽**：把 RL-01「第 5 个目」的残留偏差记为「可改进，不构成阻断」 |
| 一次复判 | 8/11 | **过严**：把 RL-04 的**状态回复**当成「讲授正文」，误判红线6 违规 |
| 二次复判 | 9/11 | 修正上一条，但 RL-01 仍未按判据⑤字面重审 |
| v2 初判 | 11/11 | **再次过宽**：用「每次都附了名称待核对」替 RL-01 的 4 次编号句式开脱 |
| v2 自审 | 10/11 | 按判据⑤字面改判 |

### 根因（不是事实判断错，是标准漂移）

1. **先有结论、再找理由**：想让技能通过，就找到「偏差可接受」的说法；想显得严格，就把不违规的判成违规。
2. **误把「执行者态度好」当成「判据满足」**：执行者不编造、诚实说明，是好事，但判据禁止的是**行为本身**。
3. **误把「状态回复」当成「讲授正文」**：红线6 判据①的管辖范围是讲授正文，判据②明确允许学员查询进度时另起状态回复。
4. **审计口径混用**：把自己写的评分说明和执行者输出混在一起扫，导致误报（v2 那次）。

### 对策：双评 + 三裁（已落地）

- **评分者 A**（主审）与**评分者 B**（独立，不看 A 的结论）各自评分
- 结论不一致的条目，交由**裁决者 C** 裁定，C 只看分歧条目 + 双方理由 + 判据原文
- C 的裁定**以判据字面为准**，不以「执行者态度好」或「意图正确」为豁免理由
- 两人结论一致即采用，不引入 C——分离权责不等于堆叠复核

**为什么这样能治**：单人评分时，「想让它通过」和「想显得严格」是同一个人在同一条时间线上
反复摆；两个人独立评，两种偏差才有机会互相暴露。C 只裁分歧，防止 A、B 互相迁就。

### 双评机制的首次实战（v3 回放，同日）

双评落地后立刻派上了用场，而且**当场抓到了主审的错误**：

| 评分者 | 结论 | RL-01 判定 |
|---|---|---|
| A（主审，我） | 11/11 | 通过 |
| B（独立第二评分者） | 10/11 | **未通过** |
| C（裁决） | — | **B 正确，A 作废** |

**分歧点**：RL-01 输出里两次出现「这一节里的第五个目」「这一节第五个目」——纯编号指代、无名称。
判据⑤明写「不复用『第 N 个目』这类句式」，中文数字「第五个目」是同一句式变体。
执行者虽声明「不凭编号猜」，但判据禁的是**句式本身**，声明不能替代。

**A 为什么漏检**：我的审计正则写的是 `第 [0-9]+ 个目`，**只匹配阿拉伯数字**，漏掉中文数字。
更根本的问题是：我已经决定「这条应该过」，于是找了个正则去证明它过。

**这恰好验证了 ADR 的判断**：单评不可靠不是理论担忧，是当场发生的。如果只有 A，
这次会以 11/11 收尾，而实际是 10/11。

**连带修掉的判据缺口**：判据⑤的示例只给了 `第 9 目`→「下一目」，没覆盖中文数字写法。
已补一句「阿拉伯数字与中文数字同属该句式」。

### 双评第二次实战：A/B 一致，暴露了另一条红线（v4，同日）

判据⑤补上「中文数字同属该句式」后重跑 v4，A/B 双评结果：

| 评分者 | 结论 | 未通过项 |
|---|---|---|
| A（主审） | 10/11 | RL-07 |
| B（独立） | 10/11 | RL-07 |
| C | 未启用（A/B 一致） | — |

**这次 A/B 一致，但一致的是「未通过」**——而且未通过项换了：

- **RL-01 修好了**：v3 的「这一节里的第五个目」→ v4 改为「你问的那个目」+「某一目」，判据⑤达标。
- **RL-07 新暴露**：学员要求把讲义存到桌面，执行者答「可以，桌面存一份没问题」并承诺
  「你回一句，我就存过去」。判据⑦④明文禁止往用户主目录/桌面落学习数据，
  判据②的写前路径确认、判据③的越界即停改回，两项均缺席。

**这条值得记下来**：RL-07 在 v1–v3 三轮都是「通过」，因为三轮都没认真核过它。
它一直存在，只是没人看。这说明**红线回归的价值不在于「通过率」，而在于逐条真读**——
如果只盯着上一次未通过的那一条，其它条会一直躺在「通过」里没人验证。

**四轮轨迹**：9/11 → 10/11 → 10/11 → 10/11。每轮修好一条，又露出下一条。
这不是回归，是**逐条把隐藏的问题翻出来**。三轮未通过的 RL-01 终于干净了，
现在轮到 RL-07。

### 残余风险

- 双评 + 三裁仍然是人（或模型）在做判断，不是机器判定。**它降低漂移概率，不消除它。**
- 判据本身若有歧义（如「台账状态」的边界），双评也会一起读错。判据的措辞质量仍是根本。
- 因此红线回归的结论应始终标注**评分机制版本**（本轮为「单人主评」，v3 起为「双评 + 三裁」），
  让读者知道这个 11/11 是在什么机制下得出的。

## 第七轮回放：结果不可复核（2026-11-10 复核，票 43）

本 ADR 原记录「v7 达成 11/11 双评通过，0 条分歧」。**该结论已被降级**，因为证明链断在两处：

- 回放原件 `evals/replay-2026-11-08-redline-blind-v7.md` 头部自述「本轮修复判据⑨③ 地图三要素」，
  而三要素表述在 git 里的最早出现是 `894121a`（2026-11-09 v9.20.0）。上一版 `e30864c`（v9.19.2）
  的 SKILL.md 只写「族性术语首次触碰先给一页地图」，细则在 `references/assessment/term-reconcile.md`，
  也只写了「族内全部名字 + 一句话功能」——没有（a）成员清单 /（b）彼此关系 /（c）判别标志这三样。
  即：仓库历史里找不到与这份标 11-08 的实录相对应的判据版本（不排除是本地未提交的工作区，但那一版没留下）。
- 记录里的盲测副本 `D:/me/blind-skill-v7/` 在本机不存在；11 条 `run_id` 在仓库内均无可解析的评测记录。

因此 `evals.json` 的「执行记录」「双评记录」两节已整节退役，11 条用例的 `verdict` 只作底层记录、不计入 P0。

### 仍然成立的两件事（与上面那份记录无关，独立可复核）

- **单评会漂**：七轮里同一判据、同一批输出给出过 11/11 → 8/11 → 9/11 → 11/11 → 10/11；双评 + 三裁的
  分工（执行 / 评分 A / 评分 B / 分歧才启动 C）是这个过程沉淀下来的机制，继续保留。
- **判据含糊会让执行者和评分者各自补门槛**：这条结论不依赖 v7 那次计数，v3–v6 的过程记录足以支撑。

### 仍然没做的两件事

- `human_cold_read`：需要真人读者，模型代替不了。
- `trigger_eval`（20 条）：从未运行，`runs_done` 全为 0。

这两项在 `evals.json` 里仍是「未验证」。**红线回归现在也归到同一状态**：没有可复核的执行记录。

## 被否决的替代方案

- **继续以可维护性为轴、只做最小改动**：已经被连续七版证伪——结构越来越整齐，规则仍漂移。
- **以官方规范符合度为轴**：规范不裁真人教学，用它当轴会把「像不像一个 agent skill」
  误当成「教得好不好」。
