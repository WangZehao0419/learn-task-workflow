## 群边界与借用

本群：编程语言的语法与读写调试、算法与数据结构实操、脚本与工具链、计算机理论（操作系统、网络原理、组成原理）。上机编程与计算机理论同群，但内容类型分布不同：编程以程序型为主，理论以概念型为主。

默认内容类型分布：程序型约七成，概念型约两成，记忆型与设计型少量。S2 按实际目清单核正。

学员有真实项目或工作场景时，示范与练习**优先改造自他的真实材料**，抽象素材退为兜底。

## 内容结构与前置链

- **语法层**：变量与类型 → 表达式与语句 → 分支 → 循环 → 函数 → 数据结构 → 模块与文件。
- **能力层**：读代码（能预测输出）→ 改代码（能小步修改）→ 写代码（能从零实现）→ 调试（能定位并修复）→ 设计（能拆解并取舍）。
- **理论层**：存储层次 → 进程与线程 → 调度与同步 → 网络分层与协议 → 组成与指令。
- **前置断层高发点**：变量「是什么」没建立（把赋值当数学等式）、循环的边界惯例（含头不含尾）、函数调用与返回值的区别。这三处不修，后面全是背语法。

## 目标深度锚点

- **程序型目**：不只是「跑通」，而是能说出每步在做什么、为什么这么写、边界在哪。跑通但说不清，只到多点结构。
- **读码能力先于写码能力**：能准确预测一段陌生代码的输出，是写码的前置。读码不达标时不要跳到从零实现。
- **概念型目**（理论层）：能画出机制（时间线、层次图、状态迁移），能判断一个具体场景会出什么问题。
- **设计型目**：能拆分子问题、给出接口、说明取舍；接受多解，不追求唯一写法。

## 排期侧重

- **环境先立起来**：第一节必须把运行环境跑通，否则后面每一节都在跟环境搏斗。环境问题记入薄弱点，下次热身复现一次。
- **每节必须有一段实跑**：读代码、写代码都要真跑。没有执行环境的会话不做「看起来对」的结论。
- **小项目收口**：每章末安排一个「无用但完整」的小项目（能用就行，不求工程化），防止学完语法不知道拿来做什么。
- **理论层与上机层交替**：连续多节纯理论会掉，连续多节纯编码会缺机制理解，交替排。
- **考前**：算法与理论题按错题重做，上机题先确认环境与版本差异。
