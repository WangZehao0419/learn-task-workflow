## 复习形态与间隔侧重

- **题型轮换**：读码预测 → 改错 → 补全，隔次换型；同一题型连做三次以上就退化为机械操作。
- **不看笔记重写**：给需求，关闭参考，从零写一遍最小版本；写不出来再看笔记，看完再关掉重写。
- **API 与语法用检索复习**：函数名、参数顺序这类属于记忆型，做成卡片按间隔复习；不要指望在写代码时自然记住。
- **错题按「心智模型错 vs 手滑」分流**——见下表。
- **环境与版本类问题**记入薄弱点，下次开课热身复现一次，直到不再复发。

## 错因分流与纠错脚本

| 错因 | 判别信号 | 纠错动作 |
|---|---|---|
| 心智模型错 | 概念性错误，改完这题换个场景还错 | 回炉对应概念目重讲，用 trace 表重建执行模型 |
| 结构设计错 | 能写但拆得不好、嵌套过深 | 重做「拆子问题 + 定接口」这一层，不从语法改 |
| 手滑 | 拼写、缩进、漏冒号 | 入技巧性专项：靠 IDE 与格式检查兜底，不做概念重讲 |
| 边界遗漏 | 正常输入过、边界崩 | 补边界用例清单（空/零/负/最大/重复）作为提交前检查 |
| 报错不会读 | 直接搜答案 | 强制造三件：行号、类型、原因；练三次再允许查 |
| 不会提问 | 只贴「跑不了」 | 教最小复现四件：代码、输入、报错、预期 |

**纠错话术**：代码类错误先说「哪一行、什么类型」，再说「你原来希望它做什么」，最后才给修法。直接把正确代码贴出来会跳过定位过程。

## 冲刺侧重（方法层）

- **手推优先于机跑**：笔试类考试（算法、理论）要能手推伪代码与复杂度，不依赖 IDE；上机考试相反，先确认环境与版本。
- **模板记牢几个就够**：遍历、递归、二分、动态规划基本形态——记结构不记细节，细节现场推。
- **复杂度口算**：看到嵌套循环就能说量级，这是最高性价比的抢分点。
- **错题重做优先**：冲刺期只重做错题与典型题，不刷新题。
- **考前确认环境**：语言版本、库版本、编译参数——记入考前一页纸。
