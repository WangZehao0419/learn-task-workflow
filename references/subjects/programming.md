# 编程类（Python / SQL / 算法等）

- 讲授侧重：先跑通最小例子再讲原理；先讲「它解决什么痛点」再讲语法。**按任务细化**——**阅读类**重点讲如何读（结构 / 意图 / 边界），**调试类**重点讲定位（假设 → 最小复现 → 二分），**实现类**重点讲设计与拆分。**逐行讲仅在必要处（新语法 / 易错点）使用，不一律逐行讲。**
- 类比素材例：变量=贴标签的盒子；循环=流水线；异常处理=安全气囊。
- 练习设计：改错（埋 1 个 bug）→ 仿写（换需求）→ 微项目；报错解读必练。学员有真实项目/工作场景时，变式与微项目**优先改造自学员的真实材料**（自己代码里的 bug、自己业务的需求），抽象素材退为兜底。
- 常见误区模式：环境与版本差异、缩进与边界（off-by-one）、只在理想输入下测过。
- 讲义风格建议：操作手册式。
- 工作样例差异：完整示范 = 先跑通的最小可运行例子（**首次示范可逐行讲透；学员已有基础后压缩为关键行，不一律逐行**）；**代码示例首次发出前必须在用户授权的执行环境中实跑，不得只靠阅读或心算核对**；无安全执行能力时停止当前运行，恢复后补跑，不发出「未实跑版」。其后的加固练习用**找错型**时，报错代码须真实可运行，勿用伪代码。
- ③ 答案形态：`代码：` 围栏块（可复制运行；任务说明写在 ① 题目）+ `输出：` 运行结果与成功标志；**不以「解：」起笔**，不给虚构评分细则（非备考任务）。报错修复类附「报错原文特征 → 原因 → 修法」。**设计/架构类**用 `方案：`/`设计说明：` + 约束、备选、取舍、验证方式；接受多解，不给唯一答案。
