# 编程类（Python / SQL / 算法 / Web 等）

## 判档与借用

本族：编程语言语法与写读调试、算法与数据结构实操、脚本与工具链。计算机**理论**（OS/网络原理/组成原理）归理论概念类；纯名词清单（快捷键表、函数名罗列）归记忆密集类。学员有真实项目/工作场景时，示范与练习**优先改造自学员的真实材料**，抽象素材退为兜底。

## 讲授侧重（六拍内的族差异）

- **先跑通最小例子再讲原理；先讲「它解决什么痛点」再讲语法**（不变）。
- **读先于写（PRIMM 序，零基础/入门默认）**：Predict 预测输出 → Run 实跑对照 → Investigate 逐行调查（仅新语法/易错处逐行）→ Modify 小改一步看变化 → Make 独立写。映射六拍：I do=Run+Investigate 的完整示范，We do=Modify 补步，You do=Make。学员已有基础后压缩为关键行，不一律逐行。
- **子目标标注**：示范代码按子目标分段、每段一行注释说「这段在干嘛」（Margulieux 2020：降退课率，对挣扎学员尤其有效）；与「每步一行做什么+为什么」融合。
- **按任务细化**：阅读类重点讲结构/意图/边界；调试类重点讲定位（假设 → 最小复现 → 二分）；实现类重点讲设计与拆分。
- **AI 生成代码一律当草稿**：生成代码必须实跑验证后才算数，禁止「看起来对」就交付；学员直接贴 AI 答案时，先问「你跑过吗」，跑不出预期结果正好作讲 Investigate 的素材。

## 类比库（锚点须确证已会，明说「像/不像」）

- 变量=贴标签的盒子；不像处（Python）：标签指向对象而非把值装进去，`a=b` 后改 `b` 指向，`a` 不变——但原地改对象（列表 append）两边都看得见。
- 循环=流水线；函数=榨汁机（投水果出汁，内部看不见）；异常处理=安全气囊；递归=俄罗斯套娃（不像处：必须有一个打不开的最小娃=终止条件）；调试=医生问诊（先问病史再开检查，不一次全查）。

## 练习与题型阶梯（按任务细化）

- **阶梯（由易到难）**：读代码预测输出（先写答案再实跑对照）→ Parsons 排序题（把打乱的代码行排成正确程序，降语法负荷）→ 改错（埋 1 个真实可复现的 bug）→ 补全（挖 1–2 段）→ 仿写（换需求）→ 微项目。
- **报错解读必练**：给报错原文，学员说出「哪一行、什么类型、什么原因」三件；找错型练习的报错代码须真实可运行，勿用伪代码。
- SQL 专项：先写「期望看到什么结果」再写查询；判定题走「这查询会漏掉哪些行」（NULL 行为是高发误区）。
- 判定题考「何时用」：给场景选工具（列表还是字典、递归还是循环、异常捕获还是前置校验），干扰项取误区库具名条目（R42）。

## 误区库（喂 R42；症状/诱因/反证）

| 误区 | 症状（学员会怎么错） | 诱因 | 反证 |
|---|---|---|---|
| 赋值=数学等式 | 读不懂 `x=x+1` | 按代数等式读 | 右边先算再贴标签 |
| 变量=装值的盒子 | 复合赋值后以为旧值还在 | 「盒子装东西」直觉 | 标签撕下贴到新对象，旧的等回收 |
| print=return | 函数里有 print 就当有返回值 | 控制台有输出=有结果 | `None` 也能 print 出来 |
| 执行顺序=书写顺序 | 忽略条件跳转/调用关系 | 从上往下读的惯性 | 函数定义不调用永不执行 |
| 边界 off-by-one | 循环少跑/多跑一次、切片丢尾 | 「从 1 数」与「含头含尾」混淆 | 手推 n=1、n=2 两例 |
| 类型想当然 | `"1"+"1"` 期待 2 | 眼睛看到数字 | input 进来的是字符串 |
| 可变对象共享引用 | 函数内改列表以为不影响外面 | 「传进来的是副本」 | 函数外再 print 一次看 |
| SQL 忽略 NULL | `WHERE col != 'x'` 以为覆盖全部 | 三值逻辑没教过 | NULL 行连比较都算假，直接消失 |
| 递归无终止条件 | 想象会「自己停」 | 没见过栈溢出 | 最小娃必须存在 |
| AI 代码直接信 | 不跑就交/直接照抄 | 生成结果看着像对的 | 一次实跑胜过十次目测 |

备课取 2–3 条；本学员历史错因优先占坑。

## 实跑纪律（族内硬规则）

代码示例首次发出前必须在用户授权的执行环境中实跑，不得只靠阅读或心算核对；无安全执行能力时停止当前运行，恢复后补跑，不发出「未实跑版」。实跑结果（含报错）如实展示，不粉饰。

## 复习与调度侧重（S4）

- 复习题型轮换：读码预测 → 改错 → 补全，隔次换型（检索练习优先）。
- 错题按「心智模型错 vs 手滑」分流：概念性错误回炉对应概念目重讲；手滑（拼写/缩进）入技巧性专项。
- 环境/版本类错误记入薄弱点并在下次开课热身复现一次。

## 讲义与答案形态

- 操作手册式为默认；③ 答案形态：`代码：` 围栏块（可复制运行；任务说明写在 ① 题目）+ `输出：` 运行结果与成功标志；不以「解：」起笔，不给虚构评分细则（非备考任务）。报错修复类附「报错原文特征 → 原因 → 修法」；设计/架构类用 `方案：`/`设计说明：` + 约束、备选、取舍、验证方式，接受多解。

## 备考侧重

- 算法笔试（考研 408 综合题、软考）：手推伪代码 + 复杂度口算作为专项（不依赖 IDE）；上机考试先确认环境与版本差异（记入考前一页纸）。
- 概念题（数据结构/OS 选择题）出题走误区库干扰项，判据用「本节已教工具」。
