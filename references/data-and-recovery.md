## 数据根（稳定根）

**规范数据根**：`<工作区根>/.learning/`。本分册全篇的「数据根」均指此路径——任何下级布局都**不再重复 `.learning` 目录段**（避免 `…/.learning/.learning/<slug>/` 的双重嵌套）。

为避免相对路径随会话 cwd 漂移导致「找不到进度」，遵循三条硬规则：

1. **一次解析、写进文件**：会话首次建立/迁移任务时，把解析到的**绝对数据根**写进 `<数据根>/<slug>/progress.md` 的「数据根」字段；此后以该字段为准，不重新猜。
2. **入口先枚举**：任何「继续学习/问进度」都先枚举数据根（宿主的目录枚举能力（根路径与匹配模式分开传入，任务目录匹配 `*/progress.md`）；若目录枚举能力不可用或返回异常，以 `python "<技能根>/scripts/task_index.py" --root "<数据根>"` 兜底），再匹配任务。
3. **不逃逸**：所有写入必须落在数据根之内（红线 CR-7）。

**根解析优先级（F11，从高到低，命中即止）**：

1. **明确用户路径**：用户显式给出的数据根 / 工作区路径；
2. **已知活动任务**：progress.md 已写「数据根」字段（规则 1）→ 直接采用；
3. **宿主工作区根**：宿主提供的工作区根下 `<工作区根>/.learning/`；
4. **限定项目发现**：在当前工作区范围内**限定深度**发现 `.learning/`（**不做全机扫描**）；
5. **当前目录兜底**：`<cwd>/.learning/`（仅当以上皆不可得，且视为**待确认**）。

- **跨 cwd 必须找到同一任务**（冒烟自检口径不变）；**不同 cwd 不得因兜底根制造重复任务**。
- **续学时若发现失败，不自动新建任务**；确实不明时**只向用户确认一次工作区**（不反复追问），确认后再按优先级解析。

> 冒烟自检：两个不同 cwd 的会话访问同一主题，必须定位到同一 `<数据根>/<slug>/progress.md`（以「数据根」字段与 slug 为准）。

## 目录布局

```
<数据根>/                          # = <工作区根>/.learning/
├── index.json                     # 派生索引（由脚本重建，禁止手改）
├── profile.md                     # 学习者画像（可选全局文件，跨任务共享；见「学习者画像」小节）
└── <slug>/                        # 每个主题一个目录，单属主免冲突
    ├── progress.md                # 唯一人类可读事实源
    ├── 知识清单.md                # KP 清单（任务目录第一层，与 progress.md 平级）
    ├── materials/                 # 讲义：NN-<小节名>.md；结课另有 复习清单-<课程名>.md
    ├── exercises/                 # 题组与判分：NN-<小节名>-<日期>.md
    └── trace.jsonl                # 结构化执行轨迹（可选，默认关闭；测评时启用）
```

- `materials/00-备课来源.md` 为可选备料台账（无材料任务；00 为专号，不占小节编号，不参与 `exercises/` 判定比对；无此文件合法）。
- `<数据根>/index.json` 是**派生缓存**，由 `<技能根>/scripts/task_index.py` 从各 `<数据根>/<slug>/progress.md` 重建，**绝不手工编辑**（单一事实源是 progress.md，索引只是它的物化视图）。**默认不物化**——`task_index.py` 默认只读、不写缓存；需物化时显式加 `--write-index`（写时**原子替换**：同目录临时文件 + `os.replace`，区分「未变化/写入失败」，失败保留原缓存、不产生半截 JSON）；`scan_status=failed` 时**绝不覆盖**既有缓存。
- 枚举**只扫数据根下第一层**：任务目录 = `<数据根>/<slug>/progress.md`；更深的嵌套目录（如 `<数据根>/a/b/progress.md`）**不在扫描范围**，请勿手动制造深层任务。
- 旧版单文件 = 数据根下第一层的裸 markdown（`*.md`），**扩展名大小写不敏感**（`.md` / `.MD` / `.Md` 均识别）；**但不含合法全局文件**——`profile.md`（学习者画像）不属旧版单文件，枚举与迁移时必须剔除（`task_index.py` 已内置排除名单，勿再判为待迁移任务）。
- **编号契约**：`materials/`、`exercises/` 的文件名编号**推荐两位补零**（`01-`、`02-`…）；脚本对「已掌握↔判分记录」的比对**同时接受 `1-` 与 `01-` 两种写法**（宽容匹配），但为一致性仍建议两位补零。文件名中的小节名须为**文件系统安全字符**（去除 `/ \ : * ? " < > |` 与首尾空格，含全角标点的小节名以连字符替换后落文件名）。

### 题组与判分文件（exercises/）

```markdown

## 题组
1. <题面>
2. <题面>
3. <题面（判定题：考「何时用」）>

## 关键能力
- C1：<本节核心方法 / 唯一核心应用题 / 主要易错点>（1–3 项；每项须能独立判分）

## 作答与判分
- 题 1：作答「<学员答案>」｜信心=4｜正确性=对｜独立性=独立｜流畅度=常规｜能力=C1｜调度档=Good
- 块 8a（推进）：作答「<学员答案>」｜信心=<1-5，可选>｜正确性=对｜独立性=独立｜流畅度=常规｜用途=推进｜块=8a｜KP=KP-03-08
- 题 2：作答「<学员答案>」｜信心=2｜正确性=错｜独立性=独立（错因=理解性，级=B）→ 入错题本｜调度档=Again

## 复述检查清单

## 参考答案（判分完成后回填；可选）
- 题 1：<答案或要点>｜依据：<解:… 或 见 materials/NN-<小节>.md 概念 N 的 ③ 框>
- 题 2：<要点行；主观/论述题可只写「见讲义概念 N 的 ③ 框」>
```

- **参考答案区块（可选，判分后回填）**：位置固定在文件**末尾**（「作答与判分」之后）——`progress_check.py` 的 `evidence_section` 截到下一个二级标题为止，区块放在判分段之前会把判分记录截断。**出题时不预写**（防泄题），判分完成后回填；客观题写「答案 + 一句依据」，主观/论述题写要点行或 `见 materials/NN-…md 概念 N 的 ③ 框`，不复制讲义全文。**正文唯一事实源仍是讲义 ③**：本区块只做复习索引，二者不一致时以 ③ 为准并同步更正。**不另建 `-答案.md` 分册**——`exercises/` 内文件按编号前缀被当作判分证据消费，同前缀的答案文件会被误当证据（`E-EMPTY-EVIDENCE` / 证据错配）。
- **组卷（独立触发「组一套卷」）**：卷末同设 `## 参考答案` 区块，题面区顶部写一行「作答后再看文末答案」；不拆答案册，命名与普通题组一致。

- **结课综合测验（`99-`）额外一行**：文件头写 `目标线：a/b`（如 `目标线：4/5`，可写 `目标线：7/10` 这类非 5 题卷）。这是 `progress_check.py` 判达标线的机器可读入口：**不写按默认 4/5**，写了按该值判（`a ≤ b`，非法值回落默认）。普通小节题组不需要这一行；收紧/放宽达标线却没写这行，脚本仍按 4/5 拦停。
- **分型标签（v6.1）**：若 `知识清单.md` 的 KP 声明了类型/视觉任务，attempt 行补 `KP=KP-xx-xx`；视觉任务再加 `｜视觉=<任务>`；概念/设计在复述勾选行写该 KP 编号。未声明类型的旧任务不需要补标签。
- **正式/轻量确认（可选）**：关键块正式确认写入 `## 作答与判分`，标 `用途=推进`；有对应 KP 时写 `KP=<id>`，无则只写 `块=<块名>`；计入正确性分母与本节新题总量；不设每节道数上限；不替代题组的关键能力独立通过与小节复述；正式确认可作记忆/程序 KP 的分型证据（带 `KP=<id>` 独立正确），概念/设计仍需复述勾选行含该 KP 编号；早期错误与变式均保留，不删不改。简单块轻量确认不写 `正确性=` 判分行；需要留痕时在学习日志写一句「块名 + 确认方式 + 结果」。
- **块与 KP 映射**：1 个讲授块 = 1 个 KP（当前节目标内的最细知识点）；禁止一块挂多个 KP。一个 KP 若需要多个块，说明它还能再拆成更细的 KP，先拆 KP 再讲。正式确认题有对应 KP 时写 `KP=KP-<节>-<KP序>`（如 `KP-03-08`）；无对应 KP 时只写 `块=<块名>`。`KP-03-08a` 这类编号不合法，脚本不识别；`块=` 是人读字段，不进闸口计算。
- **判分四态（v6.0）**：`正确性=` 只接受 `对 / 部分 / 错 / 未判`（兼容 `正确 / 错误 / correct / incorrect / partial / ungraded` 等写法）。`部分` 计入闸口分母、不计入分子（未达完整正确），按缺失点归因并进薄弱点；如需保留原题再进错题本并标 `结果=部分`，调度档用 `Again`；`未判` 不计入分母、不写 S/D、不进错题本，应补判或作废（脚本给 W 提示，不硬拦）；`作废` 行只保留审计，不计入闸口/S/D。**作废不删除原判分行**，必须写原因；改判时新增一行（可复用原 `attempt_id`，旧行已作废即不参与冲突判定）。
- 判分三维（正确性／独立性／流畅度）与调度档位口径见 `teaching-loop.md` 第 6 节；**闸口按正确性计**（独立正确与提示后正确均计 1；慢不折算，Hard 不记半分），独立性/流畅度另列不折算。**逐关键能力独立通过（v2.5）**：声明了「关键能力」区块时**每项须至少一次独立正确**，关键项错**不能被简单题抵消**（脚本 `E-KEY-ABILITY-UNMET`）；**独立性枚举**（独立 / 提示后·提示②–④ / 未测）——**缺失或 `未测` 一律不推为独立**（`E-NO-INDEPENDENCE`），同一 `attempt_id` 幂等去重、冲突判定报 `E-ATTEMPT-CONFLICT`；**目标为操作/作品型时**「操作作品验收」区块（≥2 个已勾选核验项）与复述清单**等价可替代**。**信心可选**：仅在**反馈前**随作答提交者记「信心=<1-5>」、方可用于 cw／校准；反馈后补报标「信心=回顾性」，**不用于 cw、不用于校准**。时序规则见 `teaching-loop.md` 第 6 节；错题入错题本时同轮完成归因定级（错因/级，见 `teaching-loop.md` 第 8、9 节）。
- **证据内容抽查（W-EMPTY-EVIDENCE）**：判分记录文件存在但**未提供可用证据**（空文件、或只含「作答/判分」标题模板而无真实结果行）→ `progress_check.py` 历史模式输出 `W-EMPTY-EVIDENCE`（warning 级，不阻断旧任务）；**放行模式（`--release`）升级为 `E-EMPTY-EVIDENCE`（error）**——空/模板证据不得支撑本次新增掌握或结课结论。文件缺失仍为 `E-NO-EVIDENCE`（error）。
- 闸口未过时不删题组，补齐判分后继续；S4 变式自创题文件用 `z-` 前缀（见 `phases-and-gates.md` S4）。

## slug 规则与冲突处理

- slug = 主题的稳定标识：小写、去空格、中文转拼音或直接用**主题短名**，仅保留字母/数字/连字符，长度 ≤ 48。
- 生成 step：先枚举既有 slug；无冲突直接用；有冲突则追加序号或短哈希（如 `python-2` / `python-a1b2`）。
- **禁止**在两个不同主题间复用同一 slug；同名不同课程必须区分（避免互相覆盖）。
- 无主题上下文时**不得**生成 slug（红线 SR-1）。

## 版本号体系

三层版本互不混淆：**包版本**（SKILL.md frontmatter `version`，以该字段为准）；**数据 schema 版本**（脚本输出 `schema` 键，如 `learn-task-index/5`、`ltw-due-queue/3`、`ltw-calibration/3`——加键不破坏消费方时 +1，消费方按存在性读取新键）；**兼容代际**（progress.md 条目形态 v2 / v2.1 / v2.2，行为差异见「三种数据形态兼容行为表」）。

**升版规则**：major = 闸口通过线/对外契约行为变更（如 S5 测验通过线分型）；minor = 向后兼容的机制新增（如新增告警码、可选字段）；patch = 修复与表述修正。包内不保留改动历史（零史纪律），版本演进仅以包版本号体现。

**交接、学习记录与讲授证据（v6.2，可选、零迁移）**：四类文本各司其职——`学习日志` 是**事件时间线**（只追加）；`本次交接` 是**下一次开场的摘要**（每次收尾覆盖重写：总结 / 下次先做 / 未解决）；`下次续学` 是**任务状态与动作游标**（阶段、小节、待回应项）；`学习记录` 是**任务级持久洞察**（最多 5–7 条，回答“这个学员在这个任务里为什么卡/为什么通了”，不写流水账）。`学习记录` 不替代 `profile.md` ②：跨任务稳定模式进画像，任务内洞察留本区；**本区不直接写跨任务结论**，判断可跨任务时按 `profile.md` ② 的证据/确认流程另写。没有新洞察时不写，空更新合法。缺少 `本次交接` / `学习记录` 的旧任务，按学习日志最近一条 + `下次续学` 恢复，不补造。**若 `本次交接` 与 `下次续学` 冲突，以 `下次续学` 的阶段/小节/动作游标为准**，开场向学员说明差异，不按交接里的旧话硬推。**下次开场先处理 `未解决`**；同一未解决项跨多次仍未动，转入薄弱点 / 暂缓与范围外 / 学习记录，不无限滞留在交接里。`学习记录` 最多 5–7 条，超出时合并重复、删除低信号或已被推翻的；**讲授证据**只给深讲/关键概念记，同一概念保留最近一条，不逐题记。**讲授证据**只记“已经公开讲给学习者”的内容：逐字引用 + 来源页码/链接；计划、内部思考、工具结果、来源原文都不算；讲授证据只证明“讲过”，不证明“学会”，也不替代判分/复述闸口。来源不可用或不确定时如实说明，不编造。

**记忆写法纪律（学习记录 / profile 共用，v6.2）**：正文/洞察每条 ≤120 字（`profile.md` ② 的作用域、证据、日期、状态等元数据不计入）；用动词短语（“使用 X”“卡在 Y”“换 Z 后能独立完成”），不用形容词标签；每条带证据（日期 + 场景/原话）；推断标“暂定”，只有学员陈述或后续证据才升级；禁用绝对化词（深刻、彻底、完美掌握、专家、热爱、总是、从来不、完全理解）；无证据不写；空更新合法；当前证据与当前表态优先于旧记录；一次困难不得写成全局人格判断。

**动作游标（F08，可选、零迁移）**：恢复只到「阶段 + 小节」不足以区分「待出题 / 待作答 / 待批改 / 待落盘」——续学时先读本行定位**当前动作与待回应项**。出题后中断 → 据「待回应：题组文件 + 题号」继续原题，不重新出题；已答未批改 → 据「最后提交」指向的作答继续批改，不重复作答。无本行的旧任务 = 合法形态，退回「阶段 + 小节」恢复。

**保持复习区（v6.0，可选、零迁移）**：位置在「错题归档」之后、「暂缓与范围外」之前；`scheduler.py due-queue` 把它与「薄弱点」「错题本」一起读取，条目用 `kind=保持` 标识。**写入时机**：① S3 小节达标 → 新增该小节的保持条目；② S4 薄弱点连续 2 轮全对清除 → 转入本区（不得直接消失）；③ S5 结课后复习清单以本区为准。**初始值**：S=3.0、D=3、last=掌握/清除日、due=+3 天（用 `scheduler.py next-interval --new-card --grade good --last <日> --today <日>` 算，不心算）。**日期前缀**：行首 `[YYYY-MM-DD]` 推荐；省略时以元数据 `last`/`due` 或「最近更新」兜底，全部缺失才报 `W-UNPARSED-ITEM` 不入队。**同一小节/知识点只保留一条**：复习时更新原行，不重复追加；对象身份优先用 `lesson_id` 或稳定的知识点名。**复习判分**：按既有条目命令更新 S/D/due；失败（Again）仍留本区，按短间隔重测；若需重讲，按条目对应小节回炉，**不要为同一知识点另建一套 S/D 调度条目**。**已完成任务的保持复习**：仍可由 due-queue 触发 S4，复习后按「复习来源阶段=已完成」返回。旧任务缺本区 = 合法形态，due-queue 零感知，不补建、不批量迁移。

**模块目标与材料覆盖（v6.1，可选、零迁移）**：`模块目标` 每行 `M1 ｜ 模块名 ｜ 学完能独立……`，一句能力句，不是话题清单；修改模块内容时不得违背该句，超出就重新设计。`材料覆盖` 每行 `材料 → M1 / M2`，每份材料至少归入一个模块，不允许静默遗漏。**有材料但缺 `材料覆盖`**，或**有 `材料覆盖` 但缺模块目标** → `W-MODULE-CONTRACT-INCOMPLETE`；无材料任务只写模块目标合法，不报缺覆盖。行畸形或仍是 `<…>`/待填占位 → `W-UNPARSED-MODULE` / `W-UNPARSED-MATERIAL`；`材料覆盖` 条目少于 `材料` 条目，或某份材料的字面名未在覆盖区出现 → `W-MATERIAL-COVERAGE-GAP`（简称/改名可人工确认）。旧任务两区都缺 = 合法形态，不补建、不报错。

**质量保障机制（可选区）**：记录本任务的体例约定（LaTeX 排版 / 答案框形态）与定稿校验结论；**讲义头部指针行指向本区**（头部只写指针，规则正文不进讲义，见 `lecture-styles.md`「讲义头部（两行，不复制规则正文）」）。**自检 W 项的显式后置理由记在本区**（无后置写「无」）——这是 W 后置的唯一落盘位置。缺失 = 合法旧任务形态，零迁移。

**可选 token `子类=`**：错因第六类“过度泛化”写 `错因=理解性` + `子类=过度泛化`；`scheduler.py` 已识别该键（不参与调度计算、不输出到 due-queue），不会再报 `W-META-INVALID`。

**字段合法性**（由 `<技能根>/scripts/progress_check.py` 校验）：`当前阶段`、`类型`、`学科族` 必须为上述枚举值之一；`复习来源阶段` 在 S4 期间必须为合法返回枚举（**逐节学习 / 结课 / 已完成**，任意字符串被拒）。**必填项随阶段变化**：`当前阶段`、`类型`、`学科族`、`目标` 全程必填；**`起点` 在 S0（接料建档）与 S1（诊断摸底，进行中）不要求，自诊断结束进入 S2 起（计划确认中/逐节学习/复习巩固/结课/已完成）必填**——S1 尚未产出「起点」属正常，不得据此误判（修复 F01）。**周里程碑（可选区）**：S2 排期产出、每周首次开课对账（见 `phases-and-gates.md`「周对账」）；旧任务缺失 = 合法形态，不补建、不报错（零迁移）。

**勾选语法**：学习路线用 `- [x] N. <小节名>`（`x`/`X` 均可）标记已掌握、`- [ ] N. <小节名>` 标记未完成；N 为小节序号（阿拉伯数字）。若某行出现勾选语法却不匹配该格式，`<技能根>/scripts/progress_check.py` 将输出 `W-UNPARSED-ROUTE` 告警（不静默吞掉）。

**「暂缓与范围外」区块**：位置在「错题归档」之后、「学习日志」之前；条目为自由文本 + 竖线（`｜`）分段（来源 / 处置 / 触发条件 三段），**不做枚举硬校验**——有竖线分段但字段残缺的条目由 `<技能根>/scripts/progress_check.py` / `<技能根>/scripts/task_index.py` 输出 `W-UNPARSED-HOLD` 告警（不静默、不计入 hold_count）；**无竖线分段的纯自由文本行**不判畸形、仍计入 `hold_count`（解析器宽容口径；建议仍按三段式书写，以便 W-KP-HOLD-CROSS 交叉核对）；无暂缓项时本区写「无」。区块本身**可选**：旧任务缺失 = 合法「未审计」形态（见下方零迁移兼容）。

### 脚本校验码速查（progress_check / scheduler 常用）

> 何时读：脚本报出 `E-*`/`W-*` 码需要释义时。业务机制相关码的详细口径见上文各节；本表为常用码速查，完整码表以脚本输出与 docstring 为准。

**Error 级（`progress_check.py` exit 1，必须处置后重跑）**：

| 码 | 触发条件 |
|---|---|
| `E-NO-PROGRESS` | 任务目录缺 progress.md |
| `E-UNREADABLE-PROGRESS` | progress.md 存在但不可读 |
| `E-MISSING-FIELD` | 缺必填字段（含「起点自进入 S2 起必填」特例；S0/S1 不要求起点） |
| `E-ENUM-PHASE` / `E-ENUM-TYPE` / `E-ENUM-FAMILY` | 阶段 / 类型 / 学科族取值不在枚举内 |
| `E-ENUM-STRATEGY` | 「教学策略」存在但不在 {先测后教, 先教后测}；字段缺失合法 |
| `E-KP-TYPED-GATE` | 已声明类型/视觉任务的 KP 缺对应证据（记忆/程序缺独立正确 attempt、概念/设计缺定性复述、视觉任务缺独立正确 attempt）；或含类型/视觉任务字段的清单行畸形、无法执行分型验收 |
| `E-REVIEW-ORIGIN` | 阶段「复习巩固」缺「复习来源阶段」，或取值不在 {逐节学习, 结课, 已完成} |
| `E-NO-EVIDENCE` | 勾选小节无对应 `NN-` 判分记录（文件缺失为 error） |
| `E-EMPTY-EVIDENCE` | （**放行模式 `--release`**）判分记录为空文件或仅含「作答/判分」模板、无真实结果行——不得支撑本次新增掌握/结课 |
| `E-ROUTE-UNDONE` | （**放行模式**）阶段为「结课/已完成」但学习路线仍有未勾选小节 |
| `E-EVIDENCE-REF-MISSING` | 候选状态里的 `- 本次证据：<文件名>` 指向不存在的文件（候选/放行校验时拦停） |
| `E-FINAL-ATTEMPT-CONFLICT` | 结课综合测验的同一 attempt 结果冲突（`E-ATTEMPT-CONFLICT` 的结课变体） |

**Warning 级（不阻断）**：

| 码 | 触发条件 |
|---|---|
| `W-NO-ROUTE` | 尚无学习路线（S2 前正常） |
| `W-UNPARSED-ROUTE` | 路线行含勾选语法但格式不匹配 |
| `W-UNPARSED-HOLD` | 暂缓条目畸形（缺触发条件段）或一行含多个 KP 编号（粒度不符）；畸形条目计 0 |
| `W-NO-COVERAGE-AUDIT` | 结课/已完成缺「暂缓与范围外」区块或缺审计记录 |
| `W-EMPTY-EVIDENCE` | （历史模式）判分记录为空文件或仅含「作答/判分」模板、无真实结果行；放行模式升级为 `E-EMPTY-EVIDENCE` |
| `W-VOIDED-ATTEMPT` | （放行模式）判分记录含 `作废` 行——原行保留审计，不计入闸口/S/D；不阻断，但须确认原因已写 |
| `W-MODULE-CONTRACT-INCOMPLETE` | 「模块目标」与「材料覆盖」只出现一个（两区都缺 = 旧任务合法，不报） |
| `W-UNPARSED-MODULE` | 「模块目标」行畸形（应为 M1 ｜ 模块名 ｜ 学完能独立……） |
| `W-UNPARSED-MATERIAL` | 「材料覆盖」行畸形（应为 材料 → M1 / M2） |
| `W-MATERIAL-COVERAGE-GAP` | 「材料覆盖」条目少于「材料」条目，或某份材料的字面名未在覆盖区出现；提示核对是否有材料未归入模块（简称/改名可人工确认） |
| `W-UNGRADED-ATTEMPT` | （放行模式）判分记录含 `未判` 行——不计入闸口分母；应补判或作废（W 提示，不硬拦），不阻断旧任务 |
| `W-MULTI-EVIDENCE` | 同一小节存在多份结构真实的判分证据，已按「日期最新 → 字典序最大」确定性选定；可用 `- 本次证据：<文件名>` 指定 |
| `W-CONFIDENCE-AMBIGUOUS` | （scheduler 侧）信心/时序身份歧义（孤立 cw、低信心 cw、同 evt 投影冲突）；该观察作废，不计入校准 |
| `W-KP-LIST-MISSING` | 清单指针存在但文件不存在/不可读 |
| `W-UNPARSED-KP` | 清单行畸形 / 状态非法 / 前置引用不存在 / 重复编号 / 覆盖范围行写法偏差；畸形行不计入摘要计数 |
| `W-KP-SUMMARY-MISMATCH` | 覆盖摘要行计数与逐行实际不符 |
| `W-KP-HOLD-CROSS` | 清单摘要暂缓数 ≠ 暂缓区块可比条目数，或排除数 ≠ 处置排除条目数 |
| `W-KP-STATE-MISMATCH` | 小节已掌握 × 清单该节存在无摸底括注的「未讲」KP（带「已会」括注豁免） |
| `W-STALE-REVIEW-ORIGIN` | 复习来源阶段指向已失效的阶段值 |
| `W-PROGRESS-MISSING` / `W-PROGRESS-UNREADABLE` | （scheduler 侧）任务缺 progress.md / 不可读，该任务跳过不入队 |
| `W-UNPARSED-ITEM` | （scheduler 侧）薄弱点/错题/保持复习行无法解析或缺（合法）日期，不入队不入统计；保持复习行连元数据 `last`/`due` 与「最近更新」都无可推算日期时才报此码；坏 S/D 值走缺省链并标 migrated，单条坏数据不使整队列裸崩 |

### 复习调度字段（薄弱点 / 错题本 / 保持复习条目元数据）

> 何时读：写薄弱点/错题/保持复习条目的元数据（挂载点、字段表、cw/顽固语义）时。

薄弱点条目的调度元数据放**行尾全角括号内**（半角括号 `()` 亦兼容，推荐全角）、逗号分隔的 `键=值`（`cw`/`顽固` 为无值标记）；错题本与保持复习条目在行尾追加「｜ 元数据：…」段（竖线分段与「元数据：」冒号均全角/半角双兼容）。保持复习行须以 `[YYYY-MM-DD]` 掌握日期开头，缺日期时用「最近更新」兜底并告警。解析器只认这些挂载点，其余文本不动。`S'/D'/due` 的计算由 `<技能根>/scripts/scheduler.py next-interval` 负责（判分归模型、算数归脚本，调用细则见 `phases-and-gates.md` S4）。`due-queue` 输出新增 `reason` 字段（到期/逾期/优先级的人类可读说明），schema 为 `ltw-due-queue/3`。`错因`/`级`/`meta_default` 只对薄弱点/错题有意义；`kind=保持` 时前者为空、`meta_default=false`，不参与问题元数据。

| 字段 | 类型/取值 | 语义 | 默认值（缺省时） |
|------|-----------|------|------------------|
| S | 浮点（天） | 稳定天数，间隔重复核心参数 | 3.0 |
| D | 数值 0.5 粒度，[1,5] | 难度 | 3 |
| last | YYYY-MM-DD | 最近一次判分日期（绝对日期，禁相对日期） | 取 progress.md「最近更新」；再缺 → 当日 |
| due | YYYY-MM-DD | 下次复习日。**新写由 `scheduler.py` 以「本次复习日 + interval」计算**（见 `phases-and-gates.md` S4 调度速查）；旧条目缺 due 时按 `last + round(S)` 兜底推算 | 由 last 推算 |
| 信心 | 1–5 | 作答信心自评（**反馈前**提交方可用于 cw/校准；反馈后补报标回顾性） | 3（中性） |
| cw | 标记（无值） | 自信但错（**反馈前**信心 ≥4 且判错），due-queue 排序优先 | 无 |
| 顽固 | 标记（无值） | 提示阶梯两次到梯底，重教不重测（见 S3/S4） | 无 |
| evt | 可选 ID | **作答事件 ID（v2.3）**：同一次作答的投影（错题 / 薄弱点）共享同一 `evt`，供校准统计去重（T04）；旧条目缺 = 合法 | 无 |
| 错因 | 枚举：知识性 / 理解性 / 技巧性 | 归因分类，决定 S4 补救动作（重学 / 审题圈画 / 限时技巧）。**语义属性，归模型判断写入，禁止脚本代判** | 知识性 |
| 级 | 枚举：A / B / C | A=反复出错 / 直接影响学习目标达成的核心条目（详细整理+变式）；B=一般理解偏差（记思路）；C=纯粗心（仅标知识点）。与错因同轮由模型定级，S4 复习判分可升降级 | B |

- `cw` 只由「信心 ≥4 且判错」产生；cw 条目修复后照常走清除/归档规则。
- due-queue 对 `顽固` 条目标 `teach:true`（排序不豁免），由模型据文本规则改走重教。
- **`错因` 枚举放元数据段，与既有自由文本「错因：<具体描述>」并存不冲突**：自由文本答「错在哪」（行内 `错因：` 全角冒号写法），枚举答「属哪类、该用什么补救」（元数据段内 `错因=` 等号写法）。解析器只在元数据段内搜 `错因=`，正则锚定于元数据段，不会误吃行首自由文本。
- **`级` 与 `错因` 是内容属性（错什么），S/D 是调度属性（何时再练），互不替代；`级` 不参与 due-queue 排序**（排序契约 cw→最逾期→due 早→稳定序不变），分级只影响整理深度与复盘注意力，脚本仅在输出中回显 错因/级 供模型取用。

### 字段向后兼容（旧条目缺字段）

> 何时读：遇到无新字段的旧条目，决定补默认值的方式与责任人时。

1. **不做批量迁移、不新建文件**：v2 条目（无括号/无元数据段）与 v2.1 条目（有调度字段与信心、缺 错因/级）均**原样保留**，缺新字段按上表默认值处理。
2. **补齐时机与责任人**：**首次在 S4 复习 / S3 热身 / due-queue 中遇到该条目时**，由**模型**按默认值（S=3.0、D=3）计算 due 并**顺带在下一次对 progress.md 的正常文件写入/编辑 中补写**（如判分落盘时一并补），不为迁移单独发起写盘。
3. **due-queue 对旧格式的行为**：有「最近更新」→ 按默认 S/D 推算 due，条目标 `migrated:true` 输出；连「最近更新」都没有 → 该条目**不入队**，输出 `W-UNPARSED-ITEM` 告警，**exit 0 不报错不崩溃**（最坏情况输出空队列）。
4. 日期一律 `YYYY-MM-DD` 绝对日期（既有铁律延伸到新字段）。
5. **错因是语义属性，模型侧不得盲目补写默认值「知识性」**：S/D/last/due 是**数值参数**，补默认无害，沿用第 2 条「顺带补写」；但 `错因`（与 `级` 同理）缺省值只是**脚本输出侧**的占位回显（脚本输出标 `meta_default:true`，告知消费方这是补默认不是观测）——模型侧遇到旧条目复习时，必须**按当下归因判断写入真实值**（这本身就是 S4 的归因动作），补错默认会把「技巧性失误」误导向「回归材料重学」这一最重补救，与「纠错优先于重讲」总原则相悖。
6. **缺省归因可修正话术**：S4 遇到错因为缺省推断的条目，可向学员说明「该条错因为缺省推断，如与实际不符请指正，可推翻重归因」——允许学员或后续判分推翻重归因。

### 稳定引用 · 对账 · 提交顺序（F09 / F10 / F12）

> 何时读：新增/重排小节、写双写账本、多文件落盘（掌握/结课/跨阶段）时。

**稳定引用（F09，可选、append-only、零迁移）**——把「对象身份」与「展示顺序」解耦。**落点规定（消费者优先按稳定 ID 匹配）**：
- `lesson_id`：小节稳定标识（如 `L-02`），**改名 / 同名 / 换序都不变**。**落点三处**：①**路线行**——`- [x] 1. 循环（lesson_id=L-B）`（全/半角括号均可）；②**判分记录文件头**——首行或标题下写 `lesson_id=L-B`（如 `# 循环，lesson_id=L-B`）；③**讲义/材料头**同理。`当前小节` 序号仍保留供人读，二者分离。
- **匹配规则（`progress_check.py` 的消费口径）**：路线行声明了 `lesson_id` 时，**先按 ID 在 `exercises/` 中精确匹配**该 ID 的证据文件（重排后序号对不上也能匹配正确对象）；**匹配不到时**回退按文件名序号前缀匹配（旧资料零迁移）；**回退命中却声明了另一个 `lesson_id` → `E-EVIDENCE-ID-MISMATCH`**（放行模式拦停，防止串用他节证据）。
- `attempt_id` / `evt`：一次作答的稳定标识，写入条目元数据段 `evt=`（或判分行 `attempt_id=` 前缀）；同一作答产生的「错题」与「薄弱点」两条投影**共享同一 `evt`**（供校准去重）。
- **动作游标引用**：`## 下次续学` 行的「待回应」须指向**存在的**判分记录（文件名或其前缀）、「最后提交」须指向**已出现的** `evt=`/`attempt_id=` 值；悬空引用在放行模式报 `E-CURSOR-DANGLING`（历史模式 `W-CURSOR-DANGLING`），恢复时不得把悬空游标当有效定位。
- **不自动重编号**：既有 KP ID（`KP-<节序>-<KP序>`）与旧数据一律保留原值；小节改名/换序后**引用材料与作答仍对应正确对象**，不靠序号猜、不追溯撤销历史。
- 脚本对未知可选字段**零感知**——旧任务缺这些键 = 合法，无需迁移。

**对账（F10，按对象 ID）**：「清单状态」与「progress.md 处置」双写按**对象 ID 集合对账**——有 KP 时以 `KP-xx-xx` 为准（状态单源 + 处置理由单源，progress.md 只存摘要）；**数量相同但对象不同也能检出**（W-KP-HOLD-CROSS 列出「仅清单 / 仅区块」差异，见上「暂缓/排除双写」条）；无 KP 的任务保留任务级处置。不新增第三份账本。

**提交顺序（F12，先校验拟提交状态、后提交，可重试）**——多文件更新按固定次序，断在任一步都停在「未提交」态，绝不出现「无证据已掌握」：
1. 先写**证据与材料**（`exercises/` 判分、`materials/` 讲义）；
2. 再准备 **KP / 处置变更**（清单状态、暂缓与范围外）；
3. **校验拟提交状态**——把**目标状态**送进校验器，而不是只校验磁盘旧状态：`progress_check.py <任务目录> --release --proposed-phase <目标阶段>`（拟转阶段时）或 `--staged <候选 progress 快照>`（候选文件），并用 `--changed-lessons <本次新增小节号>` 限定增量范围；校验通过后才写盘（脚本输出 `proposed_state_supplied` / `checked_lessons` 回显；未提供拟提交状态时 `proposed_state_supplied:false` + `W-NO-PROPOSED-STATE`，**不得据此声称目标变更已校验**）；
4. 最后**提交掌握 / 阶段**（progress.md 阶段字段、小节勾选）；
5. 派生**摘要**（覆盖摘要行、范围快照）。
- 失败保留可重试点（脚本幂等、文件写入/编辑能力覆盖同值 → 重跑不重复事件）；**不宣称已有跨文件原子事务**——只保证次序与可重试。

> 何时读：判断旧任务缺区块/清单/画像是否合法、何时顺带补建时。

1. **缺区块 = 合法「未审计」形态**：v2 / v2.1 / v2.2 旧任务无「暂缓与范围外」区块——不补建、不批量迁移、不报错；任务下次到达审计触发点（转结课 / 章末 / 考期阈值 / 用户要求，见 `phases-and-gates.md`「覆盖率审计」）时自然补审计，模型在**下一次正常文件写入/编辑 中顺带补区块**（沿用既有「顺带补写」惯例，不为迁移单独发起写盘——与上方兼容规则第 2 条同构）。

4. **知识清单零迁移**：既有任务无清单、progress.md 无指针 = 合法形态，**不补建、不批量迁移、不报错**，KP 相关告警（W-KP-*）一律不触发；指针存在但文件不存在 → `W-KP-LIST-MISSING`（warning 级）；旧任务到达审计触发点需顺带补建清单时，按 progress.md 现状初始化状态并**向用户显式声明补建**（沿用「顺带补写」惯例，不为迁移单独发起写盘——与上方兼容规则第 2 条同构）。

### 校准画像（派生数据，不落盘）

> 何时读：S4 开场校准反馈前（分母口径、畸形判读、呈现措辞）。

校准画像是脚本对既有「信心 / cw」元数据的**实时只读统计**：**不新增任何 progress.md 字段，不落任何新文件**。进入 S4 时由模型运行：

`python "<技能根>/scripts/scheduler.py" calibration --root "<数据根>" [--slug "<slug>"]`

- **指标名称**：**当前问题记录中的高信心错误占比**（cw 条目数 ÷ 分母；脚本键仍为 `overconfidence_rate`）——它只描述「当前未清除问题记录」中高信心错误的投影比例，**不得用来评价学员整体人格或整体校准水平**（分母只含问题记录、不含正确作答，天然不代表整体校准）。若需整体校准判断，**必须另有**包含正确与错误作答、采样时机明确的有效窗口——当前快照口径不提供该窗口。
- **畸形数据判读（v2.4 起口径收紧）**：脚本先按 `evt` 归组、合并互补字段，再形成「合法观察」（可推算日期 + 无冲突），最后才统计。**分子 `cw` 只数「反馈前信心 ≥4 且判错」的合法观察**——`cw` 必须是同口径高信心错误观察的**子集**；任何**孤立 cw**（有 cw 无显式信心）、**低信心 cw**（信心 <4）或**同 evt 投影冲突**都会单独告警（`W-CW-ORPHAN` / `W-CW-LOWCONF` / `W-CONFIDENCE-AMBIGUOUS`）并令脚本**输出 `overconfidence_rate: null` + `rate_valid:false` + `invalid_reason`**（不展示不可靠读数）；先核对补齐数据，不得采信该画像做元认知教学。
- **窗口口径：快照口径，不做时间窗**。统计对象是「当前未清除的条目」，教学呈现措辞必须用「当前快照」，禁称「全程累计」。
- **投影去重与口径披露（T04，脚本键 `dedup_mode` / `evt_tagged_count` / `legacy_count`）**：条目**带 `evt=` 作答事件 ID** 时按事件归组，同一作答的投影（错题/薄弱点）**只计一次**，互补字段合并；**无 ID 的旧条目**沿用「两条投影各计一次」的**声明式双计**。全部带 ID → `dedup_mode:"by_evt"`；全部无 ID → `"legacy_double_count"`；**新旧混排 → `"mixed"`**，并在呈现时显式披露 `evt_tagged_count` / `legacy_count`（不得统一标 `by_evt` 掩盖旧条目计数）。优雅降级：旧任务读数**不静默变样**，仅新写数据启用按事件去重。
- **两层语义（防模型混用）**：`cw` 是**逐条重测信号**——单条「自信但错」的调度标记，回答「这条该不该先练」（作用在 due-queue 排序优先）；校准画像是**聚合教学素材**——把当前问题记录里的信心标记汇总成**问题投影比例**，**只回答「当前错题快照里的高信心占比」**，**不得**回答「这位学员整体是否系统性高估自己」（那需要含正确作答的独立窗口）。一句话：**cw 是画像的输入行，画像是 cw 的列总和**。脚本只算不判；「本快照读数如何解读与呈现」归模型，但**不得越界作整体人格判断**。

## 知识清单文件

**文件**：`<数据根>/<slug>/知识清单.md`，任务目录第一层、与 progress.md 平级（不放 materials/）。**单一事实源声明**：KP 集合与 KP 状态的唯一事实源是本文件；progress.md 只存指针，不重复记账。**原子判据**：每个 KP = 当前节目标内的最细知识点，1 道题可独立检验；需 2 道题分别检验两个判断 → 拆 KP；不设时间上限。不达标条目拆分或合并后再入清单，归模型纪律。**状态枚举**：未讲 / 已讲 / 暂缓 / 排除（与审计四态同源）。

**格式模板**（逐行 + 全角 ｜ 分段；**示例仅为格式演示，KP 的取舍与依赖声明规则本身领域无关**）：

```markdown
# 知识清单：<主题>
- 版本：<N>              # KP 集合变化（增/删/拆）时 +1；状态翻转不改版本
```

## 学习者画像（可选全局文件）

**文件**：`<数据根>/profile.md`，**全局唯一**、跨任务共享（画像放数据根第一层、与任务目录平级）。**偏好按作用域生效（F13）**：①层 = 学员明说的**通用偏好**，跨主题适用；②层「稳定模式」**默认任务级作用域**（可标任务/学科族/全局），**带证据、可复评、可关闭**；**教法裁决与类比领域按任务/学科族作用域生效**，**不得当作跨主题的全局人格标签**，也不得据单任务低效就对同类主题预判。**可选**：无此文件 = 合法形态，不强制创建、不报错；首次触发建立时机 = S1 摸底顺带问「类比领域」时（见 `phases-and-gates.md` S1），用户不便回答则跳过。**单一事实源声明**：画像内容的唯一事实源是本文件；progress.md 不重复记账，讲授/类比时由模型现场读取。

**格式模板**（三层结构，逐层追加）：

```markdown

- 最近更新：<YYYY-MM-DD>
```

**三条铁律（画像纪律）**：

1. **①层只存学员明说的**，且只收**明确通用偏好**（跨主题适用）：模型观察到的偏好不算——学员明确说「讲慢点 / 别用类比讲代码」才进①层；擅自给学员贴偏好标签是越界。**任务级偏好不进①层全局段**——落到对应任务或②层作用域。
2. **②层必须有证据且带作用域**：每条稳定模式附 ≥2 条独立证据（日期 + 原话/场景）；**「永远不要从一次观察直接升级成画像」**——单次表现只进③层记场景，第三次以上同向证据才允许升②层。**教学方法裁决**带条件与作用域、证据与日期，**可复评/关闭/删除**——低效裁决只在作用域内生效，换学科族或换目标时**重新评估**，不做「连续 N 次低效即永久禁用」的绝对处置。
3. **写入前展示确认**：①层学员亲口说的事实**免确认**——学员刚说过的内容直接落盘，导师以自然话术带过（如「好，类比就用做饭」），不重复问「可以存吗」；新增②层条目时，把要写的内容读给学员、明确说「可以/对/保存」后才落盘；③层追加不需要逐条确认，但下次读到时学员可要求删除任何一条；**学员任何时候可要求删除/关闭②层任一条裁决**。

**写法纪律（v6.2，画像与学习记录共用）**：每条 ≤120 字；用**动词短语**（“用 X 能独立完成”“卡在 Y”“换 Z 后通过”），不用形容词标签；每条带**证据**（日期 + 场景/原话）；推断标“暂定”，只有学员陈述或后续证据才升级；禁用绝对化词（深刻、彻底、完美掌握、专家、热爱、总是、从来不、完全理解）；无证据不写；空更新合法；**当前证据与当前表态优先于旧记录**；一次困难不得写成全局人格判断。正例：“遇到递归先画调用栈再写代码（2026-10-20 学员原话：画出来就不乱了）”；反例：“学员递归很差 / 彻底掌握了递归”。

**消费方**：S3 讲授类比优先取①层「类比领域」（衔接 `lecture-styles.md`「类比纪律」）；跨界三猜想的「确证已会」可用②层稳定模式作证据之一（仍以摸底判分/亲口确认为最强）；S3 讲授呈现与④批改的反馈措辞同取①层沟通约定；**任务级偏好按任务作用域读取**；「换角度重讲」/换讲义风格时**先查②层教学方法裁决**，**仅在其作用域内且状态为「生效」时**才不重复推该方法（裁决可复评/关闭/删除）。**画像不参与任何闸口判定、不进脚本**——它是教学个性化素材，不是调度数据。

**零迁移**：既有任务无 profile.md = 合法形态，不补建、不批量迁移、不报错；脚本（task_index / progress_check / scheduler / kp_sort）**零感知**此文件，不出任何告警。

## 旧版迁移映射

**v6.0 零迁移补充**：旧判分行只有 `对/错` 仍按既有语义解析；`部分/未判/作废` 是新增可选写法，不要求回填。旧任务没有 `## 保持复习` 区 = 合法形态，`due-queue` 不报错、不补建；仅当本次新增大纲/复习动作需要时才按新格式追加。不得为了「升级」批量改写旧判分记录或旧 progress.md。

发现旧版数据时按类型处理，**迁移前先备份原文件、迁移后告知用户**（红线 CR-6）：

| 旧形态 | 识别 | 迁移动作 | 阶段取值 |
|--------|------|----------|----------|
| 目录 + progress.md（v1） | 有目录、progress.md 缺「数据根/复习来源阶段」 | 补齐新字段；保留原内容 | 沿用原「当前阶段」；缺失则按下表推断 |
| 单文件 `<slug>.md` | 数据根下只有裸 markdown | 建 `<slug>/` 目录，写 progress.md，建 materials/、exercises/ | 见下方推断 |

**阶段推断规则（无「当前阶段」字段时）**：

1. 有「学习路线」且有小节已勾选 → 逐节学习（当前小节 = 首个未勾选）。
2. 有路线、无小节勾选 → 计划确认中。
3. 只有材料/目标、无路线 → 诊断摸底。
4. 完全空白或无法解析 → 接料建档（S0），并把原文件内容存入「材料」区，不丢数据。

**冲突处理**：目标目录已存在 → 不覆盖，改用带后缀的 slug，或经用户确认后覆盖（红线 CR-1）。

**备份位置与删旧文件**：备份写到 `<数据根>/_backup/<YYYY-MM-DD>/<原文件名>`——放在第二层子目录，枚举只扫第一层裸 md，备份不会被误判成第二份待迁移数据；文件用**复制**不用移动，验证通过前原件不离开原位。删旧文件须同时满足四条：① 备份与原件**逐字一致**；② `task_index.py` 枚举正确（新任务 `task_count` 命中、`legacy_single_files` 不再含该文件）；③ `progress_check.py` 已跑；④ 用户明确确认删除。**若 `progress_check` 报 `E-*`**（典型：旧数据「小节已勾选但无判分记录」→ `E-NO-EVIDENCE`）：**旧文件先留着**，处置完（补真实确认题，或经确认把该节改回未勾选）再删；只有用户明确接受「带着这条 E 迁移」时才可删，并在学习日志记下该决定。**迁移完成 ≠ 校验全绿**——如实暴露 E 并处置，才算完成，不得为让校验变绿补造判分记录。

## 异常分支与降级

- 与当前阶段无关且未命中快捷指令的输入：拉回当前阶段动作，不重开话题。
- 续学且距上次 ≥3 天：先出 1 道 30 秒回忆题（上次小节核心点）；答不出 → 3 分钟回顾再继续；学员说「直接继续」→ 跳过；不计入闸口。
- 说「继续」但枚举为空：明确告知「未发现已有任务」，先确认一句「要在这个工作区新建学习，还是历史记录在其他工作区」；确认后再按新任务走 S0（红线 SR-2 要求先枚举）。
- 换工作区/换设备：把旧工作区数据根下的 `<slug>/` 任务目录与 `profile.md` 复制到新工作区数据根（slug 冲突按既有规则追加序号或短哈希）；迁移属不可逆动作，走 CR-6 确认；完成后跑一次 `task_index.py --root <新数据根>` 验证枚举。
- **单属主边界（设计取舍，非缺陷）**：本技能**不做**多设备并发写保护、**不做**自动合并、**不做**迁移自动回滚——同一数据根同一时刻只应有一个写入者。多设备各改过同一任务时，按 CR-1 只读比对 → 列差异与冲突 → 备份 → **由用户选定合并结果**后再写；没有 `merge`/`lock`/`rollback` 子命令，也不应以「测试通过」为名要求脚本自动合并。
- 材料解析失败：一级降级——请用户粘贴目录或口述要点；二级降级——先用主题通用脉络开课，「边学边补」，后续校准。
- 任务中途追加材料解析失败：按一级降级处理；不便口述时二级降级——本次不加材料、续用原对照源，并在学习日志中声明该处置。
- 连续两轮大面积答错：主动建议放慢，插入一节巩固课或回退前置小节（受 S3 回退终止条件约束）。
- 说「下课/结束学习/退出家教模式」：**先落盘**（阶段、产出、下次续学点、动作游标、Trace 收尾行），再退出家教模式，恢复正常助手行为。落盘内容含**范围快照**（未讲 M 项、暂缓 K 项）。**收尾默认给一句续学点 + 剩余/暂缓计数**（如「下次从第 4 节起，还剩 3 节未讲、2 项暂缓」）；**详细清单落 progress.md，不逐条念**（F14）。**区分「漏讲」与「正常的未来章节」**：正常未到的后续小节不必逐条报，只有越过计划顺序却缺失的才点名（衔接 🟡 SR-7）。学员说下课即**简短退出**，不被迫继续做覆盖审计。

## 快捷指令明细

- **问进度**（「我的学习进度」「学到哪了」）：读 progress.md **只读**汇报——当前阶段、小节完成度、薄弱点与错题数量、下次续学点；汇报**必须含未讲条数与暂缓条数**（**未讲条数 = 路线未勾选数；暂缓条数 = hold_count − excluded_count**），**不得只以学习路线为分母报完成度**——路线可能缺节，覆盖缺口须脱离路线分母独立可见；**不推进阶段、不改任务数据**（`index.json` 属派生缓存、由脚本重建，不受「不改文件」限制；**task_index 默认即只读、不写缓存**，需物化时才加 `--write-index`）。progress.md 记有清单指针时，一并**只读**汇报清单文件头「覆盖摘要」行的 KP 口径（如「KP 未讲 a/总 M」，带口径标签），不改任何文件；无清单任务维持原口径。**可选掌握徽章行**：薄弱点/错题条目中带调度元数据者，按稳定度 S 分档标注（🟥 S<3 天 ｜ 🟨 3–13 天 ｜ 🟩 14–89 天 ｜ 🟦 ≥90 天 ｜ ⬜ 未测）——纯呈现层，从已有元数据读值即可，不改任何文件、不新算数据；学员未要求明细时一句带过。**可选连击行**：从学习日志的日期序列推导**连续学习天数**（连续自然日有学习日志记录即计），呈现为「已连续 N 天有学习记录」；**断档不评判、不追责**，一句「断过 X 天，今天接上」即可——与徽章行同为纯呈现层，从既有数据推导，不改任何文件。
- **学习简报**（「学习简报」「学习周报」）：只读 progress.md 与 exercises/，生成 `materials/简报-<YYYY-MM-DD>.md`，含六项（本周节数与时长、正确率与独立性、薄弱点 Top3、错题 Top3、下周安排、下周优先解决的一件事）；**时长/正确率无记录时写「未记录/未测」，不估算、不补造**；不引用聊天原文、不自动发送、不改阶段。

- **帮我复习 X**：有进行中任务 → 进入 S4；**已完成任务 → 视同可复习对象**，按归档错题与复习清单出题，并记录「复习来源阶段=已完成」——**复习结束返回「已完成」，不撤销课程结果、不丢返回点**；无任何任务 → 先澄清（见近邻陷阱），不凭空建档。

## 结构化 Trace 输出（可选，默认关闭）

仅当回归测评需要过程数据时，才在闸口推进或会话收尾向 `<任务目录>/trace.jsonl` **追加一行** JSON（幂等，追加不改旧行）；**日常使用不强制记录**，不得因未记 Trace 而阻塞任何流程。字段稳定，供测评做「过程对比」与「基线回归」：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts` | string | ISO8601 时间戳 |
| `session_id` | string | 本次会话标识 |
| `phase` | string | 阶段名（枚举同 progress.md） |
| `step` | string | 阶段·动作（如 `S3·练习`） |
| `gate` | string | 本次对应的闸口判据 |
| `gate_result` | string | `pass` / `fail` / `na` |
| `tools` | array | 本步用到的工具名 |
| `files` | array | 本步读写的文件（相对数据根） |
| `evidence` | string | 落盘证据的定位（题号/检查清单/用户原话摘录） |
| `tokens` | int/null | 本步 token 消耗（会话末由平台回填，不可得填 null） |
| `duration_ms` | int/null | 本步耗时（同上） |

## 成本画像埋点

开启 Trace 时，会话收尾追加一条 `kind:"session_summary"` 记录，采集效率指标：

- `tool_calls`（本会话工具调用次数，可计数）
- `files_touched`（读写文件数，可计数）
- `gate_passes` / `gate_fails`（闸口通过/未通过次数，可计数）
- `tokens_total` / `duration_ms_total`（平台可回填则记，否则 null）
- `retries`（重试次数）

**用途**：让「效率退化」在回归测评中可被机器判定（如 token 或工具调用数超出基线的某比例即报警）。指标只增不减地追加，历史基线可逐次对比。

## 幂等与不可逆动作

- **幂等**：闸口推进/落盘动作在重复执行下结果一致——先读后写，已达标则不重复改写；`<任务目录>/trace.jsonl` 追加行允许多次运行，但同一 `(session_id, step)` 不重复落盘。
- **不可逆硬关卡**：删除任务目录、覆盖既有 progress.md、迁移旧版数据、整体重排已确认计划，四项为不可逆动作，执行前必须走 `redlines.md` 的停即报告模板获得用户确认。
