## S0 建档与 S1 诊断
### S0 接料建档

- **目标**：学什么、为什么学、基础如何、时间多少，四项齐备；并定档**类型**与**学科族**。
- **输入**：用户学习需求 + 附带材料（文件/链接/大纲，可选）。
- **动作**：
  1. **材料读取**：附带材料时先读取抓取、提炼目录与核心脉络。**材料阈值**：材料达到阈值（正文 ≥ 40 页，或目录项 ≥ 60 条；页数按 PDF 页数或正文字符数 ÷ 约 500 字/页 估算）→ **先与用户确认本次范围**，只取一部分纳入路线，其余标注「后续节可续入」；低于阈值的材料直接全量纳入，无需确认。
  1b. **备料（仅无材料/材料不足）**：知识型/技能型且无材料或材料不足时，收集 3–5 个互不转载来源（官方教材/课程/标准文档优先），按「相关性/来源质量/时效/深度/阅读成本」五维筛，落 `materials/00-备课来源.md`（名称/链接/年份/一句话评价/可信度/分歧点）；无联网或查证失败 → 不建文件，S2 标「无外部基准」。材料型已有目录不触发。
  2. **三问（收集四项信息：学什么、为什么、基础、目标与时间）**：用交互式提问（宿主提供专用提问工具则优先，否则以文本提问逐项确认）问 ① 学什么 + 为什么（应试/求职/兴趣）；② 基础（零基础/入门/进阶）；③ 目标与时间（期限/每周时长/单次时长）。**可选补充（不阻塞 S0 闸口，S2 可再补）**：学到什么程度算完成（写入 `目标程度`）。
  3. **澄清纪律**：每一项缺失信息**最多追问 2 轮**；两轮仍缺 → 按现有信息出草案/假定缺省值并向用户**声明假设**（如「按每周 3 次、每次 30 分钟排，如不符告诉我」），不得无限问卷化。只追问**会改变答案的缺失信息**，已说明的不重复问。
  4. **定档**（必须显式生成并展示给用户）：
     - **类型** ∈ {知识型, 技能型, 备考型, 材料型}。判据：有考试日 → 备考型；以实操/动手为主 → 技能型；以现成材料为载体 → 材料型；其余以理解概念为主 → 知识型。生成后**向用户展示并请其确认/更正**。
     - **学科族** ∈ {数学与统计, 实验科学, 语言, 计算与技术, 人文社科, 医学与健康, 艺术与技能}。由主题推断后**向用户确认并落盘**；S1 摸底后若发现不符，**允许修正并记录修正理由**。
  5. **先读历史**：同数据根已有同主题或相关任务时，先读其记忆.md「学习记录」与学习者画像（`profile.md`：教学方法裁决、类比领域）——复用有效裁决与类比领域，不重蹈已判低效的教法。**按作用域复用（F13）**：跨主题沿用的只有「学员明说的通用偏好」与**学科族级**的有效裁决；**任务级 / 单次的教法裁决不跨主题预判**（不得因某任务一次低效就对同类主题一律换法，须在新任务重新评估）。
- **闸口**：四项信息齐备；类型与学科族均为合法枚举且已展示确认。`目标程度` 为可选补充，不阻塞本闸口。
- **产出**：在「数据根」下创建 `<slug>/progress.md`（元信息区，含类型、学科族、数据根、目标；如已获得则一并写 `目标程度`）。**「起点」由 S1 产出，S0 与 S1（诊断摸底进行中）均不要求**（`progress_check.py` 对「起点」的必填约束**自进入 S2 起生效**）。阶段 → 诊断摸底。
- **失败怎么办**：材料读取/解析失败 → 停止当前运行，请用户修复文件、重新提供，或粘贴目录/口述要点后重新解析；不得先用通用脉络开课。范围确认完成后从 S0 原步骤继续。

### S1 诊断摸底

- **目标**：判定起点，摸出薄弱点。
- **动作**：出 3–5 道由浅入深的摸底题（用户自报进阶且确认熟练时，可减为 2 道确认题——仍须判分证据支撑起点判定）；**技能型**任务改用一个小实操。无实跑环境时停止当前运行，恢复授权执行环境后补做实操；口述步骤不能冒充实操证据。只记录不批评。**概念主导的学科族**（实验科学/人文社科/医学与健康等）可在摸底中附 1 道迷思诊断题——默认开放短答（「你怎么理解 ___」「你以为会怎样」）；选择形态的干扰项须取学科包/群级误区库具名条目（消费纪律见 `references/subjects-index.md`）；结果只作教学素材（播种 R42 预判误区清单并记学习日志一行），不作批评、不计起点判定、不入薄弱点区（内容尚未讲授，调度入队由 R35 过滤）。**摸底判分证据落盘 `exercises/00-摸底-<日期>.md`**（沿用 `NN-` 命名契约的 00 专号，含作答与判分结构）。**摸底同轮顺带问一句「类比领域」**：「你有没有特别熟悉的一个领域（做饭 / 游戏 / 音乐 / 某项运动 / 本职工作……）？之后讲新概念我优先拿它打比方。」答案写入学习者画像（见 `references/intake-optional.md`「学习者画像」；无画像文件时本次顺带建立，用户不便回答则跳过，不阻塞闸口）。
- **闸口**：起点判定为三档之一（零基础/入门/进阶）；薄弱点清单**允许为空**——全对（=进阶）时记为「薄弱点：无」并正常推进。
- **产出**：起点字段、薄弱点清单（可记「无」）；阶段 → 计划确认中。

## 数据根与目录布局
题组与判分文件（exercises/）的结构与字段正本：`references/assessment.md`。

### 数据根（稳定根）

**规范数据根**：`<工作区根>/.learning/`。本分册全篇的「数据根」均指此路径——任何下级布局都**不再重复 `.learning` 目录段**（避免 `…/.learning/.learning/<slug>/` 的双重嵌套）。

为避免相对路径随会话 cwd 漂移导致「找不到进度」，遵循三条硬规则：

1. **一次解析、写进文件**：会话首次建立/迁移任务时，把解析到的**绝对数据根**写进 `<数据根>/<slug>/progress.md` 的「数据根」字段；此后以该字段为准，不重新猜。
2. **入口先枚举**：任何「继续学习/问进度」都先枚举数据根（宿主的目录枚举能力（根路径与匹配模式分开传入，任务目录匹配 `*/progress.md`）；若目录枚举能力不可用或返回异常，以 `python "<技能根>/scripts/task_index.py" --root "<数据根>"` 兜底），再匹配任务。
3. **不逃逸**：所有写入必须落在数据根之内（红线 CR-7）。

**根解析优先级（F11，从高到低，命中即止）**：

1. **明确用户路径**：用户显式给出的数据根 / 工作区路径；
2. **已知活动任务**：progress.md 已写「数据根」字段（规则 1）→ 直接采用；
3. **宿主工作区根**：宿主提供的工作区根下 `<工作区根>/.learning/`；
4. **限定项目发现**：在当前工作区范围内**限定深度**发现 `.learning/`（**不做全机扫描**）；
5. **当前目录兜底**：`<cwd>/.learning/`（仅当以上皆不可得，且视为**待确认**）。

- **跨 cwd 必须找到同一任务**（冒烟自检口径不变）；**不同 cwd 不得因兜底根制造重复任务**。
- **续学时若发现失败，不自动新建任务**；确实不明时**只向用户确认一次工作区**（不反复追问），确认后再按优先级解析。

> 冒烟自检：两个不同 cwd 的会话访问同一主题，必须定位到同一 `<数据根>/<slug>/progress.md`（以「数据根」字段与 slug 为准）。

### 目录布局

```
<数据根>/                          # = <工作区根>/.learning/
├── index.json                     # 派生索引（由脚本重建，禁止手改）
├── profile.md                     # 学习者画像（可选全局文件，跨任务共享；见 `references/intake-optional.md`「学习者画像」）
└── <slug>/                        # 每个主题一个目录，单属主免冲突
    ├── progress.md                # 状态簿：状态字段、调度队列、暂缓、交接与续学游标
    ├── 课程体系.md                # 规划簿：章/节/目三级规划 + 目行账本（任务目录第一层，与 progress.md 平级）
    ├── 记忆.md                    # 叙事簿：学习日志、学习记录、讲授证据
    ├── materials/                 # 讲义：NN-<节名>.md；结课另有 复习清单-<课程名>.md
    ├── exercises/                 # 题组与判分：NN-<节名>-<日期>.md
    └── trace.jsonl                # 结构化执行轨迹（可选，默认关闭；测评时启用）
```

- `materials/00-备课来源.md` 为可选备料台账（无材料任务；00 为专号，不占节编号，不参与 `exercises/` 判定比对；无此文件合法）。
- `<数据根>/index.json` 是**派生缓存**，由 `<技能根>/scripts/task_index.py` 从各任务的 `progress.md` + `课程体系.md` 重建，**绝不手工编辑**（单一事实源是这两份文件，索引只是它们的物化视图）。**默认不物化**——`task_index.py` 默认只读、不写缓存；需物化时显式加 `--write-index`（写时**原子替换**：同目录临时文件 + `os.replace`，区分「未变化/写入失败」，失败保留原缓存、不产生半截 JSON）；`scan_status=failed` 时**绝不覆盖**既有缓存。
- 枚举**只扫数据根下第一层**：任务目录 = `<数据根>/<slug>/progress.md`；更深的嵌套目录（如 `<数据根>/a/b/progress.md`）**不在扫描范围**，请勿手动制造深层任务。
- **编号契约**：`materials/`、`exercises/` 的文件名编号**推荐两位补零**（`01-`、`02-`…）；脚本对「已掌握↔判分记录」的比对**同时接受 `1-` 与 `01-` 两种写法**（宽容匹配），但为一致性仍建议两位补零。文件名中的节名须为**文件系统安全字符**（去除 `/ \ : * ? " < > |` 与首尾空格，含全角标点的节名以连字符替换后落文件名）。
- **题组与判分文件（exercises/）**：文件结构与字段正本见 `references/assessment.md`「题组与判分文件（exercises/）」。
- **效果报告（materials/效果报告-<课程名>.md）**：结课时的评审证据，**不是讲义、也不是学员可见输出**——不进讲授轮、不贴聊天轮、不进讲义区；文件名是标识位，`W-EFFECT-*` 六码兜底。**位置不变**——留在学员数据根内，理由见红线 6 的管辖范围（管的是讲授正文这个话语行为，不是磁盘文件内容）。
  - **体例**：四个二级小节硬必填（结课绝对水平 / 延迟保持 / 元认知校准 / 证据指针），每段一行三态判定（`判定：已测` 或 `判定：未测（理由：…）`，理由禁占位词）。**小节标题容忍尾随括注与全角冒号**（`## 结课绝对水平（2026-11-20）`、`## 结课绝对水平：` 都算命中），与 `TARGET_RE`、doc 指针的口径一致。段落必填、值可「未测」：结课当天写完即「完整」，第 30 天只回填「延迟保持」段。
  - **「结课绝对水平」判已测时必须写出得分率的分母来源**（票 103 / 规格 90 结算项 B 第 3 条）：引用该卷的 `目标线：a/b` 行，或显式声明「按契约默认 4/5」。**这是存在性检查，不是一致性检查**——分母数值与卷面不一致不报（一致性校验已被票 64 否决）。段判「未测」时没有得分率可写分母，不要求。缺了报 `W-EFFECT-DENOMINATOR`，只告警不拦停。**这条按段找，不按全文找**——分母来源写进别的段不算数（与 99- 指针的「全文找」宽口相反，这是有意收紧）。
  - **不要写「键=值」字段行**：不是因为它会触发 `W-META-INVALID`——`materials/` 根本不进 `parse_meta`（那条通道只吃 `progress.md` 三区条目），写了也不会报。禁它是**体例纪律**：报告一旦长得像台账，就会被误当证据源。机检只认**行首列表项 + `键=`** 的形态（`- 信心=4` 报 `W-EFFECT-MARKER`），行文里裸写的 `信心=4` 不拦。
  - **防 `verify_explanation.py` 误扫，靠的是段名互斥不是首行声明**：该脚本的 gate 是结构特征（`本节速览` / `概念地图` / `回看索引` / `概念 N` 等），**没有任何脚本读首行声明**。所以段名不得使用这些特征词；写了「本节速览」的报告即使有首行声明，照样被当讲义扫出 `W-READER-*`。首行写「本文件是效果报告，不是讲义」仍建议保留，但它是**人读纪律项，零机检**。
  - **机检的边界（照实写，别当它更强）**：只验完整性与指针闭合，不重算得分率、不验内容一致性、只告警不拦停（`scripts/verify_effect_report.py`）。两处已知宽口——**指针按全文找、不按段**（`结课绝对水平` 段的 99- 指针写在「证据指针」段也算过；`元认知校准` 的「信心=」同理，全文任意位置出现即过）；**围栏代码块里的 `## 段名` 会被当成真段落**（与 `verify-doc-pointers.py` 的剥围栏口径不同）。多份 `效果报告-*.md` 时**只校验排序第一份**，其余仅 stderr 提示。

### slug 规则与冲突处理

- slug = 主题的稳定标识：小写、去空格、中文转拼音或直接用**主题短名**，仅保留字母/数字/连字符，长度 ≤ 48。
- 生成 step：先枚举既有 slug；无冲突直接用；有冲突则追加序号或短哈希（如 `python-2` / `python-a1b2`）。
- **禁止**在两个不同主题间复用同一 slug；同名不同课程必须区分（避免互相覆盖）。
- 无主题上下文时**不得**生成 slug（红线 SR-1）。

### 版本号体系

两层版本互不混淆：**包版本**（SKILL.md frontmatter `version`，以该字段为准）；**数据 schema 版本**（脚本输出 `schema` 键，如 `learn-task-index/7`、`ltw-due-queue/5`、`ltw-calibration/4`——加键不破坏消费方时 +1，消费方按存在性读取新键）。

**升版规则**：major = 闸口通过线/对外契约行为变更（如 S5 测验通过线分型、数据布局重构）；minor = 向后兼容的机制新增（如新增告警码、可选字段）；patch = 修复与表述修正。**判据只作建议，包版本由维护者指定**：它用来判断「这次改动值不值得进 major 段」，不是硬约束——维护者可出于发版节奏或历史连续性，把 major 级改动压在 minor 段里。无论怎么定，四处锚点必须同值（见 `references/ops.md`「脚本操作与验证」）。
> **两类的分界**：「加键不破坏消费方」说的是**键集合**的变化；**同一个键的取值形态变了**（如 D 从 0.5 粒度整数变连续 4 位小数）属**对外契约行为变更**，消费方按旧形态解析会读错值——`ltw-due-queue` 的 /3→/4 就是这一类，升版理由必须写「取值形态变更」，不能只写「加键」。包内不保留改动历史（零史纪律），版本演进仅以包版本号体现。

### 三簿分工（数据布局总纲）

每个任务的持久数据按「状态 / 规划 / 叙事」拆三簿，外加全局画像——**一类信息只进一本账**：

| 簿 | 文件 | 装什么 | 不装什么 |
|---|---|---|---|
| 状态簿 | `<slug>/progress.md` | 元信息、薄弱点/错题本/错题归档/保持复习（调度队列）、日达标（按天事实）、检索锚（内容线索，不进调度）、暂缓与范围外、本次交接、下次续学 | 任何规划与叙事 |
| 规划簿 | `<slug>/课程体系.md` | 章/节/目三级规划、目行账本（状态/前置/来源/类型/引入）、对照结论、材料、材料覆盖、排期、质量保障机制、协作协议 | 判分记录、调度队列、对话叙事 |
| 叙事簿 | `<slug>/记忆.md` | 学习日志（事件时间线）、学习记录（任务级洞察）、讲授证据 | 状态字段、规划 |
| 画像 | `<数据根>/profile.md` | 跨任务学习者画像（见下「学习者画像」） | 任务内洞察（进记忆.md） |

**读写纪律**：续学开场读状态簿恢复游标；开节/重排读规划簿对应章/节；复盘与画像读取读叙事簿。同一信息出现两处 = 结构违规，以本册定义的簿为准并当场去重。判分记录仍在 `exercises/`（单一判分证据源，见 `references/assessment.md`「题组与判分文件（exercises/）」）。

## progress.md 字段（唯一事实源）
progress.md 是**状态簿**：只装「当前状态与游标」——元信息、调度队列、暂缓处置、续学交接。课程规划（章/节/目、对照结论、排期）在 `课程体系.md`，学习叙事（日志/记录/讲授证据）在 `记忆.md`，三者分工见「三簿分工」。

**字段行的行内注释（全仓统一口径）**：字段行尾用**两个以上空格 + `#`** 写的解说属于**文档层注释，不是字段值的一部分**——三个字段解析器（`progress_check` / `task_index` / `scheduler`）与两处课程体系头行解析（`progress_check.parse_kp_list` / `kp_sort.parse_kp_list`）统一经 `scripts/ltw_parse.py` 的 `parse_field_line()` / `strip_inline_comment()` 剥离。**边界**：① 值内嵌的 `#`（`C#`、`第#3章`）前面无空格，不受影响；② 单空格 + `#`（`学完 # 标记`）**不剥离**，保留为值；③ `<...>` 占位符是「未填写」信号，**不剥离也不放行**，该字段仍按各自判据拦截。写新模板时按此口径挂注释，不要改写成普通正文行。

**目游标**：`task_index.py` 从 `## 下次续学` 的「节」行解析「已讲到第 k/N 目」→ 输出 `current_item` / `item_total`（缺失为 null）；目名随游标成对书写。**目编号是唯一游标口径**——按节连续（=KP 序），禁止按场分段重编号。

**三簿读写分工**：续学开场读 progress.md（本文件）恢复状态与游标；开节/规划读 `课程体系.md` 对应章/节；历史与洞察读 `记忆.md`。字段冲突时以本文件的状态字段为准。

**交接与记忆**：`本次交接` 是下一次开场的摘要（每次收尾覆盖重写）；事件时间线（学习日志）、持久洞察（学习记录）、讲授证据落 `记忆.md`（格式见「记忆文件」）。**若 `本次交接` 与 `下次续学` 冲突，以 `下次续学` 的阶段/节/动作游标为准**，开场向学员说明差异，不按交接里的旧话硬推。**下次开场先处理 `未解决`**；同一未解决项跨多次仍未动，转入薄弱点 / 暂缓与范围外 / 记忆.md 学习记录，不无限滞留在交接里。

**记忆写法纪律**（适用于本次交接与记忆.md 各区）：正文/洞察每条 ≤120 字（`profile.md` ② 的作用域、证据、日期、状态等元数据不计入）；用动词短语（"使用 X""卡在 Y""换 Z 后能独立完成"），不用形容词标签；每条带证据（日期 + 场景/原话）；推断标"暂定"，只有学员陈述或后续证据才升级；禁用绝对化词（深刻、彻底、完美掌握、专家、热爱、总是、从来不、完全理解）；无证据不写；空更新合法；当前证据与当前表态优先于旧记录；一次困难不得写成全局人格判断。

**动作游标（F08，可选）**：恢复只到「阶段 + 节」不足以区分「待出题 / 待作答 / 待批改 / 待落盘」——续学时先读本行定位**当前动作与待回应项**。出题后中断 → 据「待回应：题组文件 + 题号」继续原题，不重新出题；已答未批改 → 据「最后提交」指向的作答继续批改，不重复作答。缺本行 = 合法形态，退回「阶段 + 节」恢复。

### 保持复习区

位置在「错题归档」之后、「暂缓与范围外」之前；`scheduler.py due-queue` 把它与「薄弱点」「错题本」一起读取，条目用 `kind=保持` 标识。**写入时机（R54，目级化）**：① S3 目关闭（正式或轻量确认通过）→ **同轮为该目写一条目级保持条目**（初始 good）；节达标时核对保持条目已齐、缺漏当场补齐（`references/lessons.md`「节末收尾五件套」③）；节达标**不再新增节级条目**（存量节级条目仍合法并被 due-queue 继续读取，不回改）；② S4 薄弱点 2 轮全对（跨日，R52）清除 → 转入本区（不得直接消失）；③ S5 结课后复习清单以本区为准。**行格式**：目级条目 `[<日期>] <目名>（KP-xx-xx）｜ 元数据：…`；存量节级 `[<日期>] <节名> ｜ 元数据：…` 继续合法。**初始值**：取 `scheduler.py next-interval --new-card --grade good --last <日> --today <日>` 的 `stability_new` / `difficulty_new` / `due`（= FSRS-6 的 S0(good) / D0(good)，当前为 2.3065 / 2.1181 / +2 天），不心算、不抄死值。**日期前缀**：行首 `[YYYY-MM-DD]` 推荐；缺日期时用元数据 `last`/`due` 或「最近更新」兜底，全部缺失才报 `W-UNPARSED-ITEM` 不入队（不猜当日）。**同一对象只保留一条**（节或目各一条）：复习时更新原行，不重复追加；对象身份优先用 `lesson_id` / KP 编号 / 稳定目名。**复习判分**：按既有条目命令更新 S/D/due；失败（Again）仍留本区，按短间隔重测；若需重讲，按条目对应节回炉，**不要为同一知识点另建一套 S/D 调度条目**。**已完成任务的保持复习**：仍可由 due-queue 触发 S4，复习后按「复习来源阶段=已完成」返回。**「需巩固」标注（R54，第五态语义）**：课程体系目行状态可写 `已讲（需巩固：<依据>，<日期>）`（对齐摸底标注先例，随「已讲」基值计数、不新增覆盖摘要键）。**触发**（模型按证据执行）：同一保持条目累计 2 次热身答错（R51）、保持复习重测判 Again、或 due 逾期未清且抽测不过；**翻回**：该目复习独立答对（题组、保持抽测或清除链通过）→ 撤标注恢复「已讲」。标注不参与闸口与纳入分母判断，脚本只读计数（覆盖率审计输出，见 `references/lessons.md`）。

### 日达标区（红线 8 判据④）

位置在「保持复习」之后、「暂缓与范围外」之前，**必须是二级标题**——写成 `###` 会被 `scheduler.py` 并进上一条保持条目当调度条目消费（票 38 实测）。**只存按天事实，不存派生计数**：连续天数由 `scheduler.py day-streak` 从行序派生，不单独落盘（票 75）。

- **行格式**：`- <YYYY-MM-DD> ｜ <达|未达> ｜ 证据：<…>`，日期 ISO 绝对日期，状态二选一，三段用全角竖线分隔；无记录时本区写「无」（占位行跳过，不报坏数据）。
- **达的判据（可机检等价物）**：当天至少完成 1 条到期复习 **或** 1 次作答（任一判分记录）。判定由模型在写入时做，脚本只消费「达/未达」这一事实，不重算教学事实。
- **15 分钟是话术不是口径**：它只用于「对学员怎么说」（见 `references/gates.md`「最小可行日」），不进判定、不进机检。
- **连续天数由行序派生**，不落盘、不写进任何字段行。
- **缺区合法**：等同「无历史」——不推断、不回溯、不迁移，存量任务不补写。
- **缺天终止计数**：日期与今天不连续时连续计数**终止**，不把「没记录」折算成「未达」——宁可漏，不可错。
- **同一天多行以「达」优先**，其余取最后一行。方向不能反：反了就把达标日改判成未达、凭空造出一次未达并触发判据④ 的干预。写重复行本身就是错，但脚本不许把它变成对学员的施压。
- **证据位可以留空**（`证据：` 后面什么都不写）：未达日本来就没有证据，如实留空是合规，不是坏数据。
- **照模板原样抄的占位行不算坏数据**：日期位仍是 `<YYYY-MM-DD>` 或整行是「（无记录时本区写「无」）」这类括注说明时跳过——闸口不惩罚一个照文档办事的人。

机检：`progress_check.py` 只做结构校验出 `W-DAY-ROW-INVALID`（行形态不符 / 日期非 ISO / 状态非「达|未达」），**不拦停**；`scheduler.py day-streak --root <数据根> --today <日期>` 只读输出 `schema=ltw-day-streak/1`、`per_slug[].entries` / `miss_streak` / `last_met_date`，模型**只消费它的输出，不自行计数**。

### 检索锚区（只做内容不做调度）

位置在「日达标」之后、「暂缓与范围外」之前，**必须是二级标题**——写成 `###` 会被解析层静音（不进任何区）并由 `progress_check.py` 出 `W-SECTION-LEVEL`（票 97；「日达标」在票 38 已实测踩过同一个坑：三级标题不切换区，条目被并进上一条保持条目当调度条目消费）。

- **它是内容，不是调度**：检索锚 = 给某个知识点留一条回查线索的产物，用来在复习时**回到出处**。因此本区**不写调度字段**（`S=` / `D=` / `due=` / `last=` / `信心=` / `evt=` 等一律不写），**不进保持复习区**，也不被 `scheduler.py` 的 due-queue 读取。给知识点排复习间隔是「保持复习」区的职责；本区只管「这条线索去哪查」。
- **行格式**：`- [<YYYY-MM-DD>] <目名 / KP 编号> ｜ 线索：<回查入口>`；日期段可选，缺日期不影响本条合法性（本区不参与任何日期推算）。无检索锚时本区写「无」。
- **脚本态度**：解析层（`ltw_parse.parse_progress_sections`）只按精确区名取三区 + 日达标，本区**不产生任何队列条目**；不写调度字段因此也**不会**产生 `W-META-INVALID`。
- **为什么必须卡层级**：三级标题不会切换当前区，其下条目会继续落进上一条区间被消费。对本区而言，落进「保持复习」就会被当调度条目去算 S/D/due——一条回查线索会凭空变成一个复习任务，而且**全程不报错**。所以解析层对任何层级的同名区一律静音（宁可漏，不可错），`progress_check.py` 另出 `W-SECTION-LEVEL` 让它看得见。
- **机检**：`progress_check.py --selftest` 的结构守卫用例覆盖两种形态——二级合法（线索行不进任何调度区、不出告警）与三级非法（静音 + `W-SECTION-LEVEL`）；变异测试把 `## 检索锚` 降成 `### 检索锚` 必须变红。

### 暂缓与范围区块

条目为自由文本 + 竖线（`｜`）分段（来源 / 处置 / 触发条件 三段），**不做枚举硬校验**——有竖线分段但字段残缺的条目由 `progress_check.py` / `task_index.py` 输出 `W-UNPARSED-HOLD` 告警（不静默、不计入 hold_count）；**无竖线分段的纯自由文本行**不判畸形、仍计入 `hold_count`（解析器宽容口径；建议仍按三段式书写，以便 W-KP-HOLD-CROSS 交叉核对）；无暂缓项时本区写「无」。
