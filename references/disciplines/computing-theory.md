## 学科身份

归 **计算与技术群**，但内容类型分布与编程相反：概念型过半（机制与权衡），程序型（手推与计算）约三成，记忆型少量。

上机编程靠实跑验证，理论课没有可跑的东西——**只能靠机制讲透与手推验证**。所以本包的重点是「让人能在脑子里跑一遍」。

## 内容结构与前置链

**主干**：数据表示与组成（数制、补码、指令）→ 存储层次（寄存器—缓存—主存—外存）→ 操作系统（进程、调度、同步、内存、文件）→ 网络（分层、协议、路由、可靠传输）→ 算法（复杂度、排序、查找、图、动态规划）。

**前置链最常断的三处**：数制与补码、地址空间与指针对应关系、分层思想（每层只对上下负责）。

## 学科专属教学法

- **手推先于结论**：讲调度算法就手推一组进程的时间线；讲页面置换就手推一个访问序列的命中率；讲协议就画一次握手的报文顺序。没有手推的结论都是背来的。
- **分层思想反复强调**：每一层只对上下层负责，同层对等通信靠协议。学员一切「为什么不能直接……」，多半是没建立分层观。
- **权衡用表格摆出来**：时间换空间、空间换时间、加锁换一致性、缓存换新鲜度。每个机制都给出「它在为什么让步」。
- **并发必须画时间线**：多线程的交错、竞态、死锁，用两条竖线加事件点画出来，比文字描述清楚一个数量级。
- **算法先讲「怎么想出来的」再讲复杂度**：从暴力解出发，指出重复计算在哪，再引出优化。直接给最优解，学员只会背。
- **复杂度要能口算**：看到嵌套循环就能说量级，这是最高性价比的得分点。

## 实证误区库

| 误区 | 症状 | 诱因 | 反证 |
|---|---|---|---|
| 并发当串行理解 | 以为语句必按书写顺序整体执行 | 单线程编程经验 | 画两线程交错时间线 |
| 缓存一定更快 | 不分场景地认为缓存总是提升性能 | 只记「缓存快」 | 缓存不命中、一致性维护都有成本 |
| 虚拟内存＝磁盘交换 | 把两个概念等同 | 只记「内存不够用磁盘」 | 虚拟内存是地址映射，交换只是其中一种机制 |
| 进程＝线程 | 互换使用 | 名字相近 | 画地址空间与调度单位 |
| TCP 保证实时 | 认为可靠传输就等于快 | 「可靠」的日常语义 | 重传与拥塞控制带来延迟 |
| 五层模型当实现 | 把教学用的分层模型当真实实现细节 | 教材模型简化 | 实际协议栈有合并与跨层优化 |
| 复杂度只看最坏 | 忽略数据分布与常数 | 只记大 O | 小规模下常数因子可能主导 |
| 排序算法死记 | 能背复杂度表，说不出为什么 | 应试背表 | 让学员推一遍某个排序的比较次数 |
| 补码当「取反加一」口诀 | 会用不会解释 | 只记操作 | 从模运算解释为什么这样表示负数 |
| 算法的正确性靠「试了几个」 | 不写循环不变式 | 程序可以跑测试 | 理论题无法靠抽样证明 |

备课取 2–3 条，本学员历史错因优先占坑。

## 表征与标准流程

**标准表征**：存储层次金字塔、进程状态机、线程交错时间线、协议报文序列图、算法执行的表格或树形展开图、复杂度增长曲线。

**算法分析流程**：明确输入规模 → 写暴力解 → 找重复子问题或可剪枝处 → 优化 → 推复杂度 → 构造边界输入检验。

**系统题流程**：定层次（在说哪一层）→ 定对象（进程/页/包）→ 画状态或时序 → 说机制 → 说代价。

**手推题流程**：列初始状态 → 逐事件推进（每步只改一个状态）→ 记录中间结果 → 汇总指标（命中率、周转时间、总时延）。

## 验收形态

- **概念型目**：能画机制图或时间线，能判断某个场景会出什么问题，能说出该机制的代价。
- **程序型目**：能手推（不依赖运行环境），复杂度口算正确。
- **不接受**：只背结论不手推；只记复杂度表不推过程；用「跑了一下是对的」代替正确性论证。

- 群级规则（读先于写、trace、子目标标注、报错三件、实跑纪律）中，**trace 与「手推」同源**：本包把 trace 从代码扩展到系统状态。
