**目游标**：`task_index.py` 从 `## 下次续学` 的「节」行解析「已讲到第 k/N 目」→ 输出 `current_item` / `item_total`（缺失为 null）；目名随游标成对书写。**目编号是唯一游标口径**——按节连续（=KP 序），禁止按场分段重编号。

**三簿读写分工**：续学开场读 progress.md（本文件）恢复状态与游标；开节/规划读 `课程体系.md` 对应章/节；历史与洞察读 `记忆.md`。字段冲突时以本文件的状态字段为准。

**交接与记忆**：`本次交接` 是下一次开场的摘要（每次收尾覆盖重写）；事件时间线（学习日志）、持久洞察（学习记录）、讲授证据落 `记忆.md`（格式见 `references/data/memory.md`「记忆文件」）。**若 `本次交接` 与 `下次续学` 冲突，以 `下次续学` 的阶段/节/动作游标为准**，开场向学员说明差异，不按交接里的旧话硬推。**下次开场先处理 `未解决`**；同一未解决项跨多次仍未动，转入薄弱点 / 暂缓与范围外 / 记忆.md 学习记录，不无限滞留在交接里。

**记忆写法纪律**（适用于本次交接与记忆.md 各区）：正文/洞察每条 ≤120 字（`profile.md` ② 的作用域、证据、日期、状态等元数据不计入）；用动词短语（"使用 X""卡在 Y""换 Z 后能独立完成"），不用形容词标签；每条带证据（日期 + 场景/原话）；推断标"暂定"，只有学员陈述或后续证据才升级；禁用绝对化词（深刻、彻底、完美掌握、专家、热爱、总是、从来不、完全理解）；无证据不写；空更新合法；当前证据与当前表态优先于旧记录；一次困难不得写成全局人格判断。

**动作游标（F08，可选）**：恢复只到「阶段 + 节」不足以区分「待出题 / 待作答 / 待批改 / 待落盘」——续学时先读本行定位**当前动作与待回应项**。出题后中断 → 据「待回应：题组文件 + 题号」继续原题，不重新出题；已答未批改 → 据「最后提交」指向的作答继续批改，不重复作答。缺本行 = 合法形态，退回「阶段 + 节」恢复。

**保持复习区**：位置在「错题归档」之后、「暂缓与范围外」之前；`scheduler.py due-queue` 把它与「薄弱点」「错题本」一起读取，条目用 `kind=保持` 标识。**写入时机（R54，目级化）**：① S3 目关闭（正式或轻量确认通过）→ **同轮为该目写一条目级保持条目**（初始 good）；节达标时核对保持条目已齐、缺漏当场补齐（`references/workflow/s3-close.md`「节末收尾五件套」③）；节达标**不再新增节级条目**（存量节级条目仍合法并被 due-queue 继续读取，不回改）；② S4 薄弱点 2 轮全对（跨日，R52）清除 → 转入本区（不得直接消失）；③ S5 结课后复习清单以本区为准。**行格式**：目级条目 `[<日期>] <目名>（KP-xx-xx）｜ 元数据：…`；存量节级 `[<日期>] <节名> ｜ 元数据：…` 继续合法。**初始值**：取契约 `scheduler` 块（default_s / default_d 与 due 偏移），last=掌握/清除日；用 `scheduler.py next-interval --new-card --grade good --last <日> --today <日>` 算，不心算。**日期前缀**：行首 `[YYYY-MM-DD]` 推荐；缺日期时用元数据 `last`/`due` 或「最近更新」兜底，全部缺失才报 `W-UNPARSED-ITEM` 不入队（不猜当日）。**同一对象只保留一条**（节或目各一条）：复习时更新原行，不重复追加；对象身份优先用 `lesson_id` / KP 编号 / 稳定目名。**复习判分**：按既有条目命令更新 S/D/due；失败（Again）仍留本区，按短间隔重测；若需重讲，按条目对应节回炉，**不要为同一知识点另建一套 S/D 调度条目**。**已完成任务的保持复习**：仍可由 due-queue 触发 S4，复习后按「复习来源阶段=已完成」返回。**「需巩固」标注（R54，第五态语义）**：课程体系目行状态可写 `已讲（需巩固：<依据>，<日期>）`（对齐摸底标注先例，随「已讲」基值计数、不新增覆盖摘要键）。**触发**（模型按证据执行）：同一保持条目累计 2 次热身答错（R51）、保持复习重测判 Again、或 due 逾期未清且抽测不过；**翻回**：该目复习独立答对（题组、保持抽测或清除链通过）→ 撤标注恢复「已讲」。标注不参与闸口与纳入分母判断，脚本只读计数（覆盖率审计输出，见 `references/workflow/coverage-audit.md`）。

**暂缓与范围区块**：条目为自由文本 + 竖线（`｜`）分段（来源 / 处置 / 触发条件 三段），**不做枚举硬校验**——有竖线分段但字段残缺的条目由 `progress_check.py` / `task_index.py` 输出 `W-UNPARSED-HOLD` 告警（不静默、不计入 hold_count）；**无竖线分段的纯自由文本行**不判畸形、仍计入 `hold_count`（解析器宽容口径；建议仍按三段式书写，以便 W-KP-HOLD-CROSS 交叉核对）；无暂缓项时本区写「无」。
