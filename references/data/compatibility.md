## 稳定引用 · 对账 · 提交顺序（F09 / F10 / F12）

> 何时读：新增/重排节、写双写账本、多文件落盘（掌握/结课/跨阶段）时。

**稳定引用（F09，可选、append-only）**——把「对象身份」与「展示顺序」解耦。**落点规定（消费者优先按稳定 ID 匹配）**：
- `lesson_id`：节稳定标识（如 `L-02`），**改名 / 同名 / 换序都不变**。**落点三处**：①**节路线行**——`- [x] 1. 循环（lesson_id=L-B）`（全/半角括号均可）；②**判分记录文件头**——首行或标题下写 `lesson_id=L-B`（如 `# 循环，lesson_id=L-B`）；③**讲义/材料头**同理。`当前节` 序号仍保留供人读，二者分离。
- **匹配规则（`progress_check.py` 的消费口径）**：节路线行声明了 `lesson_id` 时，**先按 ID 在 `exercises/` 中精确匹配**该 ID 的证据文件（重排后序号对不上也能匹配正确对象）；**匹配不到时**回退按文件名序号前缀匹配；**回退命中却声明了另一个 `lesson_id` → `E-EVIDENCE-ID-MISMATCH`**（放行模式拦停，防止串用他节证据）。
- `attempt_id` / `evt`：一次作答的稳定标识，写入条目元数据段 `evt=`（或判分行 `attempt_id=` 前缀）；同一作答产生的「错题」与「薄弱点」两条投影**共享同一 `evt`**（供校准去重）。
- **动作游标引用**：`## 下次续学` 行的「待回应」须指向**存在的**判分记录（文件名或其前缀）、「最后提交」须指向**已出现的** `evt=`/`attempt_id=` 值；悬空引用在放行模式报 `E-CURSOR-DANGLING`（历史模式 `W-CURSOR-DANGLING`），恢复时不得把悬空游标当有效定位。
- **不自动重编号**：既有 KP 编号（`KP-<节序>-<目序>`）一律保留原值；节改名/换序后**引用材料与作答仍对应正确对象**，不靠序号猜、不追溯撤销历史。
- 脚本对未知可选字段**零感知**——缺这些键 = 合法，无需迁移。

**对账（F10，按对象 ID）**：「课程体系目行状态」与「progress.md 处置」双写按**对象 ID 集合对账**——有 KP 时以 `KP-xx-xx` 为准（状态单源 + 处置理由单源，progress.md 只存摘要）；**数量相同但对象不同也能检出**（W-KP-HOLD-CROSS 列出「仅清单 / 仅区块」差异）；无 KP 的任务保留任务级处置。不新增第三份账本。

**提交顺序（F12，先校验拟提交状态、后提交，可重试）**——多文件更新按固定次序，断在任一步都停在「未提交」态，绝不出现「无证据已掌握」：
1. 先写**证据与材料**（`exercises/` 判分、`materials/` 讲义）；
2. 再准备 **KP / 处置变更**（课程体系目行状态、progress.md 暂缓与范围外）；
3. **校验拟提交状态**——把**目标状态**送进校验器，而不是只校验磁盘旧状态：`progress_check.py <任务目录> --release --proposed-phase <目标阶段>`（拟转阶段时）或 `--staged <候选 progress 快照>`（候选文件），并用 `--changed-lessons <本次新增节号>` 限定增量范围；校验通过后才写盘（脚本输出 `proposed_state_supplied` / `checked_lessons` 回显；未提供拟提交状态时 `proposed_state_supplied:false` + `W-NO-PROPOSED-STATE`，**不得据此声称目标变更已校验**）；
4. 最后**提交掌握 / 阶段**（progress.md 阶段字段、课程体系节勾选）；
5. 派生**摘要**（课程体系覆盖摘要行、progress.md 范围快照）。
- 失败保留可重试点（脚本幂等、文件写入/编辑能力覆盖同值 → 重跑不重复事件）；**不宣称已有跨文件原子事务**——只保证次序与可重试。

## 结构化 Trace 输出（可选，默认关闭）

仅当回归测评需要过程数据时，才在闸口推进或会话收尾向 `<任务目录>/trace.jsonl` **追加一行** JSON（幂等，追加不改旧行）；**日常使用不强制记录**，不得因未记 Trace 而阻塞任何流程。字段稳定，供测评做「过程对比」与「基线回归」：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts` | string | ISO8601 时间戳 |
| `session_id` | string | 本次会话标识 |
| `phase` | string | 阶段名（枚举同 progress.md） |
| `step` | string | 阶段·动作（如 `S3·练习`） |
| `gate` | string | 本次对应的闸口判据 |
| `gate_result` | string | `pass` / `fail` / `na` |
| `tools` | array | 本步用到的工具名 |
| `files` | array | 本步读写的文件（相对数据根） |
| `evidence` | string | 落盘证据的定位（题号/检查清单/用户原话摘录） |
| `tokens` | int/null | 本步 token 消耗（会话末由平台回填，不可得填 null） |
| `duration_ms` | int/null | 本步耗时（同上） |

## 成本画像埋点

开启 Trace 时，会话收尾追加一条 `kind:"session_summary"` 记录，采集效率指标：

- `tool_calls`（本会话工具调用次数，可计数）
- `files_touched`（读写文件数，可计数）
- `gate_passes` / `gate_fails`（闸口通过/未通过次数，可计数）
- `tokens_total` / `duration_ms_total`（平台可回填则记，否则 null）
- `retries`（重试次数）

**用途**：让「效率退化」在回归测评中可被机器判定（如 token 或工具调用数超出基线的某比例即报警）。指标只增不减地追加，历史基线可逐次对比。
