## 数据根（稳定根）

**规范数据根**：`<工作区根>/.learning/`。本分册全篇的「数据根」均指此路径——任何下级布局都**不再重复 `.learning` 目录段**（避免 `…/.learning/.learning/<slug>/` 的双重嵌套）。

为避免相对路径随会话 cwd 漂移导致「找不到进度」，遵循三条硬规则：

1. **一次解析、写进文件**：会话首次建立/迁移任务时，把解析到的**绝对数据根**写进 `<数据根>/<slug>/progress.md` 的「数据根」字段；此后以该字段为准，不重新猜。
2. **入口先枚举**：任何「继续学习/问进度」都先枚举数据根（宿主的目录枚举能力（根路径与匹配模式分开传入，任务目录匹配 `*/progress.md`）；若目录枚举能力不可用或返回异常，以 `python "<技能根>/scripts/task_index.py" --root "<数据根>"` 兜底），再匹配任务。
3. **不逃逸**：所有写入必须落在数据根之内（红线 CR-7）。

**根解析优先级（F11，从高到低，命中即止）**：

1. **明确用户路径**：用户显式给出的数据根 / 工作区路径；
2. **已知活动任务**：progress.md 已写「数据根」字段（规则 1）→ 直接采用；
3. **宿主工作区根**：宿主提供的工作区根下 `<工作区根>/.learning/`；
4. **限定项目发现**：在当前工作区范围内**限定深度**发现 `.learning/`（**不做全机扫描**）；
5. **当前目录兜底**：`<cwd>/.learning/`（仅当以上皆不可得，且视为**待确认**）。

- **跨 cwd 必须找到同一任务**（冒烟自检口径不变）；**不同 cwd 不得因兜底根制造重复任务**。
- **续学时若发现失败，不自动新建任务**；确实不明时**只向用户确认一次工作区**（不反复追问），确认后再按优先级解析。

> 冒烟自检：两个不同 cwd 的会话访问同一主题，必须定位到同一 `<数据根>/<slug>/progress.md`（以「数据根」字段与 slug 为准）。

### 续学匹配（多任务与科目别名）

- 命中同名任务 → 续学：只读其 progress.md「当前阶段」，不得覆盖既有文件。
- 命中多个任务且用户未指名科目 → **列出候选**（科目名 + 当前阶段 + 最近学习日期），请用户选择；不猜、不默认最近一个。
- 用户指名科目 → 按科目与任务 slug/主题模糊匹配（含别名，如「高数」↔ shaanxi-gaoshu），命中单个即续学。
- 未命中 → 新任务，从 S0 开始。
- 枚举异常或为空但怀疑有数据 → 先用 `task_index.py --root` 兜底；`scan_status=partial/failed` 时任务集合不完整，不得当「无任务」处理，停止枚举/续学并修复后重跑。

## 目录布局

```
<数据根>/                          # = <工作区根>/.learning/
├── index.json                     # 派生索引（由脚本重建，禁止手改）
├── profile.md                     # 学习者画像（可选全局文件，跨任务共享；见 `data/curriculum.md`「学习者画像」）
└── <slug>/                        # 每个主题一个目录，单属主免冲突
    ├── progress.md                # 状态簿：状态字段、调度队列、暂缓、交接与续学游标
    ├── 课程体系.md                # 规划簿：章/节/目三级规划 + 目行账本（任务目录第一层，与 progress.md 平级）
    ├── 记忆.md                    # 叙事簿：学习日志、学习记录、讲授证据
    ├── materials/                 # 讲义：NN-<节名>.md；结课另有 复习清单-<课程名>.md
    ├── exercises/                 # 题组与判分：NN-<节名>-<日期>.md
    └── trace.jsonl                # 结构化执行轨迹（可选，默认关闭；测评时启用）
```

- `materials/00-备课来源.md` 为可选备料台账（无材料任务；00 为专号，不占节编号，不参与 `exercises/` 判定比对；无此文件合法）。
- `<数据根>/index.json` 是**派生缓存**，由 `<技能根>/scripts/task_index.py` 从各任务的 `progress.md` + `课程体系.md` 重建，**绝不手工编辑**（单一事实源是这两份文件，索引只是它们的物化视图）。**默认不物化**——`task_index.py` 默认只读、不写缓存；需物化时显式加 `--write-index`（写时**原子替换**：同目录临时文件 + `os.replace`，区分「未变化/写入失败」，失败保留原缓存、不产生半截 JSON）；`scan_status=failed` 时**绝不覆盖**既有缓存。
- 枚举**只扫数据根下第一层**：任务目录 = `<数据根>/<slug>/progress.md`；更深的嵌套目录（如 `<数据根>/a/b/progress.md`）**不在扫描范围**，请勿手动制造深层任务。
- **编号契约**：`materials/`、`exercises/` 的文件名编号**推荐两位补零**（`01-`、`02-`…）；脚本对「已掌握↔判分记录」的比对**同时接受 `1-` 与 `01-` 两种写法**（宽容匹配），但为一致性仍建议两位补零。文件名中的节名须为**文件系统安全字符**（去除 `/ \ : * ? " < > |` 与首尾空格，含全角标点的节名以连字符替换后落文件名）。

### 题组与判分文件（exercises/）

文件名 `NN-<节名>-<日期>.md`（编号两位补零；判分记录与「已掌握」勾选的比对口径见上方「编号契约」）。文件内按以下结构落盘：

```markdown
# 第 2 节 循环与迭代 · 题组与判分（2026-10-15）

## 题组
1. <题面>
2. <题面>
3. <题面（判定题：考「何时用」）>

## 关键能力
- C1：<本节核心方法 / 唯一核心应用题 / 主要易错点>（1–3 项；每项须能独立判分）

## 作答与判分
- 题 1：作答「<学员答案>」｜信心=4｜正确性=对｜独立性=独立｜流畅度=常规｜能力=C1｜调度档=Good
- 目 8「KP 名」（推进）：作答「<学员答案>」｜信心=<1-5，可选>｜正确性=对｜独立性=独立｜流畅度=常规｜用途=推进｜KP=KP-03-08
- 题 2：作答「<学员答案>」｜信心=2｜正确性=错｜独立性=独立（错因=理解性，级=B）→ 入错题本｜调度档=Again
- 题 3：作答「<学员答案>」｜正确性=对｜独立性=提示②–④｜流畅度=未测｜调度档=Hard
- 题 4：作答「<学员答案>」｜正确性=部分｜独立性=独立｜调度档=Again（得分点缺 X）→ 入薄弱点
- 题 5：作答「<学员答案>」｜正确性=未判｜独立性=未测（答案键待核）→ 补判或作废
- 题 6：作答「<学员答案>」｜正确性=错｜独立性=独立｜调度档=Again｜作废（答案键错误：正确应为 C，2026-10-20）
- 伺服：档位=保持 ｜ 依据：近 7 题正确率 79% ｜ 样本 n=7
- 闸口：正确性达契约比例（见 `assessment/scoring.md`）＋**每项关键能力独立通过**＋复述通过 → 达标；独立性：1 独立对 ／ 1 提示后对

## 复述检查清单
- [x] 关键点 1：<名称>｜[x] 关键点 2：<名称>｜[x] 无事实性错误

## 参考答案（判分完成后回填；可选）
- 题 1：<答案或要点>｜依据：<解:… 或 见 materials/NN-<节名>.md 概念 N 的 ③ 框>
- 题 2：<要点行；主观/论述题可只写「见讲义概念 N 的 ③ 框」>
```

- **参考答案区块（可选，判分后回填）**：位置固定在文件**末尾**（「作答与判分」之后）——`progress_check.py` 的 `evidence_section` 截到下一个二级标题为止，区块放在判分段之前会把判分记录截断。**出题时不预写**（防泄题），判分完成后回填；客观题写「答案 + 一句依据」，主观/论述题写要点行或 `见 materials/NN-…md 概念 N 的 ③ 框`，不复制讲义全文。**正文唯一事实源仍是讲义 ③**：本区块只做复习索引，二者不一致时以 ③ 为准并同步更正。**不另建 `-答案.md` 分册**——`exercises/` 内文件按编号前缀被当作判分证据消费，同前缀的答案文件会被误当证据（`E-EMPTY-EVIDENCE` / 证据错配）。
- **组卷（独立触发「组一套卷」）**：卷末同设 `## 参考答案` 区块，题面区顶部写一行「作答后再看文末答案」；不拆答案册，命名与普通题组一致。

- **结课综合测验（`99-`）额外一行**：文件头写 `目标线：a/b`（如 `目标线：4/5`，可写 `目标线：7/10` 这类非 5 题卷）。这是 `progress_check.py` 判达标线的机器可读入口：**不写按契约 `gates.final_ratio` 判**，写了按该值判（`a ≤ b`）；**非法值 → `E-FINAL-INVALID-TARGET` 拦停，不得回退默认线**。普通节题组不需要这一行；收紧/放宽达标线却没写这行，脚本仍按契约默认拦停。
- **分型标签**：若 `课程体系.md` 的目行声明了类型/视觉任务，attempt 行补 `KP=KP-xx-xx`；视觉任务再加 `｜视觉=<任务>`；概念/设计在复述勾选行写该 KP 编号。
- **正式/轻量确认（可选）**：关键目正式确认写入 `## 作答与判分`，标 `用途=推进`；有对应 KP 时写 `KP=<id>`，无对应目行时写 `目=<目名>`；计入正确性分母与本节新题总量（题量口径见 `assessment/generation.md`「题量预算」）；不替代题组的关键能力独立通过与节复述；正式确认可作记忆/程序 KP 的分型证据（带 `KP=<id>` 独立正确），概念/设计仍需复述勾选行含该 KP 编号；早期错误与变式均保留，不删不改。简单目轻量确认不写 `正确性=` 判分行；需要留痕时在记忆.md 学习日志写一句「目名 + 确认方式 + 结果」。
- **目与 KP 映射**：1 个讲授目 = 1 个 KP（目定义见 `workflow/s3-block.md`「逐目推进」）。禁止一个目挂多个 KP；一个知识点若需要多个目，先拆 KP 再讲。正式确认题有对应 KP 时写 `KP=KP-<节>-<KP序>`（如 `KP-03-08`）；无对应目行时只写 `目=<目名>`。`KP-03-08a` 这类编号不合法，脚本不识别；`目=` 是人读字段，不进闸口计算。
- **判分四态（字段）**：`正确性=` 只接受 `对 / 部分 / 错 / 未判`（无别名，非法值放行模式报 `E-ENUM-GRADE`）。**作废不删除原判分行**，必须写原因；改判时新增一行（可复用原 `attempt_id`，旧行已作废即不参与冲突判定）。**四态语义、分母与调度口径见 `assessment/scoring.md`「判分口径」**。
- 判分三维（正确性／独立性／流畅度）与调度档位口径见 `assessment/scoring.md`「判分口径」；**闸口计分口径见 `assessment/scoring.md`「判分口径」**（按正确性计，慢不折算），独立性/流畅度另列不折算。**逐关键能力独立通过**：声明了「关键能力」区块时**每项须至少一次独立正确**，关键项错**不能被简单题抵消**（脚本 `E-KEY-ABILITY-UNMET`）；**独立性枚举**（独立 / 提示后·提示②–④ / 未测）——**缺失或 `未测` 一律不推为独立**（`E-NO-INDEPENDENCE`），同一 `attempt_id` 幂等去重、冲突判定报 `E-ATTEMPT-CONFLICT`；**目标为操作/作品型时**「操作作品验收」区块（≥2 个已勾选核验项）与复述清单**等价可替代**。**信心可选**：仅在**反馈前**随作答提交者记「信心=<1-5>」、方可用于 cw／校准；反馈后补报标「信心=回顾性」，**不用于 cw、不用于校准**。时序规则见 `assessment/scoring.md`「判分口径」；错题入错题本时同轮完成归因定级（错因/级，见 `teaching/interaction.md`「错因分类与补救」）。
- **证据内容抽查（W-EMPTY-EVIDENCE）**：判分记录文件存在但**未提供可用证据**（空文件、或只含「作答/判分」标题模板而无真实结果行）→ `progress_check.py` 日常模式输出 `W-EMPTY-EVIDENCE`；**放行模式（`--release`）升级为 `E-EMPTY-EVIDENCE`**——空/模板证据不得支撑本次新增掌握或结课结论。文件缺失仍为 `E-NO-EVIDENCE`。
- 闸口未过时不删题组，补齐判分后继续；S4 变式自创题文件用 `z-` 前缀（见 `workflow/gates.md` S4）。

## slug 规则与冲突处理

- slug = 主题的稳定标识：小写、去空格、中文转拼音或直接用**主题短名**，仅保留字母/数字/连字符，长度 ≤ 48。
- 生成 step：先枚举既有 slug；无冲突直接用；有冲突则追加序号或短哈希（如 `python-2` / `python-a1b2`）。
- **禁止**在两个不同主题间复用同一 slug；同名不同课程必须区分（避免互相覆盖）。
- 无主题上下文时**不得**生成 slug（红线 SR-1）。

## 版本号体系

两层版本互不混淆：**包版本**（SKILL.md frontmatter `version`，以该字段为准）；**数据 schema 版本**（脚本输出 `schema` 键，如 `learn-task-index/6`、`ltw-due-queue/3`、`ltw-calibration/3`——加键不破坏消费方时 +1，消费方按存在性读取新键）。

**升版规则**：major = 闸口通过线/对外契约行为变更（如 S5 测验通过线分型、数据布局重构）；minor = 向后兼容的机制新增（如新增告警码、可选字段）；patch = 修复与表述修正。包内不保留改动历史（零史纪律），版本演进仅以包版本号体现。
