# 操作手册式

<!-- owns: 操作手册式骨架与写作要点；must-not-define: 风格切换映射（styles）、单元 schema（unit-schema） -->

> 相关正本：`references/handout/style-standard.md`「标准讲义（默认）」。

> 何时读：技能型任务（编程、工具、软件操作）的讲义。

- 适用：技能型任务（编程、工具、软件操作）。
- 骨架：①题目〔要完成的操作与预期成果〕→ 环境与前置〔按需表示〕→ 分步操作〔② 解析〕→ ③ 答案〔`步骤：`/`代码：` + `输出：` 成功标志，代码/命令可复制、逐行注释〕→ 常见报错与修复（≥2 条）〔④：报错原文特征 → 原因 → 修法〕→ 关键决策三句话〔⑤ 小结：先做什么 / 卡住看哪条报错 / 什么算做成，≤3 句〕→ 练手任务（改错 / 仿写 / 微项目三选二）〔检验〕→ 完成检查清单。
- 槽位下限：④ 的每条报错必须是**本操作真会遇到的**（能对上②里某一步），不写「权限不足」这类泛泛报错凑数。
- 写作要点：每步可独立验证并给出「成功标志」；报错条目写「报错原文特征 → 原因 → 修法」。练手任务以成功标志判定，若单独写成 `## 检验` 区，须在该区首行写 `- 检验说明：练手任务，按成功标志自评`。
