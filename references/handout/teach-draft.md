# 边讲边写（同轮追加草稿）

> 何时读：边讲边写讲义需要按流水线追加草稿。

<!-- intent:I-TEACH-DRAFT@handout -->

- **适用**：`references/routing/triggers.md`「S3 内场景判别」判为「边讲边写讲义」（`s3-teach` 主讲）时，讲授轮结束后**同轮**把本目内容追加为讲义草稿；不整场景加载 s3-handout——本小节即该动作的唯一加载入口（s3-teach 补读）。
- **追加动作**：每目讲完 → 按**最小槽位集**写该目单元并追加进讲义草稿：①题目 / ②解析 / ③答案框（引用块起稿，起笔按学科族，如 `解：`/`代码：`）/ ④易错 / ⑤小结 + tier 标注（【本节最小必需】/【选学·后期必用（何时用/依赖哪节）】/【参照】）；**分块呈现（R41）照适用**——一次只追加一个目，学员跟上检验再进下一目，不整篇投喂。
- **状态与定稿**：讲义头部带状态行（`- 状态：草稿（…）`）；节闸口通过前保持草稿、不删（草稿留存口径见本册「讲义状态行」区）；定稿仍走真人冷读四证与本册定稿硬项——**边讲边写不豁免任何定稿闸口**。
- **版面与体例**：草稿期按本小节最小形态落盘（答案框用引用块、字级排印随 `references/layout/char-typography.md`——s3-teach core 已载）；写盘前按 Markdown 基本格式自检列表空格、行内 `$` 成对、标题层级与表头，不设机器闸口；**完整单元 schema 与版面契约唯一事实源在 `references/handout/unit-schema.md`、`references/layout/handout-page.md`、`references/layout/handout-elements.md`（讲义场景 core，本轮不加载），定稿前由讲义场景按完整 schema 补齐**；既有单元只作内容参照不作体例范本。追加完提示学员：「草稿已就位，节末可走讲义修订场景定稿」。
