## 数据根（稳定根）

**规范数据根**：`<工作区根>/.learning/`。本分册全篇的「数据根」均指此路径——任何下级布局都**不再重复 `.learning` 目录段**（避免 `…/.learning/.learning/<slug>/` 的双重嵌套）。

为避免相对路径随会话 cwd 漂移导致「找不到进度」，遵循三条硬规则：

1. **一次解析、写进文件**：会话首次建立/迁移任务时，把解析到的**绝对数据根**写进 `<数据根>/<slug>/progress.md` 的「数据根」字段；此后以该字段为准，不重新猜。
2. **入口先枚举**：任何「继续学习/问进度」都先枚举数据根（宿主的目录枚举能力（根路径与匹配模式分开传入，任务目录匹配 `*/progress.md`）；若目录枚举能力不可用或返回异常，以 `python "<技能根>/scripts/task_index.py" --root "<数据根>"` 兜底），再匹配任务。
3. **不逃逸**：所有写入必须落在数据根之内（红线 CR-7）。

**根解析优先级（F11，从高到低，命中即止）**：

1. **明确用户路径**：用户显式给出的数据根 / 工作区路径；
2. **已知活动任务**：progress.md 已写「数据根」字段（规则 1）→ 直接采用；
3. **宿主工作区根**：宿主提供的工作区根下 `<工作区根>/.learning/`；
4. **限定项目发现**：在当前工作区范围内**限定深度**发现 `.learning/`（**不做全机扫描**）；
5. **当前目录兜底**：`<cwd>/.learning/`（仅当以上皆不可得，且视为**待确认**）。

- **跨 cwd 必须找到同一任务**（冒烟自检口径不变）；**不同 cwd 不得因兜底根制造重复任务**。
- **续学时若发现失败，不自动新建任务**；确实不明时**只向用户确认一次工作区**（不反复追问），确认后再按优先级解析。

> 冒烟自检：两个不同 cwd 的会话访问同一主题，必须定位到同一 `<数据根>/<slug>/progress.md`（以「数据根」字段与 slug 为准）。

### 续学匹配（多任务与科目别名）

- 命中同名任务 → 续学：只读其 progress.md「当前阶段」，不得覆盖既有文件。
- 命中多个任务且用户未指名科目 → **列出候选**（科目名 + 当前阶段 + 最近学习日期），请用户选择；不猜、不默认最近一个。
- 用户指名科目 → 按科目与任务 slug/主题模糊匹配（含别名，如「高数」↔ shaanxi-gaoshu），命中单个即续学。
- 未命中 → 新任务，从 S0 开始。
- 枚举异常或为空但怀疑有数据 → 先用 `task_index.py --root` 兜底；`scan_status=partial/failed` 时任务集合不完整，不得当「无任务」处理，停止枚举/续学并修复后重跑。

## 目录布局

```
<数据根>/                          # = <工作区根>/.learning/
├── index.json                     # 派生索引（由脚本重建，禁止手改）
├── profile.md                     # 学习者画像（可选全局文件，跨任务共享；见「学习者画像」小节）
└── <slug>/                        # 每个主题一个目录，单属主免冲突
    ├── progress.md                # 唯一人类可读事实源
    ├── 知识清单.md                # KP 清单（任务目录第一层，与 progress.md 平级）
    ├── materials/                 # 讲义：NN-<小节名>.md；结课另有 复习清单-<课程名>.md
    ├── exercises/                 # 题组与判分：NN-<小节名>-<日期>.md
    └── trace.jsonl                # 结构化执行轨迹（可选，默认关闭；测评时启用）
```

- `materials/00-备课来源.md` 为可选备料台账（无材料任务；00 为专号，不占小节编号，不参与 `exercises/` 判定比对；无此文件合法）。
- `<数据根>/index.json` 是**派生缓存**，由 `<技能根>/scripts/task_index.py` 从各 `<数据根>/<slug>/progress.md` 重建，**绝不手工编辑**（单一事实源是 progress.md，索引只是它的物化视图）。**默认不物化**——`task_index.py` 默认只读、不写缓存；需物化时显式加 `--write-index`（写时**原子替换**：同目录临时文件 + `os.replace`，区分「未变化/写入失败」，失败保留原缓存、不产生半截 JSON）；`scan_status=failed` 时**绝不覆盖**既有缓存。
- 枚举**只扫数据根下第一层**：任务目录 = `<数据根>/<slug>/progress.md`；更深的嵌套目录（如 `<数据根>/a/b/progress.md`）**不在扫描范围**，请勿手动制造深层任务。
- 旧版单文件 = 数据根下第一层的裸 markdown（`*.md`），**扩展名大小写不敏感**（`.md` / `.MD` / `.Md` 均识别）；**但不含合法全局文件**——`profile.md`（学习者画像）不属旧版单文件，枚举与迁移时必须剔除（`task_index.py` 已内置排除名单，勿再判为待迁移任务）。
- **编号契约**：`materials/`、`exercises/` 的文件名编号**推荐两位补零**（`01-`、`02-`…）；脚本对「已掌握↔判分记录」的比对**同时接受 `1-` 与 `01-` 两种写法**（宽容匹配），但为一致性仍建议两位补零。文件名中的小节名须为**文件系统安全字符**（去除 `/ \ : * ? " < > |` 与首尾空格，含全角标点的小节名以连字符替换后落文件名）。

```markdown
## 参考答案（判分完成后回填；可选）
```

- **参考答案区块（可选，判分后回填）**：位置固定在文件**末尾**（「作答与判分」之后）——`progress_check.py` 的 `evidence_section` 截到下一个二级标题为止，区块放在判分段之前会把判分记录截断。**出题时不预写**（防泄题），判分完成后回填；客观题写「答案 + 一句依据」，主观/论述题写要点行或 `见 materials/NN-…md 概念 N 的 ③ 框`，不复制讲义全文。**正文唯一事实源仍是讲义 ③**：本区块只做复习索引，二者不一致时以 ③ 为准并同步更正。**不另建 `-答案.md` 分册**——`exercises/` 内文件按编号前缀被当作判分证据消费，同前缀的答案文件会被误当证据（`E-EMPTY-EVIDENCE` / 证据错配）。
- **组卷（独立触发「组一套卷」）**：卷末同设 `## 参考答案` 区块，题面区顶部写一行「作答后再看文末答案」；不拆答案册，命名与普通题组一致。

- **结课综合测验（`99-`）额外一行**：文件头写 `目标线：a/b`（如 `目标线：4/5`，可写 `目标线：7/10` 这类非 5 题卷）。这是 `progress_check.py` 判达标线的机器可读入口：**不写按契约 `gates.final_ratio` 判**，写了按该值判（`a ≤ b`）；**非法值 → `E-FINAL-INVALID-TARGET` 拦停，不得回退默认线**。普通小节题组不需要这一行；收紧/放宽达标线却没写这行，脚本仍按契约默认拦停。
- **分型标签**：若 `知识清单.md` 的 KP 声明了类型/视觉任务，attempt 行补 `KP=KP-xx-xx`；视觉任务再加 `｜视觉=<任务>`；概念/设计在复述勾选行写该 KP 编号。未声明类型的旧任务不需要补标签。
- **正式/轻量确认（可选）**：关键块正式确认写入 `## 作答与判分`，标 `用途=推进`；有对应 KP 时写 `KP=<id>`，无则只写 `块=<块名>`；计入正确性分母与本节新题总量（题量口径见 `assessment.md`「题量预算」）；不替代题组的关键能力独立通过与小节复述；正式确认可作记忆/程序 KP 的分型证据（带 `KP=<id>` 独立正确），概念/设计仍需复述勾选行含该 KP 编号；早期错误与变式均保留，不删不改。简单块轻量确认不写 `正确性=` 判分行；需要留痕时在学习日志写一句「块名 + 确认方式 + 结果」。
- **块与 KP 映射**：有 `知识清单.md` 时 1 个讲授块 = 1 个 KP；无清单时块 = 当前节目标内最细知识点，可不带 KP。禁止一块挂多个 KP；一个 KP 若需要多个块，先拆 KP 再讲（块定义见 `workflow.md`「逐块推进」）。正式确认题有对应 KP 时写 `KP=KP-<节>-<KP序>`（如 `KP-03-08`）；无对应 KP 时只写 `块=<块名>`。`KP-03-08a` 这类编号不合法，脚本不识别；`块=` 是人读字段，不进闸口计算。
- **判分四态（字段）**：`正确性=` 只接受 `对 / 部分 / 错 / 未判`（兼容 `正确 / 错误 / correct / incorrect / partial / ungraded` 等写法）。**作废不删除原判分行**，必须写原因；改判时新增一行（可复用原 `attempt_id`，旧行已作废即不参与冲突判定）。**四态语义、分母与调度口径见 `assessment.md`「判分口径」**。
- 判分三维（正确性／独立性／流畅度）与调度档位口径见 `assessment.md`「判分口径」；**闸口计分口径见 `assessment.md`「判分口径」**（按正确性计，慢不折算），独立性/流畅度另列不折算。**逐关键能力独立通过（v2.5）**：声明了「关键能力」区块时**每项须至少一次独立正确**，关键项错**不能被简单题抵消**（脚本 `E-KEY-ABILITY-UNMET`）；**独立性枚举**（独立 / 提示后·提示②–④ / 未测）——**缺失或 `未测` 一律不推为独立**（`E-NO-INDEPENDENCE`），同一 `attempt_id` 幂等去重、冲突判定报 `E-ATTEMPT-CONFLICT`；**目标为操作/作品型时**「操作作品验收」区块（≥2 个已勾选核验项）与复述清单**等价可替代**。**信心可选**：仅在**反馈前**随作答提交者记「信心=<1-5>」、方可用于 cw／校准；反馈后补报标「信心=回顾性」，**不用于 cw、不用于校准**。时序规则见 `assessment.md`「判分口径」；错题入错题本时同轮完成归因定级（错因/级，见 `teaching.md`「错因分类与补救」）。
- **证据内容抽查（W-EMPTY-EVIDENCE）**：判分记录文件存在但**未提供可用证据**（空文件、或只含「作答/判分」标题模板而无真实结果行）→ `progress_check.py` 历史模式输出 `W-EMPTY-EVIDENCE`（warning 级，不阻断旧任务）；**放行模式（`--release`）升级为 `E-EMPTY-EVIDENCE`（error）**——空/模板证据不得支撑本次新增掌握或结课结论。文件缺失仍为 `E-NO-EVIDENCE`（error）。
- 闸口未过时不删题组，补齐判分后继续；S4 变式自创题文件用 `z-` 前缀（见 `workflow.md` S4）。

## slug 规则与冲突处理

- slug = 主题的稳定标识：小写、去空格、中文转拼音或直接用**主题短名**，仅保留字母/数字/连字符，长度 ≤ 48。
- 生成 step：先枚举既有 slug；无冲突直接用；有冲突则追加序号或短哈希（如 `python-2` / `python-a1b2`）。
- **禁止**在两个不同主题间复用同一 slug；同名不同课程必须区分（避免互相覆盖）。
- 无主题上下文时**不得**生成 slug（红线 SR-1）。

## 版本号体系

三层版本互不混淆：**包版本**（SKILL.md frontmatter `version`，以该字段为准）；**数据 schema 版本**（脚本输出 `schema` 键，如 `learn-task-index/5`、`ltw-due-queue/3`、`ltw-calibration/3`——加键不破坏消费方时 +1，消费方按存在性读取新键）；**兼容代际**（progress.md 条目形态 v2 / v2.1 / v2.2，行为差异见「三种数据形态兼容行为表」）。

**升版规则**：major = 闸口通过线/对外契约行为变更（如 S5 测验通过线分型）；minor = 向后兼容的机制新增（如新增告警码、可选字段）；patch = 修复与表述修正。包内不保留改动历史（零史纪律），版本演进仅以包版本号体现。

### 复习调度字段（薄弱点 / 错题本 / 保持复习条目元数据）

> 何时读：写薄弱点/错题/保持复习条目的元数据（挂载点、字段表、cw/顽固语义）时。

薄弱点条目的调度元数据放**行尾全角括号内**（半角括号 `()` 亦兼容，推荐全角）、逗号分隔的 `键=值`（`cw`/`顽固` 为无值标记）；错题本与保持复习条目在行尾追加「｜ 元数据：…」段（竖线分段与「元数据：」冒号均全角/半角双兼容）。保持复习行推荐以 `[YYYY-MM-DD]` 掌握日期开头；缺日期时用「最近更新」兜底并告警，仍缺 → `W-UNPARSED-ITEM` 不入队（不猜当日）。解析器只认这些挂载点，其余文本不动。`S'/D'/due` 的计算由 `<技能根>/scripts/scheduler.py next-interval` 负责（判分归模型、算数归脚本，调用细则见 `assessment.md`「间隔调度」）。`due-queue` 输出新增 `reason` 字段（到期/逾期/优先级的人类可读说明），schema 为 `ltw-due-queue/3`。`错因`/`级`/`meta_default` 只对薄弱点/错题有意义；`kind=保持` 时前者为空、`meta_default=false`，不参与问题元数据。

| 字段 | 类型/取值 | 语义 | 默认值（缺省时） |
|------|-----------|------|------------------|
| S | 浮点（天） | 稳定天数，间隔重复核心参数 | 3.0 |
| D | 数值 0.5 粒度，[1,5] | 难度 | 3 |
| last | YYYY-MM-DD | 最近一次判分日期（绝对日期，禁相对日期） | 取 progress.md「最近更新」；仍缺 → 不入队，报 `W-UNPARSED-ITEM`（不猜当日） |
| due | YYYY-MM-DD | 下次复习日。**新写由 `scheduler.py` 以「本次复习日 + interval」计算**（见 `assessment.md`「间隔调度」）；旧条目缺 due 时按 `last + round(S)` 兜底推算 | 由 last 推算 |
| 信心 | 1–5 | 作答信心自评（**反馈前**提交方可用于 cw/校准；反馈后补报标回顾性） | 未写 → 不计入校准分母（不补 3） |
| cw | 标记（无值） | 自信但错（**反馈前**信心 ≥4 且判错），due-queue 排序优先 | 无 |
| 顽固 | 标记（无值） | 提示阶梯两次到梯底，重教不重测（见 S3/S4） | 无 |
| evt | 可选 ID | **作答事件 ID（v2.3）**：同一次作答的投影（错题 / 薄弱点）共享同一 `evt`，供校准统计去重（T04）；旧条目缺 = 合法 | 无 |
| 错因 | 枚举：知识性 / 理解性 / 技巧性 | 归因分类，决定 S4 补救动作（重学 / 审题圈画 / 限时技巧）。**语义属性，归模型判断写入，禁止脚本代判** | 知识性 |
| 级 | 枚举：A / B / C | A=反复出错 / 直接影响学习目标达成的核心条目（详细整理+变式）；B=一般理解偏差（记思路）；C=纯粗心（仅标知识点）。与错因同轮由模型定级，S4 复习判分可调整级别 | B |

- `cw` 只由「信心 ≥4 且判错」产生；cw 条目修复后照常走清除/归档规则。
- due-queue 对 `顽固` 条目标 `teach:true`（排序不豁免），由模型据文本规则改走重教。
- **`错因` 枚举放元数据段，与既有自由文本「错因：<具体描述>」并存不冲突**：自由文本答「错在哪」（行内 `错因：` 全角冒号写法），枚举答「属哪类、该用什么补救」（元数据段内 `错因=` 等号写法）。解析器只在元数据段内搜 `错因=`，正则锚定于元数据段，不会误吃行首自由文本。
- **`级` 与 `错因` 是内容属性（错什么），S/D 是调度属性（何时再练），互不替代；`级` 不参与 due-queue 排序**（排序契约 cw→最逾期→due 早→稳定序不变），分级只影响整理深度与复盘注意力，脚本仅在输出中回显 错因/级 供模型取用。

### 字段向后兼容（旧条目缺字段）

> 何时读：遇到无新字段的旧条目，决定补默认值的方式与责任人时。

1. **不做批量迁移、不新建文件**：v2 条目（无括号/无元数据段）与 v2.1 条目（有调度字段与信心、缺 错因/级）均**原样保留**，缺新字段按上表默认值处理。
2. **补齐时机与责任人**：**首次在 S4 复习 / S3 热身 / due-queue 中遇到该条目时**，由**模型**按契约初始值（default_s / default_d）计算 due 并**顺带在下一次对 progress.md 的正常文件写入/编辑 中补写**（如判分落盘时一并补），不为迁移单独发起写盘。
3. **due-queue 对旧格式的行为**：有「最近更新」→ 按默认 S/D 推算 due，条目标 `migrated:true` 输出；连「最近更新」都没有 → 该条目**不入队**，输出 `W-UNPARSED-ITEM` 告警，**exit 0 不报错不崩溃**（最坏情况输出空队列）。
4. 日期一律 `YYYY-MM-DD` 绝对日期（既有铁律延伸到新字段）。
5. **错因是语义属性，模型侧不得盲目补写默认值「知识性」**：S/D/last/due 是**数值参数**，补默认无害，沿用第 2 条「顺带补写」；但 `错因`（与 `级` 同理）缺省值只是**脚本输出侧**的占位回显（脚本输出标 `meta_default:true`，告知消费方这是补默认不是观测）——模型侧遇到旧条目复习时，必须**按当下归因判断写入真实值**（这本身就是 S4 的归因动作），补错默认会把「技巧性失误」误导向「回归材料重学」这一最重补救，与「纠错优先于重讲」总原则相悖。
6. **缺省归因可修正话术**：S4 遇到错因为缺省推断的条目，可向学员说明「该条错因为缺省推断，如与实际不符请指正，可推翻重归因」——允许学员或后续判分推翻重归因。

### 稳定引用 · 对账 · 提交顺序（F09 / F10 / F12）

> 何时读：新增/重排小节、写双写账本、多文件落盘（掌握/结课/跨阶段）时。

**稳定引用（F09，可选、append-only、零迁移）**——把「对象身份」与「展示顺序」解耦。**落点规定（消费者优先按稳定 ID 匹配）**：
- `lesson_id`：小节稳定标识（如 `L-02`），**改名 / 同名 / 换序都不变**。**落点三处**：①**路线行**——`- [x] 1. 循环（lesson_id=L-B）`（全/半角括号均可）；②**判分记录文件头**——首行或标题下写 `lesson_id=L-B`（如 `# 循环，lesson_id=L-B`）；③**讲义/材料头**同理。`当前小节` 序号仍保留供人读，二者分离。
- **匹配规则（`progress_check.py` 的消费口径）**：路线行声明了 `lesson_id` 时，**先按 ID 在 `exercises/` 中精确匹配**该 ID 的证据文件（重排后序号对不上也能匹配正确对象）；**匹配不到时**回退按文件名序号前缀匹配（旧资料零迁移）；**回退命中却声明了另一个 `lesson_id` → `E-EVIDENCE-ID-MISMATCH`**（放行模式拦停，防止串用他节证据）。
- `attempt_id` / `evt`：一次作答的稳定标识，写入条目元数据段 `evt=`（或判分行 `attempt_id=` 前缀）；同一作答产生的「错题」与「薄弱点」两条投影**共享同一 `evt`**（供校准去重）。
- **动作游标引用**：`## 下次续学` 行的「待回应」须指向**存在的**判分记录（文件名或其前缀）、「最后提交」须指向**已出现的** `evt=`/`attempt_id=` 值；悬空引用在放行模式报 `E-CURSOR-DANGLING`（历史模式 `W-CURSOR-DANGLING`），恢复时不得把悬空游标当有效定位。
- **不自动重编号**：既有 KP ID（`KP-<节序>-<KP序>`）与旧数据一律保留原值；小节改名/换序后**引用材料与作答仍对应正确对象**，不靠序号猜、不追溯撤销历史。
- 脚本对未知可选字段**零感知**——旧任务缺这些键 = 合法，无需迁移。

**对账（F10，按对象 ID）**：「清单状态」与「progress.md 处置」双写按**对象 ID 集合对账**——有 KP 时以 `KP-xx-xx` 为准（状态单源 + 处置理由单源，progress.md 只存摘要）；**数量相同但对象不同也能检出**（W-KP-HOLD-CROSS 列出「仅清单 / 仅区块」差异，见上「暂缓/排除双写」条）；无 KP 的任务保留任务级处置。不新增第三份账本。

**提交顺序（F12，先校验拟提交状态、后提交，可重试）**——多文件更新按固定次序，断在任一步都停在「未提交」态，绝不出现「无证据已掌握」：
1. 先写**证据与材料**（`exercises/` 判分、`materials/` 讲义）；
2. 再准备 **KP / 处置变更**（清单状态、暂缓与范围外）；
3. **校验拟提交状态**——把**目标状态**送进校验器，而不是只校验磁盘旧状态：`progress_check.py <任务目录> --release --proposed-phase <目标阶段>`（拟转阶段时）或 `--staged <候选 progress 快照>`（候选文件），并用 `--changed-lessons <本次新增小节号>` 限定增量范围；校验通过后才写盘（脚本输出 `proposed_state_supplied` / `checked_lessons` 回显；未提供拟提交状态时 `proposed_state_supplied:false` + `W-NO-PROPOSED-STATE`，**不得据此声称目标变更已校验**）；
4. 最后**提交掌握 / 阶段**（progress.md 阶段字段、小节勾选）；
5. 派生**摘要**（覆盖摘要行、范围快照）。
- 失败保留可重试点（脚本幂等、文件写入/编辑能力覆盖同值 → 重跑不重复事件）；**不宣称已有跨文件原子事务**——只保证次序与可重试。

## 知识清单文件

**文件**：`<数据根>/<slug>/知识清单.md`，任务目录第一层、与 progress.md 平级（不放 materials/）。**单一事实源声明**：KP 集合与 KP 状态的唯一事实源是本文件；progress.md 只存指针，不重复记账。**原子判据**：每个 KP = 当前节目标内的最细知识点，1 道题可独立检验；需 2 道题分别检验两个判断 → 拆 KP；不设时间上限。不达标条目拆分或合并后再入清单，归模型纪律。**状态枚举**：未讲 / 已讲 / 暂缓 / 排除（与审计四态同源）。

**格式模板**（逐行 + 全角 ｜ 分段；**示例仅为格式演示，KP 的取舍与依赖声明规则本身领域无关**）：

```markdown
## ② 稳定模式（跨多次对话看清的，每条必须带证据；**带作用域：默认任务级，非全局人格标签**）

- <教学方法裁决>：<有效 / 低效>（**作用域：<学科族 / 任务 / 目标>**；条件：<什么场景下>；证据：<日期> <场景与效果>；裁决日期：<YYYY-MM-DD>；状态：<生效 / 已复评 / 已关闭>）——同一条裁决**可复评、可关闭、可删除**；低效裁决在**其作用域内**不再推该方法，**不跨任务/学科族永久禁用**（数学类比无效 ≠ 编程类比无效），也不写成人格标签

## ③ 观察暂存（注意到了但没看清的，只记场景）
- <日期> 在 <什么场景> 做了 <什么>——<尚未归类，不起名字>
```

**三条铁律（画像纪律）**：

1. **①层只存学员明说的**，且只收**明确通用偏好**（跨主题适用）：模型观察到的偏好不算——学员明确说「讲慢点 / 别用类比讲代码」才进①层；擅自给学员贴偏好标签是越界。**任务级偏好不进①层全局段**——落到对应任务或②层作用域。
2. **②层必须有证据且带作用域**：每条稳定模式附 ≥2 条独立证据（日期 + 原话/场景）；**「永远不要从一次观察直接升级成画像」**——单次表现只进③层记场景，第三次以上同向证据才允许升②层。**教学方法裁决**带条件与作用域、证据与日期，**可复评/关闭/删除**——低效裁决只在作用域内生效，换学科族或换目标时**重新评估**，不做「连续 N 次低效即永久禁用」的绝对处置。
3. **写入前展示确认**：①层学员亲口说的事实**免确认**——学员刚说过的内容直接落盘，导师以自然话术带过（如「好，类比就用做饭」），不重复问「可以存吗」；新增②层条目时，把要写的内容读给学员、明确说「可以/对/保存」后才落盘；③层追加不需要逐条确认，但下次读到时学员可要求删除任何一条；**学员任何时候可要求删除/关闭②层任一条裁决**。

**写法纪律**：每条 ≤120 字；用**动词短语**（“用 X 能独立完成”“卡在 Y”“换 Z 后通过”），不用形容词标签；每条带**证据**（日期 + 场景/原话）；推断标“暂定”，只有学员陈述或后续证据才升级；禁用绝对化词（深刻、彻底、完美掌握、专家、热爱、总是、从来不、完全理解）；无证据不写；空更新合法；**当前证据与当前表态优先于旧记录**；一次困难不得写成全局人格判断。正例：“遇到递归先画调用栈再写代码（2026-10-20 学员原话：画出来就不乱了）”；反例：“学员递归很差 / 彻底掌握了递归”。

**消费方**：S3 讲授类比优先取①层「类比领域」（衔接 `teaching.md`「类比纪律」）；跨界三猜想的「确证已会」可用②层稳定模式作证据之一（仍以摸底判分/亲口确认为最强）；S3 讲授呈现与④批改的反馈措辞同取①层沟通约定；**任务级偏好按任务作用域读取**；「换角度重讲」/换讲义风格时**先查②层教学方法裁决**，**仅在其作用域内且状态为「生效」时**才不重复推该方法（裁决可复评/关闭/删除）。**画像不参与任何闸口判定、不进脚本**——它是教学个性化素材，不是调度数据。

**零迁移**：既有任务无 profile.md = 合法形态，不补建、不批量迁移、不报错；脚本（task_index / progress_check / scheduler / kp_sort）**零感知**此文件，不出任何告警。

## 旧版迁移映射

**零迁移补充**：旧判分行只有 `对/错` 仍按既有语义解析；`部分/未判/作废` 是新增可选写法，不要求回填。旧任务没有 `## 保持复习` 区 = 合法形态，`due-queue` 不报错、不补建；仅当本次新增大纲/复习动作需要时才按新格式追加。不得为了「升级」批量改写旧判分记录或旧 progress.md。

发现旧版数据时按类型处理，**迁移前先备份原文件、迁移后告知用户**（红线 CR-6）：

| 旧形态 | 识别 | 迁移动作 | 阶段取值 |
|--------|------|----------|----------|
| 目录 + progress.md（v1） | 有目录、progress.md 缺「数据根/复习来源阶段」 | 补齐新字段；保留原内容 | 沿用原「当前阶段」；缺失则按下表推断 |
| 单文件 `<slug>.md` | 数据根下只有裸 markdown | 建 `<slug>/` 目录，写 progress.md，建 materials/、exercises/ | 见下方推断 |

**阶段推断规则（无「当前阶段」字段时）**：

1. 有「学习路线」且有小节已勾选 → 逐节学习（当前小节 = 首个未勾选）。
2. 有路线、无小节勾选 → 计划确认中。
3. 只有材料/目标、无路线 → 诊断摸底。
4. 完全空白或无法解析 → 接料建档（S0），并把原文件内容存入「材料」区，不丢数据。

**冲突处理**：目标目录已存在 → 不覆盖，改用带后缀的 slug，或经用户确认后覆盖（红线 CR-1）。

**备份位置与删旧文件**：备份写到 `<数据根>/_backup/<YYYY-MM-DD>/<原文件名>`——放在第二层子目录，枚举只扫第一层裸 md，备份不会被误判成第二份待迁移数据；文件用**复制**不用移动，验证通过前原件不离开原位。删旧文件须同时满足四条：① 备份与原件**逐字一致**；② `task_index.py` 枚举正确（新任务 `task_count` 命中、`legacy_single_files` 不再含该文件）；③ `progress_check.py` 已跑；④ 用户明确确认删除。**若 `progress_check` 报 `E-*`**（典型：旧数据「小节已勾选但无判分记录」→ `E-NO-EVIDENCE`）：**旧文件先留着**，处置完（补真实确认题，或经确认把该节改回未勾选）再删；只有用户明确接受「带着这条 E 迁移」时才可删，并在学习日志记下该决定。**迁移完成 ≠ 校验全绿**——如实暴露 E 并处置，才算完成，不得为让校验变绿补造判分记录。

## 结构化 Trace 输出（可选，默认关闭）

仅当回归测评需要过程数据时，才在闸口推进或会话收尾向 `<任务目录>/trace.jsonl` **追加一行** JSON（幂等，追加不改旧行）；**日常使用不强制记录**，不得因未记 Trace 而阻塞任何流程。字段稳定，供测评做「过程对比」与「基线回归」：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts` | string | ISO8601 时间戳 |
| `session_id` | string | 本次会话标识 |
| `phase` | string | 阶段名（枚举同 progress.md） |
| `step` | string | 阶段·动作（如 `S3·练习`） |
| `gate` | string | 本次对应的闸口判据 |
| `gate_result` | string | `pass` / `fail` / `na` |
| `tools` | array | 本步用到的工具名 |
| `files` | array | 本步读写的文件（相对数据根） |
| `evidence` | string | 落盘证据的定位（题号/检查清单/用户原话摘录） |
| `tokens` | int/null | 本步 token 消耗（会话末由平台回填，不可得填 null） |
| `duration_ms` | int/null | 本步耗时（同上） |

## 成本画像埋点

开启 Trace 时，会话收尾追加一条 `kind:"session_summary"` 记录，采集效率指标：

- `tool_calls`（本会话工具调用次数，可计数）
- `files_touched`（读写文件数，可计数）
- `gate_passes` / `gate_fails`（闸口通过/未通过次数，可计数）
- `tokens_total` / `duration_ms_total`（平台可回填则记，否则 null）
- `retries`（重试次数）

**用途**：让「效率退化」在回归测评中可被机器判定（如 token 或工具调用数超出基线的某比例即报警）。指标只增不减地追加，历史基线可逐次对比。
