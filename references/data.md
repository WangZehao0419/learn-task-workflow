## 课程体系（规划簿）

### 课程体系文件

**文件**：`<数据根>/<slug>/课程体系.md`，任务目录第一层、与 progress.md 平级（不放 materials/）。它是**详细的课程规划**：章/节/目三级结构 + 每目的账本行，同时承担四职——覆盖分母、前置依赖图、术语账本（`引入` 列，R46 出题对账）、分型验收底座。**全类型强制**：四类任务 S2 一律生成；唯一例外 = 极简任务经用户确认的「无课程体系」形态（对照结论声明理由）。**详细度标准 = 原子判据**：细化到「1 道题能独立检验」的最细知识点（目）才算合格；允许分批细化（覆盖范围行显式标注），但**每节开讲前本节目的必须细化完毕并登记引入列**。

**格式模板**（逐行 + 全角 ｜ 分段；**示例仅为格式演示，目的取舍与依赖声明规则本身领域无关**）：

**层级口径（章/节/目）**：**章** = 课程顶层分组（教材的部/章、考纲板块或自拟分组；教材结构与课程章的对应经「章→节」归属与对照结论呈现，不要求一一对应）；**节** = 学习路线一行（`- [x] N. 节名`）；**目** = 节下最细知识点。**目行 = 原 KP 行**，编号 `KP-<两位节序>-<两位KP序>`（如 KP-03-08 = 第 3 节第 8 个目），两位补零沿用材料编号契约，脚本宽容匹配单位数；纯数字字典序 = 教学序，编号全文件唯一。**每个目必须有目名**（即知识点名），目名节内唯一；**目序按节连续，禁止按场/次分段重编号**。**1 个讲授目 = 1 个 KP**：禁止一个目挂多个 KP；一个知识点若需要多个目，先拆 KP 再讲（目定义见 `references/workflow.md`「逐目推进」）。对学员指代一律用目名、编号只落盘（口径见 `SKILL.md`「十一条教学红线（判据自足，任何场景都生效）」）。

- **字段合法性**：前置列只接受合法 KP 编号或空；`progress_check.py` 校验前置引用存在性（引用不存在的 KP → W-UNPARSED-KP）；行畸形（缺段/状态非法）→ W-UNPARSED-KP，**不计入摘要计数**（不静默）。
- **互为前置定向**：概念目与程序目互为前置会成环，`kp_sort.py` 报环即停；此时按「先教可独立检验的一侧」定向登记前置边，另一侧紧接着教（同节或相邻节，不悬空），复习把两侧串起来。
- **可选分型字段**：目行第 6 段后追加 `｜ 类型：记忆/概念/程序/设计`（精确枚举；全/半角冒号均可）与/或 `｜ 视觉任务：识别/关系/图表/比较`（多选用逗号/顿号分隔）。声明后启用分型验收；口径见 `references/workflow.md`「S3 闸口（可检验）」。KP 标签支持单位数别名（`KP-1-1` ≡ `KP-01-01`）。分型门按 KP 编号的节序归组；重排节时保持编号稳定或同步更新 KP 编号/所属节，避免分型证据串节。`kp_sort.py` 只读前六段，忽略可选字段；可选字段畸形 → W-UNPARSED-KP，放行模式另报 E-KP-TYPED-GATE（不能靠写坏字段绕过分型门）。
- **引入字段**：追加 `｜ 引入：<术语1；术语2>…`，登记该目**首次引入**的术语/记号/族名（如「定语」「现在完成时」「±记号」；分号或顿号分隔）。这是出题前术语对账（R46，见 `references/assessment.md`「出题前术语对账（R46）」）的账本：`scripts/prereq_check.py --list <课程体系.md>` 以已讲目的引入列 ∪ 目名 ∪ 追加项为「已引入集合」，扫描题面中的未引入术语。**新任务开节时逐目登记**；术语命名与讲授一致（同一概念全文件同名），畸形容忍：缺段不报错，只贡献空集。
- **覆盖范围行（分批显式标注）**：分批产出时必须写「已细化至第 N 节，其余待细化」；行缺失视同全量；分批未显式标注即 SR-7 命中。未拆节的滚雪球候选拒绝入目行（仍留 progress.md「暂缓与范围外」标「滚雪球候选」）。
- **progress.md 指针（元信息区可选字段）**：`- 课程体系：课程体系.md ｜ 版本 <N> ｜ 总 <M>`——指针存在但文件不存在 → W-KP-LIST-MISSING。
- **暂缓/排除双写与交叉核对**：课程体系目行记状态（分母账本），progress.md「暂缓与范围外」记处置明细（处置账本），职责不重叠。交叉核对**按对象 ID 集合对账**（**数量相同但对象不同也能检出**；warning 级，由 `progress_check.py` 只读输出）：目行暂缓集合 ≠ progress.md 暂缓区块可比条目的 KP 集合（剔除设计性范围外与排除条目）→ **W-KP-HOLD-CROSS**（暂缓侧，列出「仅清单 / 仅区块」差异）；目行排除集合 ≠ 处置为排除条目的 KP 集合 → **W-KP-HOLD-CROSS**（排除侧）；节勾选「已掌握」× 该节目行全「未讲」→ **W-KP-STATE-MISMATCH**（可能是账本滞后，处置归模型提醒补齐）。

## 结课综合测验目标线（99-）

- **结课综合测验（`99-`）额外一行**：文件头写 `目标线：a/b`（如 `目标线：4/5`，可写 `目标线：7/10` 这类非 5 题卷）。这是 `progress_check.py` 判达标线的机器可读入口：**不写按契约 `gates.final_ratio` 判**，写了按该值判（`1 ≤ a ≤ b`；`a=0` 视为非法）；**非法值 → `E-FINAL-INVALID-TARGET` 拦停，不得回退默认线**。普通节题组不需要这一行；收紧/放宽达标线却没写这行，脚本仍按契约默认拦停。

## 数据根与目录布局

题组与判分文件（exercises/）的结构与字段正本：`references/assessment.md`。

### 数据根（稳定根）

**规范数据根**：`<工作区根>/.learning/`。本分册全篇的「数据根」均指此路径——任何下级布局都**不再重复 `.learning` 目录段**（避免 `…/.learning/.learning/<slug>/` 的双重嵌套）。

为避免相对路径随会话 cwd 漂移导致「找不到进度」，遵循三条硬规则：

1. **一次解析、写进文件**：会话首次建立/迁移任务时，把解析到的**绝对数据根**写进 `<数据根>/<slug>/progress.md` 的「数据根」字段；此后以该字段为准，不重新猜。
2. **入口先枚举**：任何「继续学习/问进度」都先枚举数据根（宿主的目录枚举能力（根路径与匹配模式分开传入，任务目录匹配 `*/progress.md`）；若目录枚举能力不可用或返回异常，以 `python "<技能根>/scripts/task_index.py" --root "<数据根>"` 兜底），再匹配任务。
3. **不逃逸**：所有写入必须落在数据根之内（红线 CR-7）。

**根解析优先级（F11，从高到低，命中即止）**：

1. **明确用户路径**：用户显式给出的数据根 / 工作区路径；
2. **已知活动任务**：progress.md 已写「数据根」字段（规则 1）→ 直接采用；
3. **宿主工作区根**：宿主提供的工作区根下 `<工作区根>/.learning/`；
4. **限定项目发现**：在当前工作区范围内**限定深度**发现 `.learning/`（**不做全机扫描**）；
5. **当前目录兜底**：`<cwd>/.learning/`（仅当以上皆不可得，且视为**待确认**）。

- **跨 cwd 必须找到同一任务**（冒烟自检口径不变）；**不同 cwd 不得因兜底根制造重复任务**。
- **续学时若发现失败，不自动新建任务**；确实不明时**只向用户确认一次工作区**（不反复追问），确认后再按优先级解析。

> 冒烟自检：两个不同 cwd 的会话访问同一主题，必须定位到同一 `<数据根>/<slug>/progress.md`（以「数据根」字段与 slug 为准）。

- `materials/00-备课来源.md` 为可选备料台账（无材料任务；00 为专号，不占节编号，不参与 `exercises/` 判定比对；无此文件合法）。
- `<数据根>/index.json` 是**派生缓存**，由 `<技能根>/scripts/task_index.py` 从各任务的 `progress.md` + `课程体系.md` 重建，**绝不手工编辑**（单一事实源是这两份文件，索引只是它们的物化视图）。**默认不物化**——`task_index.py` 默认只读、不写缓存；需物化时显式加 `--write-index`（写时**原子替换**：同目录临时文件 + `os.replace`，区分「未变化/写入失败」，失败保留原缓存、不产生半截 JSON）；`scan_status=failed` 时**绝不覆盖**既有缓存。

- **编号契约**：`materials/`、`exercises/` 的文件名编号**推荐两位补零**（`01-`、`02-`…）；脚本对「已掌握↔判分记录」的比对**同时接受 `1-` 与 `01-` 两种写法**（宽容匹配），但为一致性仍建议两位补零。文件名中的节名须为**文件系统安全字符**（去除 `/ \ : * ? " < > |` 与首尾空格，含全角标点的节名以连字符替换后落文件名）。
- **题组与判分文件（exercises/）**：文件结构与字段正本见 `references/assessment.md`「题组与判分文件（exercises/）」。

### slug 规则与冲突处理

- slug = 主题的稳定标识：小写、去空格、中文转拼音或直接用**主题短名**，仅保留字母/数字/连字符，长度 ≤ 48。
- 生成 step：先枚举既有 slug；无冲突直接用；有冲突则追加序号或短哈希（如 `python-2` / `python-a1b2`）。
- **禁止**在两个不同主题间复用同一 slug；同名不同课程必须区分（避免互相覆盖）。
- 无主题上下文时**不得**生成 slug（红线 SR-1）。

### 版本号体系

两层版本互不混淆：**包版本**（SKILL.md frontmatter `version`，以该字段为准）；**数据 schema 版本**（脚本输出 `schema` 键，如 `learn-task-index/7`、`ltw-due-queue/3`、`ltw-calibration/4`——加键不破坏消费方时 +1，消费方按存在性读取新键）。

**升版规则**：major = 闸口通过线/对外契约行为变更（如 S5 测验通过线分型、数据布局重构）；minor = 向后兼容的机制新增（如新增告警码、可选字段）；patch = 修复与表述修正。包内不保留改动历史（零史纪律），版本演进仅以包版本号体现。

### 三簿分工（数据布局总纲）

每个任务的持久数据按「状态 / 规划 / 叙事」拆三簿，外加全局画像——**一类信息只进一本账**：

| 簿 | 文件 | 装什么 | 不装什么 |
|---|---|---|---|
| 状态簿 | `<slug>/progress.md` | 元信息、薄弱点/错题本/错题归档/保持复习（调度队列）、暂缓与范围外、本次交接、下次续学 | 任何规划与叙事 |
| 规划簿 | `<slug>/课程体系.md` | 章/节/目三级规划、目行账本（状态/前置/来源/类型/引入）、对照结论、材料、材料覆盖、排期、质量保障机制、协作协议 | 判分记录、调度队列、对话叙事 |
| 叙事簿 | `<slug>/记忆.md` | 学习日志（事件时间线）、学习记录（任务级洞察）、讲授证据 | 状态字段、规划 |
| 画像 | `<数据根>/profile.md` | 跨任务学习者画像（见下「学习者画像」） | 任务内洞察（进记忆.md） |

**读写纪律**：续学开场读状态簿恢复游标；开节/重排读规划簿对应章/节；复盘与画像读取读叙事簿。同一信息出现两处 = 结构违规，以本册定义的簿为准并当场去重。判分记录仍在 `exercises/`（单一判分证据源，见 `references/assessment.md`「题组与判分文件（exercises/）」）。

## 学习者画像

### 学习者画像（可选全局文件）

**文件**：`<数据根>/profile.md`，**全局唯一**、跨任务共享（画像放数据根第一层、与任务目录平级）。**偏好按作用域生效（F13）**：①层 = 学员明说的**通用偏好**，跨主题适用；②层「稳定模式」**默认任务级作用域**（可标任务/学科族/全局），**带证据、可复评、可关闭**；**教法裁决与类比领域按任务/学科族作用域生效**，**不得当作跨主题的全局人格标签**，也不得据单任务低效就对同类主题预判。**可选**：无此文件 = 合法形态，不强制创建、不报错；首次触发建立时机 = S1 摸底顺带问「类比领域」时（见 `references/workflow.md` S1），用户不便回答则跳过。**单一事实源声明**：画像内容的唯一事实源是本文件；讲授/类比时由模型现场读取。

**格式模板**（三层结构，逐层追加）：

```markdown
## 学习者画像
- 最近更新：<YYYY-MM-DD>

### ① 明说的偏好（只有学员亲口明确提过的才进这里；**明确通用偏好，跨主题适用**）
- 类比领域：做饭（S1 摸底时确认，2026-10-12）
- 沟通约定：<学员明确要求的沟通规则，如"不要堆术语""重点加粗、结论先行"（无则写「无」）>

### ② 稳定模式（跨多次对话看清的，每条必须带证据；**带作用域：默认任务级，非全局人格标签**）
- <模式描述>（作用域：<任务/学科族/全局>；证据：<日期> <学员原话/具体场景>；至少 2 条独立证据）
- <教学方法裁决>：<有效 / 低效>（**作用域：<学科族 / 任务 / 目标>**；条件：<什么场景下>；证据：<日期> <场景与效果>；裁决日期：<YYYY-MM-DD>；状态：<生效 / 已复评 / 已关闭>）——同一条裁决**可复评、可关闭、可删除**；低效裁决在**其作用域内**不再推该方法，**不跨任务/学科族永久禁用**（数学类比无效 ≠ 编程类比无效），也不写成人格标签

### ③ 观察暂存（注意到了但没看清的，只记场景）
- <日期> 在 <什么场景> 做了 <什么>——<尚未归类，不起名字>
```

**三条铁律（画像纪律）**：

1. **①层只存学员明说的**，且只收**明确通用偏好**（跨主题适用）：模型观察到的偏好不算——学员明确说「讲慢点 / 别用类比讲代码」才进①层；擅自给学员贴偏好标签是越界。**任务级偏好不进①层全局段**——落到对应任务或②层作用域。
2. **②层必须有证据且带作用域**：每条稳定模式附 ≥2 条独立证据（日期 + 原话/场景）；**「永远不要从一次观察直接升级成画像」**——单次表现只进③层记场景，第三次以上同向证据才允许升②层。**教学方法裁决**带条件与作用域、证据与日期，**可复评/关闭/删除**——低效裁决只在作用域内生效，换学科族或换目标时**重新评估**，不做「连续 N 次低效即永久禁用」的绝对处置。
3. **写入前展示确认**：①层学员亲口说的事实**免确认**——学员刚说过的内容直接落盘，导师以自然话术带过（如"好，类比就用做饭"），不重复问"可以存吗"；新增②层条目时，把要写的内容读给学员、明确说"可以/对/保存"后才落盘；③层追加不需要逐条确认，但下次读到时学员可要求删除任何一条；**学员任何时候可要求删除/关闭②层任一条裁决**。

**写法纪律**：每条 ≤120 字（作用域、证据、日期、状态等元数据不计入）；用**动词短语**，不用形容词标签；每条带**证据**（日期 + 场景/原话）；推断标"暂定"，只有学员陈述或后续证据才升级；无证据不写，空更新合法，当前证据与当前表态优先；禁用绝对化词，一次困难不得写成全局人格判断。正例："遇到递归先画调用栈再写代码（2026-10-20 学员原话：画出来就不乱了）"；反例："学员递归很差 / 彻底掌握了递归"。

**消费方**：S3 讲授类比优先取①层「类比领域」（衔接 `references/teaching.md`「类比纪律」）；跨界三猜想的「确证已会」可用②层稳定模式作证据之一（仍以摸底判分/亲口确认为最强）；S3 讲授呈现与④批改的反馈措辞同取①层沟通约定；**任务级偏好按任务作用域读取**；「换角度重讲」/换讲义风格时**先查②层教学方法裁决**，**仅在其作用域内且状态为「生效」时**才不重复推该方法（裁决可复评/关闭/删除）。**画像不参与任何闸口判定、不进脚本**——它是教学个性化素材，不是调度数据。

**零感知**：脚本（task_index / progress_check / scheduler / kp_sort / prereq_check）对 `profile.md` 与 `记忆.md` **零感知**（不解析、不出告警；进度校验所需的审计记录改由 progress_check 从记忆.md 学习日志只读检索，缺文件 = 合法形态）。

**目游标**：`task_index.py` 从 `## 下次续学` 的「节」行解析「已讲到第 k/N 目」→ 输出 `current_item` / `item_total`（缺失为 null）；目名随游标成对书写。**目编号是唯一游标口径**——按节连续（=KP 序），禁止按场分段重编号。

**三簿读写分工**：续学开场读 progress.md（本文件）恢复状态与游标；开节/规划读 `课程体系.md` 对应章/节；历史与洞察读 `记忆.md`。字段冲突时以本文件的状态字段为准。

**交接与记忆**：`本次交接` 是下一次开场的摘要（每次收尾覆盖重写）；事件时间线（学习日志）、持久洞察（学习记录）、讲授证据落 `记忆.md`（格式见「记忆文件」）。**若 `本次交接` 与 `下次续学` 冲突，以 `下次续学` 的阶段/节/动作游标为准**，开场向学员说明差异，不按交接里的旧话硬推。**下次开场先处理 `未解决`**；同一未解决项跨多次仍未动，转入薄弱点 / 暂缓与范围外 / 记忆.md 学习记录，不无限滞留在交接里。

**记忆写法纪律**（适用于本次交接与记忆.md 各区）：正文/洞察每条 ≤120 字（`profile.md` ② 的作用域、证据、日期、状态等元数据不计入）；用动词短语（"使用 X""卡在 Y""换 Z 后能独立完成"），不用形容词标签；每条带证据（日期 + 场景/原话）；推断标"暂定"，只有学员陈述或后续证据才升级；禁用绝对化词（深刻、彻底、完美掌握、专家、热爱、总是、从来不、完全理解）；无证据不写；空更新合法；当前证据与当前表态优先于旧记录；一次困难不得写成全局人格判断。

**动作游标（F08，可选）**：恢复只到「阶段 + 节」不足以区分「待出题 / 待作答 / 待批改 / 待落盘」——续学时先读本行定位**当前动作与待回应项**。出题后中断 → 据「待回应：题组文件 + 题号」继续原题，不重新出题；已答未批改 → 据「最后提交」指向的作答继续批改，不重复作答。缺本行 = 合法形态，退回「阶段 + 节」恢复。

**保持复习区**：位置在「错题归档」之后、「暂缓与范围外」之前；`scheduler.py due-queue` 把它与「薄弱点」「错题本」一起读取，条目用 `kind=保持` 标识。**写入时机（R54，目级化）**：① S3 目关闭（正式或轻量确认通过）→ **同轮为该目写一条目级保持条目**（初始 good）；节达标时核对保持条目已齐、缺漏当场补齐（`references/workflow.md`「节末收尾五件套」③）；节达标**不再新增节级条目**（存量节级条目仍合法并被 due-queue 继续读取，不回改）；② S4 薄弱点 2 轮全对（跨日，R52）清除 → 转入本区（不得直接消失）；③ S5 结课后复习清单以本区为准。**行格式**：目级条目 `[<日期>] <目名>（KP-xx-xx）｜ 元数据：…`；存量节级 `[<日期>] <节名> ｜ 元数据：…` 继续合法。**初始值**：取契约 `scheduler` 块（default_s / default_d 与 due 偏移），last=掌握/清除日；用 `scheduler.py next-interval --new-card --grade good --last <日> --today <日>` 算，不心算。**日期前缀**：行首 `[YYYY-MM-DD]` 推荐；缺日期时用元数据 `last`/`due` 或「最近更新」兜底，全部缺失才报 `W-UNPARSED-ITEM` 不入队（不猜当日）。**同一对象只保留一条**（节或目各一条）：复习时更新原行，不重复追加；对象身份优先用 `lesson_id` / KP 编号 / 稳定目名。**复习判分**：按既有条目命令更新 S/D/due；失败（Again）仍留本区，按短间隔重测；若需重讲，按条目对应节回炉，**不要为同一知识点另建一套 S/D 调度条目**。**已完成任务的保持复习**：仍可由 due-queue 触发 S4，复习后按「复习来源阶段=已完成」返回。**「需巩固」标注（R54，第五态语义）**：课程体系目行状态可写 `已讲（需巩固：<依据>，<日期>）`（对齐摸底标注先例，随「已讲」基值计数、不新增覆盖摘要键）。**触发**（模型按证据执行）：同一保持条目累计 2 次热身答错（R51）、保持复习重测判 Again、或 due 逾期未清且抽测不过；**翻回**：该目复习独立答对（题组、保持抽测或清除链通过）→ 撤标注恢复「已讲」。标注不参与闸口与纳入分母判断，脚本只读计数（覆盖率审计输出，见 `references/workflow.md`）。

**暂缓与范围区块**：条目为自由文本 + 竖线（`｜`）分段（来源 / 处置 / 触发条件 三段），**不做枚举硬校验**——有竖线分段但字段残缺的条目由 `progress_check.py` / `task_index.py` 输出 `W-UNPARSED-HOLD` 告警（不静默、不计入 hold_count）；**无竖线分段的纯自由文本行**不判畸形、仍计入 `hold_count`（解析器宽容口径；建议仍按三段式书写，以便 W-KP-HOLD-CROSS 交叉核对）；无暂缓项时本区写「无」。

## 稳定引用、对账与 Trace

### 稳定引用 · 对账 · 提交顺序（F09 / F10 / F12）

**稳定引用（F09，append-only）**——把「对象身份」与「展示顺序」解耦。**落点规定（证据只按稳定 ID 匹配）**：
- `lesson_id`：节稳定标识（如 `L-02`），**必填**，**改名 / 同名 / 换序都不变**。**落点三处**：①**节路线行**——`- [x] 1. 循环（lesson_id=L-B）`（全/半角括号均可）；②**判分记录文件头**——首行或标题下写 `lesson_id=L-B`（如 `# 循环，lesson_id=L-B`）；③**讲义/材料头**同理。`当前节` 序号仍保留供人读，二者分离。缺 `lesson_id` 的路线行 → `E-LESSON-ID-MISSING` 拦停。
- **匹配规则（`progress_check.py` 的消费口径）**：证据只按 `lesson_id` 精确匹配——`exercises/` 判分记录须声明与路线行一致的 `lesson_id=`；无序号回退，声明了他节 ID 的文件不会被本节命中（声明不一致 → 补正确 ID 或另写判分记录，不得串用）。
- `attempt_id` / `evt`：一次作答的稳定标识，写入条目元数据段 `evt=`（或判分行 `attempt_id=` 前缀）；同一作答产生的「错题」与「薄弱点」两条投影**共享同一 `evt`**（供校准去重；无 `evt` 的条目按单条观察计入校准并报 `W-NO-EVT`）。
- **动作游标引用**：`## 下次续学` 行的「待回应」须指向**存在的**判分记录（文件名或其前缀）、「最后提交」须指向**已出现的** `evt=`/`attempt_id=` 值；悬空引用在放行模式报 `E-CURSOR-DANGLING`（日常模式 `W-CURSOR-DANGLING`），恢复时不得把悬空游标当有效定位。
- **不自动重编号**：既有 KP 编号（`KP-<节序>-<目序>`）一律保留原值；节改名/换序后**引用材料与作答仍对应正确对象**，不靠序号猜、不追溯撤销历史。
- 脚本对未知可选字段**零感知**——缺这些键 = 合法。

**对账（F10，按对象 ID）**：「课程体系目行状态」与「progress.md 处置」双写按**对象 ID 集合对账**——有 KP 时以 `KP-xx-xx` 为准（状态单源 + 处置理由单源，progress.md 只存摘要）；**数量相同但对象不同也能检出**（W-KP-HOLD-CROSS 列出「仅清单 / 仅区块」差异）；无 KP 的任务保留任务级处置。不新增第三份账本。

**提交顺序（F12，先校验拟提交状态、后提交，可重试）**——多文件更新按固定次序，断在任一步都停在「未提交」态，绝不出现「无证据已掌握」：
1. 先写**证据与材料**（`exercises/` 判分、`materials/` 讲义）；
2. 再准备 **KP / 处置变更**（课程体系目行状态、progress.md 暂缓与范围外）；
3. **校验拟提交状态**——把**目标状态**送进校验器，而不是只校验磁盘旧状态：`progress_check.py <任务目录> --release --proposed-phase <目标阶段>`（拟转阶段时）或 `--staged <候选 progress 快照>`（候选文件），并用 `--changed-lessons <本次新增节号>` 限定增量范围；校验通过后才写盘（脚本输出 `proposed_state_supplied` / `checked_lessons` 回显；未提供拟提交状态时 `proposed_state_supplied:false` + `W-NO-PROPOSED-STATE`，**不得据此声称目标变更已校验**）；
4. 最后**提交掌握 / 阶段**（progress.md 阶段字段、课程体系节勾选）；
5. 派生**摘要**（课程体系覆盖摘要行、progress.md 范围快照）。
- 失败保留可重试点（脚本幂等、文件写入/编辑能力覆盖同值 → 重跑不重复事件）；**不宣称已有跨文件原子事务**——只保证次序与可重试。

### 结构化 Trace 输出（可选，默认关闭）

仅当回归测评需要过程数据时，才在闸口推进或会话收尾向 `<任务目录>/trace.jsonl` **追加一行** JSON（幂等，追加不改旧行）；**日常使用不强制记录**，不得因未记 Trace 而阻塞任何流程。字段稳定，供测评做「过程对比」与「基线回归」：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts` | string | ISO8601 时间戳 |
| `session_id` | string | 本次会话标识 |
| `phase` | string | 阶段名（枚举同 progress.md） |
| `step` | string | 阶段·动作（如 `S3·练习`） |
| `gate` | string | 本次对应的闸口判据 |
| `gate_result` | string | `pass` / `fail` / `na` |
| `tools` | array | 本步用到的工具名 |
| `files` | array | 本步读写的文件（相对数据根） |
| `evidence` | string | 落盘证据的定位（题号/检查清单/用户原话摘录） |
| `tokens` | int/null | 本步 token 消耗（会话末由平台回填，不可得填 null） |
| `duration_ms` | int/null | 本步耗时（同上） |

### 成本画像埋点

开启 Trace 时，会话收尾追加一条 `kind:"session_summary"` 记录，采集效率指标：

- `tool_calls`（本会话工具调用次数，可计数）
- `files_touched`（读写文件数，可计数）
- `gate_passes` / `gate_fails`（闸口通过/未通过次数，可计数）
- `tokens_total` / `duration_ms_total`（平台可回填则记，否则 null）
- `retries`（重试次数）

**用途**：让「效率退化」在回归测评中可被机器判定（如 token 或工具调用数超出基线的某比例即报警）。指标只增不减地追加，历史基线可逐次对比。

## 续学匹配（多任务与科目别名）

- 命中同名任务 → 续学：只读其 progress.md「当前阶段」，不得覆盖既有文件。
- 命中多个任务且用户未指名科目 → **列出候选**（科目名 + 当前阶段 + 最近学习日期），请用户选择；不猜、不默认最近一个。
- 用户指名科目 → 按科目与任务 slug/主题模糊匹配（含别名，如「高数」↔ shaanxi-gaoshu），命中单个即续学。
- 未命中 → 新任务，从 S0 开始。
- 枚举异常或为空但怀疑有数据 → 先用 `task_index.py --root` 兜底；`scan_status=partial/failed` 时任务集合不完整，不得当「无任务」处理，停止枚举/续学并修复后重跑。

## 复习调度字段（T04）

薄弱点条目的调度元数据放**行尾全角括号内**（半角括号亦兼容，推荐全角）、逗号分隔的 `键=值`（`cw`/`顽固` 为无值标记）；错题本与保持复习条目在行尾追加「｜ 元数据：…」段（竖线分段与「元数据：」冒号均全角/半角双兼容）。保持复习行推荐以 `[YYYY-MM-DD]` 掌握日期开头；缺日期时用「最近更新」兜底并告警，仍缺 → `W-UNPARSED-ITEM` 不入队（不猜当日）。解析器只认这些挂载点，其余文本不动。`S'/D'/due` 的计算由 `scripts/scheduler.py next-interval` 负责（判分归模型、算数归脚本，调用细则见 `references/assessment.md`「间隔调度」）。`due-queue` 输出 `reason` 字段（到期/逾期/优先级的人类可读说明），schema 为 `ltw-due-queue/3`。`错因`/`级`/`meta_default` 只对薄弱点/错题有意义；`kind=保持` 时前者为空、`meta_default=false`，不参与问题元数据。

| 字段 | 类型/取值 | 语义 | 默认值（缺省时） |
|------|-----------|------|------------------|
| S | 浮点（天） | 稳定天数，间隔重复核心参数 | 3.0 |
| D | 数值 0.5 粒度，[1,5] | 难度 | 3 |
| last | YYYY-MM-DD | 最近一次判分日期（绝对日期，禁相对日期） | 取 progress.md「最近更新」；仍缺 → 不入队，报 `W-UNPARSED-ITEM`（不猜当日） |
| due | YYYY-MM-DD | 下次复习日。**新写由 `scheduler.py` 以「本次复习日 + interval」计算**（见 `references/assessment.md`「间隔调度」）；缺 due 时按 `last + round(S)` 兜底推算 | 由 last 推算 |
| 信心 | 1–5 | 作答信心自评（**反馈前**提交方可用于 cw/校准；反馈后补报标回顾性） | 未写 → 不计入校准分母（不补 3） |
| cw | 标记（无值） | 自信但错（**反馈前**信心 ≥4 且判错），due-queue 排序优先 | 无 |
| 顽固 | 标记（无值） | 提示阶梯两次到梯底，重教不重测（见 S3/S4） | 无 |
| evt | 可选 ID | **作答事件 ID**：同一次作答的投影（错题 / 薄弱点）共享同一 `evt`，供校准统计去重（T04） | 无 |
| 错因 | 枚举：知识性 / 理解性 / 技巧性 | 归因分类，决定 S4 补救动作（重学 / 审题圈画 / 限时技巧）。**语义属性，归模型判断写入，禁止脚本代判** | 知识性 |
| 级 | 枚举：A / B / C | A=反复出错 / 直接影响学习目标达成的核心条目（详细整理+变式）；B=一般理解偏差（记思路）；C=纯粗心（仅标知识点）。与错因同轮由模型定级，S4 复习判分可调整级别 | B |

- `cw` 只由「信心 ≥4 且判错」产生；cw 条目修复后照常走清除/归档规则。
- due-queue 对 `顽固` 条目标 `teach:true`（排序不豁免），由模型据文本规则改走重教。
- **`错因` 枚举放元数据段，与既有自由文本「错因：<具体描述>」并存不冲突**：自由文本答「错在哪」（行内 `错因：` 全角冒号写法），枚举答「属哪类、该用什么补救」（元数据段内 `错因=` 等号写法）。解析器只在元数据段内搜 `错因=`，正则锚定于元数据段，不会误吃行首自由文本。
- **`级` 与 `错因` 是内容属性（错什么），S/D 是调度属性（何时再练），互不替代；`级` 不参与 due-queue 排序**（排序契约 cw→最逾期→due 早→稳定序不变），分级只影响整理深度与复盘注意力，脚本仅在输出中回显 错因/级 供模型取用。
- **可选 token `子类=`**：错因第六类"过度泛化"写 `错因=理解性` + `子类=过度泛化`；`scheduler.py` 已识别该键（不参与调度计算、不输出到 due-queue），不会再报 `W-META-INVALID`。

**字段合法性**（由 `scripts/progress_check.py` 校验）：`当前阶段`、`类型`、`学科族` 必须为上述枚举值之一；`复习来源阶段` 在 S4 期间必须为合法返回枚举（**逐节学习 / 结课 / 已完成**，任意字符串被拒）。**必填项随阶段变化**：`当前阶段`、`类型`、`学科族`、`目标` 全程必填；**`起点` 在 S0（接料建档）与 S1（诊断摸底，进行中）不要求，自诊断结束进入 S2 起（计划确认中/逐节学习/复习巩固/结课/已完成）必填**——S1 尚未产出「起点」属正常，不得据此误判。
