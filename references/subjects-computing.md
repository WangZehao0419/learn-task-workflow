# computing 学科群 正本册

> 本册是「computing」学科族的四类切片（plan / teach / practice / review）合一。

## 计算与技术群 · 规划切片

### 群边界与借用

本群：编程语言的语法与读写调试、算法与数据结构实操、脚本与工具链、计算机理论（操作系统、网络原理、组成原理）。上机编程与计算机理论同群，但内容类型分布不同：编程以程序型为主，理论以概念型为主。

默认内容类型分布：程序型约七成，概念型约两成，记忆型与设计型少量。S2 按实际目清单核正。

学员有真实项目或工作场景时，示范与练习**优先改造自他的真实材料**，抽象素材退为兜底。

### 内容结构与前置链

- **语法层**：变量与类型 → 表达式与语句 → 分支 → 循环 → 函数 → 数据结构 → 模块与文件。
- **能力层**：读代码（能预测输出）→ 改代码（能小步修改）→ 写代码（能从零实现）→ 调试（能定位并修复）→ 设计（能拆解并取舍）。
- **理论层**：存储层次 → 进程与线程 → 调度与同步 → 网络分层与协议 → 组成与指令。
- **前置断层高发点**：变量「是什么」没建立（把赋值当数学等式）、循环的边界惯例（含头不含尾）、函数调用与返回值的区别。这三处不修，后面全是背语法。

### 目标深度锚点

- **程序型目**：不只是「跑通」，而是能说出每步在做什么、为什么这么写、边界在哪。跑通但说不清，只到多点结构。
- **读码能力先于写码能力**：能准确预测一段陌生代码的输出，是写码的前置。读码不达标时不要跳到从零实现。
- **概念型目**（理论层）：能画出机制（时间线、层次图、状态迁移），能判断一个具体场景会出什么问题。
- **设计型目**：能拆分子问题、给出接口、说明取舍；接受多解，不追求唯一写法。

### 排期侧重

- **环境先立起来**：第一节必须把运行环境跑通，否则后面每一节都在跟环境搏斗。环境问题记入薄弱点，下次热身复现一次。
- **每节必须有一段实跑**：读代码、写代码都要真跑。没有执行环境的会话不做「看起来对」的结论。
- **小项目收口**：每章末安排一个「无用但完整」的小项目（能用就行，不求工程化），防止学完语法不知道拿来做什么。
- **理论层与上机层交替**：连续多节纯理论会掉，连续多节纯编码会缺机制理解，交替排。
- **考前**：算法与理论题按错题重做，上机题先确认环境与版本差异。

## 计算与技术群 · 出题切片

### 题型阶梯

由易到难，语法负荷逐级下降、思维负荷逐级上升：

1. **读码预测输出**：先写答案再实跑对照。错了正好用 trace 表查。
2. **Parsons 排序**：把打乱的代码行排成正确程序（可含干扰行）。降语法负荷，专练结构。
3. **改错**：埋一个**真实可复现**的 bug（不是伪代码），让学员定位并修。
4. **补全**：挖一到两段关键代码，其余给全。
5. **仿写**：换需求，保留结构。
6. **微项目**：从零实现一个小功能，含输入校验与边界。

**报错解读题必练**：给报错原文，学员说出「哪一行、什么类型、什么原因」三件。找错型练习的报错代码必须真实可运行。

### 群级共享误区库

只放**跨技术栈通用**的条目；并发时间线、存储层次、协议栈等理论课专属误区见 `references/disciplines/computing-theory.md`。

| 误区 | 症状 | 诱因 | 反证 |
|---|---|---|---|
| 赋值＝数学等式 | 读不懂 `x = x + 1` | 按代数等式读 | 右边先算再贴标签 |
| 变量＝装值的盒子 | 复合赋值后以为旧值还在 | 「盒子装东西」直觉 | 标签撕下贴到新对象，旧的等回收 |
| 执行顺序＝书写顺序 | 忽略条件跳转与调用关系 | 从上往下读的惯性 | 函数定义不调用就永不执行 |
| print 当 return | 函数里有输出就当有返回值 | 控制台有字＝有结果 | `None` 也能 print 出来 |
| 边界差一 | 循环多跑或少跑一次、切片丢尾 | 「从 1 数」与「含头不含尾」混淆 | 手推 n=1、n=2 两例 |
| 类型想当然 | `"1" + "1"` 期待 2 | 眼睛看到数字 | 输入进来的是字符串 |
| 可变对象共享引用 | 函数内改列表以为不影响外面 | 「传进来的是副本」 | 函数外再打印一次 |
| 不读报错直接搜答案 | 报错只看最后一行或直接贴搜索框 | 报错像噪音 | 报错里有文件名行号与类型，先读它 |
| 跑通即正确 | 一个用例过就交付 | 样例太友好 | 补边界用例（空、零、负数、最大） |
| 照抄 AI 代码不验证 | 不跑就交 | 生成结果看着像对的 | 一次实跑胜过十次目测 |

### 判定题构造

问「为什么这么做」而不是「这行干什么」：给两种实现问哪种更好（复杂度、可读性、边界安全）、给一个场景问用列表还是字典、问 `==` 与 `is` 的区别该在什么时候在意、给一段代码问它在什么输入下会崩。干扰项要是「在这个场景下也说得通」的方案。

### 答案形态与最小单元

- 起笔用 `代码：` + 围栏块（整块算一段），末段 `输出：` 给运行结果与成功标志。
- 报错修复类：附「报错特征 → 原因 → 修法」三行。
- 设计/架构类：`方案：` 起笔，给约束、备选、取舍、验证方式；接受多解，不编唯一答案。
- 不以 `解：` 起笔；代码类不给虚构评分细则（非备考任务）。

### 视觉任务

本群视觉任务以**执行轨迹与结构图**为主：变量快照表、调用栈、内存布局、层次图；这些由讲义生成、属讲解用图，证据资格见 `references/assessment.md`「视觉任务证据」——视觉任务只在确有原始材料（源码、报错截图、系统拓扑图）时声明。

### 给分点结构

上机题按「能跑通 / 边界正确 / 结构与可读性 / 复杂度说明」四段给分；理论题按「概念准确 / 机制完整 / 场景判断正确」三段给分。

## 计算与技术群 · 复习切片

### 复习形态与间隔侧重

- **题型轮换**：读码预测 → 改错 → 补全，隔次换型；同一题型连做三次以上就退化为机械操作。
- **不看笔记重写**：给需求，关闭参考，从零写一遍最小版本；写不出来再看笔记，看完再关掉重写。
- **API 与语法用检索复习**：函数名、参数顺序这类属于记忆型，做成卡片按间隔复习；不要指望在写代码时自然记住。
- **错题按「心智模型错 vs 手滑」分流**——见下表。
- **环境与版本类问题**记入薄弱点，下次开课热身复现一次，直到不再复发。

### 错因分流与纠错脚本

| 错因 | 判别信号 | 纠错动作 |
|---|---|---|
| 心智模型错 | 概念性错误，改完这题换个场景还错 | 回炉对应概念目重讲，用 trace 表重建执行模型 |
| 结构设计错 | 能写但拆得不好、嵌套过深 | 重做「拆子问题 + 定接口」这一层，不从语法改 |
| 手滑 | 拼写、缩进、漏冒号 | 入技巧性专项：靠 IDE 与格式检查兜底，不做概念重讲 |
| 边界遗漏 | 正常输入过、边界崩 | 补边界用例清单（空/零/负/最大/重复）作为提交前检查 |
| 报错不会读 | 直接搜答案 | 强制造三件：行号、类型、原因；练三次再允许查 |
| 不会提问 | 只贴「跑不了」 | 教最小复现四件：代码、输入、报错、预期 |

**纠错话术**：代码类错误先说「哪一行、什么类型」，再说「你原来希望它做什么」，最后才给修法。直接把正确代码贴出来会跳过定位过程。

### 冲刺侧重（方法层）

- **手推优先于机跑**：笔试类考试（算法、理论）要能手推伪代码与复杂度，不依赖 IDE；上机考试相反，先确认环境与版本。
- **模板记牢几个就够**：遍历、递归、二分、动态规划基本形态——记结构不记细节，细节现场推。
- **复杂度口算**：见 `references/disciplines/computing-theory.md`「学科专属教学法」。
- **错题重做优先**：冲刺期只重做错题与典型题，不刷新题。
- **考前确认环境**：语言版本、库版本、编译参数——记入考前一页纸。

## 计算与技术群 · 讲授切片

### 讲授侧重（六拍内的群差异）

- **读先于写**：新语法/新结构先给一段可运行代码，让学员**预测输出**，再实跑对照，再逐行调查（只查新语法与易错处），再小改一步看变化，最后自己写。零基础与入门默认全程走这个序；有基础后压缩为只查关键行。
- **先讲它解决什么痛点，再讲语法**：讲列表推导先给一个必须手写循环的场景，让学员感到麻烦，再引出更短的写法。
- **子目标标注**：示范代码按子目标分段，每段一行注释说「这段在干嘛」。这对挣扎学员尤其有效——它把代码从「字符流」变成「几个可命名的步骤」。
- **trace 表要显式**：变量 × 行号的表，手填每一步的值。读码能力是写码能力的前置，trace 是把「你以为你懂」变成「你确认你懂」的手段。
- **报错三件**：哪一行、什么类型、什么原因。每次报错都按这三件说，不许直接贴一段完整解法。
- **不写伪代码冒充真代码**：任何示范代码都要能真跑。

### 计算思维实践

1. **分解**：把问题拆成能独立验证的小块。每块给一句「这块负责什么」。
2. **模式识别**：这题和做过的哪题同构？可以套用什么模板？
3. **抽象**：哪些细节可以隐藏？该暴露什么参数？
4. **算法**：把步骤写成能逐步执行的序列，含边界条件。

每讲完一个实现，追问一句「如果需求改一个字，你要改哪几行」——这是检验抽象是否成立的快办法。

### 表征体系

- **执行轨迹**：变量快照表、调用栈图、状态迁移图。任何「为什么输出这个」的解释都落到轨迹上。
- **结构图**：数据结构画内存布局（谁指向谁），不只用文字描述。
- **层次图**：理论层用分层图（存储层次、协议栈、进程状态机）。
- **对照表**：易混结构并排（列表 vs 元组、进程 vs 线程、TCP vs UDP）。

### 类比库

- 变量＝贴标签的盒子；不像处（Python）——标签指向对象而非把值装进去，`a=b` 后改 `b` 指向，`a` 不变；但原地改对象（列表 append）两边都看得见。
- 循环＝流水线；函数＝榨汁机（投水果出汁，内部看不见）；异常＝安全气囊；递归＝俄罗斯套娃（必须有打不开的最小娃＝终止条件）。
- 调试＝医生问诊：先问病史（报错与复现条件）再开检查，不一次全查。
- **不要用「内存像一排抽屉」讲指针**——这个类比会让人以为指针是地址簿里的编号，实际它同时是类型加地址。

### 记号与术语纪律

语法术语（类型、作用域、引用、值传递、复杂度）首现给「定义 + 一个例子 + 一处易错」。复杂度记号（O、Ω、Θ）首现说明各自的界定，不要笼统说「大 O 就是上界」。

### 实跑纪律（群内硬规则）

示例代码首次发出前必须在授权的执行环境中实跑，不得只靠阅读或心算核对；无执行能力时停止当前运行，恢复后补跑，不发出「未实跑版」。实跑结果（含报错）如实展示。AI 生成的代码一律当草稿，跑过才算数；学员直接贴 AI 答案时先问「你跑过吗」。

### 标准流程示范

**实现**：读题定输入输出 → 拆子问题 → 选数据结构 → 写最小可跑版本 → 补边界 → 跑测试 → 说明复杂度。
**调试**：读完整报错 → 最小复现 → 二分定位（注释掉一半、打印中间值）→ 修一处 → 重跑确认 → 记录原因。
**读码**：找入口 → 追调用链 → 填 trace 表 → 预测输出 → 实跑对照。
